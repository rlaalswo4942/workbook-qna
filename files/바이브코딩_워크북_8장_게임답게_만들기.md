# 8장. 게임답게 만들기

> **이번 주 목표** "돌아가는 것"을 **"하고 싶은 것"** 으로 바꾼다. 소리, 화면 전환, 난이도, 최고 점수.

---

## 1. 학습 목표

이 장이 끝나면 다음을 할 수 있다.

- 게임에 효과음을 넣고, 브라우저의 소리 제한을 이해한다.
- 시작 화면 → 플레이 → 게임 오버의 화면 전환을 만들 수 있다.
- 시간이 지날수록 어려워지는 난이도 곡선을 만들 수 있다.
- `localStorage`로 최고 점수를 저장할 수 있다.
- 무료 에셋을 찾고, 라이선스를 확인하고, 출처를 표기할 수 있다.

---

## 2. 개념 설명

### 2.1 "돌아가는 게임"과 "하고 싶은 게임"의 차이

6장에서 플레이 가능한 게임이 됐다. 그런데 남에게 보여 주면 보통 한 판 하고 끝난다. 왜 그런가.

사람이 "한 판 더"를 누르는 이유는 네 가지로 거의 설명된다.

| 요소 | 심리 | 이번 주에 만드는 것 |
|---|---|---|
| **반응** | 내 행동에 세상이 반응한다 | 효과음, 번쩍임 |
| **기록** | 지난번보다 잘하고 싶다 | 최고 점수 저장 |
| **곡선** | 처음은 쉽고 점점 조여 온다 | 난이도 상승 |
| **의례** | 시작하고 끝나는 느낌이 있다 | 시작 화면, 게임 오버 화면 |

이번 주에 넣는 것은 전부 **기능이 아니라 느낌**이다. 코드 양은 많지 않은데 체감 차이는 이 과정에서 가장 크다.

> **과제는 "두 가지 이상"이다.** 네 개를 다 넣지 않아도 된다. **내 게임에 가장 효과가 큰 것부터** 고른다. 예를 들어 점수 경쟁이 핵심인 게임은 최고 점수가 1순위이고, 타격감이 중요한 게임은 효과음이 1순위다.

### 2.2 소리 — 가장 효과가 큰 한 줄

효과음은 코드가 가장 간단하면서 체감 변화가 가장 크다.

```javascript
const hitSound = new Audio("hit.mp3");   // 파일을 준비한다

// 부딪힌 순간에
hitSound.currentTime = 0;    // 처음으로 되감는다
hitSound.play();             // 재생한다
```

`currentTime = 0`이 중요하다. **되감지 않으면 소리가 재생되는 동안 `play()`를 다시 불러도 아무 일이 일어나지 않는다** — 이미 재생 중이기 때문이다. 되감으면 처음부터 다시 난다.

단, 이 방식은 **이전 소리를 끊고 다시 시작하는 것**이지 두 소리가 겹쳐 나는 것이 아니다. 효과음이 짧으면(0.1~0.3초) 그걸로 충분하다. 정말 겹쳐서 들려야 하면 재생할 때마다 사본을 만든다.

```javascript
const hit = hitSound.cloneNode();   // 사본을 만들어 재생 → 여러 개가 겹친다
hit.play();
```

**다만 사본을 너무 많이 만들면 느려진다.** 짧은 효과음은 `currentTime = 0` 방식으로 가고, 겹침이 꼭 필요한 곳에만 사본을 쓴다.

**브라우저의 소리 제한 — 이것 때문에 대부분 한 번 막힌다**

브라우저는 **사용자가 한 번이라도 클릭이나 키 입력을 하기 전에는 소리를 재생하지 않는다.** 광고가 멋대로 소리를 내는 것을 막기 위한 정책이다.

```
페이지를 열자마자 배경음악을 재생   →  막힌다 (콘솔에 경고가 뜬다)
시작 화면에서 키를 누른 뒤 재생     →  된다
```

그래서 **이번 주에 시작 화면을 만드는 것이 소리와 궁합이 좋다.** "아무 키나 눌러 시작"을 거치면 그 뒤로는 소리가 자유롭게 난다.

**배경음악은 조심한다**

```javascript
bgm.loop = true;      // 반복 재생
bgm.volume = 0.3;     // 음량을 낮춘다 (0~1)
```

**반드시 음량을 낮추고, 끌 수 있게 만든다.** 1.5시간 수업에서 서른 명이 각자 배경음악을 켜면 교실이 어떻게 되는지 상상해 보면 된다. 발표(10장) 때도 마찬가지다. **M 키로 음소거**를 넣어 두는 것을 권한다.

**소리 파일은 어디서 구하나** → 2.6을 본다. 형식은 **`.mp3`** 또는 **`.wav`** 를 쓴다. 효과음은 짧아야 한다(0.1~0.5초). 파일 이름은 영어로.

### 2.3 화면 전환 — 상태를 하나 더 늘린다

6장에서 `gameState`를 만들었다. 거기에 **값 하나만 추가하면** 시작 화면이 생긴다.

```javascript
let gameState = "start";    // "start" → "playing" → "gameover" → (다시) "playing"
```

```
┌─────────┐  아무 키    ┌──────────┐   부딪힘   ┌──────────┐
│  start  │ ─────────→ │ playing  │ ────────→ │ gameover │
│ 제목·설명│            │   게임    │           │ 점수·안내 │
└─────────┘            └──────────┘           └──────────┘
                            ↑                       │
                            └───────── R 키 ────────┘
```

루프는 이렇게 갈라진다.

```javascript
function gameLoop() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  if (gameState === "start") {
    // 제목, 조작법, "아무 키나 눌러 시작"
  } else if (gameState === "playing") {
    // 계산 + 그리기
  } else {
    // GAME OVER, 최종 점수, 최고 점수, "R키로 재시작"
  }

  requestAnimationFrame(gameLoop);
}
```

**6장에서 루프를 멈추지 않는 구조로 만든 이유가 여기서 드러난다.** 상태 값 하나만 늘리면 화면이 하나 늘어난다. 구조를 바꿀 필요가 없다.

**시작 화면에 반드시 넣을 것**

| 항목 | 이유 |
|---|---|
| 게임 제목 | 이게 무슨 게임인지 |
| 조작법 한 줄 | **링크만 받은 사람은 뭘 눌러야 하는지 모른다** |
| 목표 한 줄 | 무엇을 하면 이기는지 |
| "아무 키나 눌러 시작" | 시작 방법. 소리 제한도 함께 풀린다 |

6장 플레이테스트에서 "친구가 뭘 해야 하는지 몰랐다"는 경험을 한 사람은 이 화면의 가치를 안다.

### 2.4 난이도 곡선 — 점점 조여 온다

좋은 게임은 처음엔 쉽고 뒤로 갈수록 어렵다. 방법은 세 가지다.

**방법 1. 시간이 지나면 빨라진다 (가장 간단하다)**

6장에서 점수를 `Date.now()`로 쟀다. 난이도도 같은 시계를 쓴다.

```javascript
let nextLevelUp = 10;      // 다음에 어려워질 시점(초)

// 매 프레임
const elapsed = (Date.now() - startTime) / 1000;    // 흐른 시간(초)
if (elapsed > nextLevelUp) {
  enemySpeed = enemySpeed + 0.5;
  nextLevelUp = nextLevelUp + 10;                   // 그다음은 10초 뒤
}
```

**프레임 수를 세지 않는 이유는 6장과 같다.** 120Hz 기기에서는 프레임이 두 배로 돌아서, 난이도가 두 배 빨리 올라간다. 그러면 9장 플레이테스트 결과가 기기마다 달라져 비교할 수 없게 된다.

> `nextLevelUp`을 쓰는 이유 — "흐른 시간이 10초를 넘었는가"만 보면 그 뒤로 매 프레임 참이 되어 속도가 폭주한다. **다음 시점을 미뤄 두는 것**이 한 번만 올리는 방법이다. `resetGame`에서 `nextLevelUp`도 되돌린다.

**방법 2. 점수에 따라 어려워진다**

```javascript
if (score > 50) enemyCount = 8;
```

**방법 3. 적이 점점 자주 등장한다**

등장 간격을 줄여 나가는 방식이다. 피하기 게임에 잘 맞는다.

**주의: 끝없이 올리면 안 된다**

```javascript
enemySpeed = enemySpeed + 0.5;              // 2분 뒤 사람이 반응 못 하는 속도가 된다
enemySpeed = Math.min(enemySpeed + 0.5, 12);  // 12에서 멈춘다 ⭕
```

`Math.min`은 둘 중 작은 값을 고르는 명령이다. **상한을 정해 두는 것**이 난이도 설계의 기본이다. 상한이 없으면 실력과 무관하게 모두 같은 시점에 죽는다.

**좋은 곡선을 찾는 기준**

| 시점 | 바람직한 느낌 |
|---|---|
| 0~10초 | 조작을 익힌다. 거의 안 죽는다 |
| 10~30초 | 긴장이 생긴다. 집중하면 버틴다 |
| 30초~ | 실력에 따라 갈린다 |
| 상한 도달 후 | 매우 어렵지만 "불가능"은 아니다 |

**초보자가 10초 안에 죽으면 다시 안 한다.** 처음 10초는 일부러 쉽게 만든다.

### 2.5 `localStorage` — 브라우저에 저장하기

새로고침하면 최고 점수가 사라진다. **값을 브라우저에 남겨 두는 방법**이 `localStorage`다.

```javascript
// 저장
localStorage.setItem("highScore", score);

// 불러오기
let highScore = localStorage.getItem("highScore") || 0;
```

세 가지만 알면 된다.

| 코드 | 뜻 |
|---|---|
| `setItem("이름", 값)` | 이름을 붙여 저장한다 |
| `getItem("이름")` | 그 이름으로 꺼낸다 |
| `\|\| 0` | **없으면 0을 쓴다** (처음 플레이하는 사람) |

**반드시 알아야 할 함정: 꺼내면 글자가 된다**

`localStorage`는 무엇을 넣어도 **글자(문자열)로 저장한다.** 그래서 꺼낸 값으로 비교하면 엉뚱한 결과가 나온다.

```javascript
let high = localStorage.getItem("highScore");     // "100" (글자!)
if (score > high) { ... }                         // 비교가 이상해진다

let high = Number(localStorage.getItem("highScore")) || 0;   // 100 (숫자) ⭕
```

`Number()`로 숫자로 바꿔 준다. **7장에서 배운 `NaN` 문제와 같은 뿌리**다 — 글자와 숫자를 섞으면 계산이 깨진다.

**최고 점수를 갱신하는 흐름**

```javascript
if (score > highScore) {
  highScore = score;
  localStorage.setItem("highScore", highScore);
}
```

게임 오버가 되는 순간에 이 검사를 한다. 그리고 게임 오버 화면에 **"최고 점수: ○○"** 을 함께 보여 주면, 다음 판을 하고 싶어진다.

**`localStorage`의 성질**

- **그 브라우저, 그 기기에만** 남는다. 다른 사람의 최고 점수와는 섞이지 않는다
- 새로고침하거나 브라우저를 닫아도 남는다
- 시크릿 모드에서는 창을 닫으면 사라진다
- 전교 랭킹처럼 **모두가 공유하는 기록은 만들 수 없다** → 서버가 필요하다. **심화 11장**의 주제다

> **테스트 요령** — 저장이 제대로 되는지 확인하려면 `F12` → **Application**(또는 저장소) 탭 → Local Storage에서 값을 직접 볼 수 있다. 지우고 "처음 플레이하는 사람" 상태를 다시 테스트할 수도 있다.

### 2.6 무료 에셋과 저작권

도형만으로도 게임은 성립한다. 하지만 그림과 소리가 들어가면 완성도가 확 올라간다. 이번 주에 넣는 사람이 많을 테니, **규칙을 먼저 정리한다.**

**원칙 세 가지**

1. **검색해서 나온 이미지를 그냥 쓰지 않는다.** 구글 이미지 검색 결과는 대부분 남의 저작물이다. 내 게임은 **공개된 웹페이지**다(2장에서 Public으로 만들었다). 즉 "개인적으로 쓴다"가 성립하지 않는다.
2. **"무료"와 "자유롭게 써도 됨"은 다르다.** 무료로 받을 수 있어도 조건이 붙는 경우가 많다 — 출처 표기 필수, 상업적 이용 금지, 수정 금지 등.
3. **쓴 것은 모두 적어 둔다.** 파일 이름, 출처 주소, 라이선스 이름. 나중에 찾으려면 못 찾는다.

**라이선스에서 확인할 네 가지**

에셋을 받을 때 그 페이지에서 네 가지를 확인한다.

| 확인 항목 | 왜 |
|---|---|
| 출처 표기(크레딧)가 필요한가 | 필요하면 `README.md`에 적는다 |
| 상업적 이용이 가능한가 | 수업 과제는 비상업이지만, 습관을 들인다 |
| 수정해도 되는가 | 색을 바꾸거나 자르는 것도 수정이다 |
| 어떤 라이선스인가 | 이름을 그대로 적어 둔다 |

흔히 보이는 표시의 뜻은 대략 이렇다. **다만 사이트와 작품마다 조건이 다르므로, 반드시 그 작품의 페이지에서 직접 확인한다.**

| 표시 | 대략의 뜻 |
|---|---|
| **CC0 / Public Domain** | 자유롭게 사용. 출처 표기도 의무가 아니다 (그래도 적는 게 예의다) |
| **CC BY** | 자유롭게 사용하되 **출처 표기 필수** |
| **CC BY-NC** | 출처 표기 + **비상업적 용도만** |
| **CC BY-SA** | 출처 표기 + 내 결과물도 같은 조건으로 공개 |
| **ND가 붙은 것** | **수정 금지** — 자르거나 색을 바꾸면 안 된다 |

**AI로 만든 이미지를 쓰는 경우**

생성형 AI로 그림을 만들어 쓰는 것도 방법이다. 그때도 **`README.md`에 "AI로 생성(도구 이름)"이라고 적는다.** 이 수업의 원칙은 "AI 사용은 숨기지 않고 기록한다"이고, 그림도 코드와 같다.

**직접 만든 것도 적는다**

도형으로 직접 그렸거나, 그림판으로 그렸다면 **"직접 제작"** 이라고 적는다. 채점자가 구분할 수 있어야 한다.

**어디서 찾나**

수업에서 특정 사이트를 지정하지는 않는다. 검색할 때 **"CC0", "free game assets", "royalty free sound effects"** 같은 말을 함께 넣으면 라이선스가 명시된 곳이 나온다. 찾은 사이트에서 네 가지 확인 항목을 점검하는 것이 핵심이다.

AI에게 물어볼 수도 있다. 단, **AI가 알려 준 라이선스를 그대로 믿지 않고 그 페이지에서 직접 확인한다.**

```
2D 웹 게임용 무료 효과음과 스프라이트를 구할 수 있는 사이트를 알려 줘.
각 사이트의 라이선스 조건(출처 표기 필요 여부)도 함께 알려 주고,
내가 직접 확인해야 할 부분이 어디인지 알려 줘.
```

**`README.md`에 적는 양식**

```markdown
## 사용한 에셋
| 파일 | 용도 | 출처 | 라이선스 |
|---|---|---|---|
| player.png | 플레이어 | (주소) | CC0 |
| hit.mp3 | 충돌 효과음 | (주소) | CC BY (작자: ○○) |
| bg.png | 배경 | 직접 제작 | - |
| enemy.png | 적 | AI 생성 (도구명) | - |
```

이 표가 10장 제출물의 일부가 된다. **지금 적어 두면 10장에서 편하다.**

## 3. 따라 하기 실습

작업 폴더는 **`my-game`** 이다.

> **시작 전에 커밋한다.** 소스 제어 → `8장 시작 전 상태` → Commit.

> **이번 주도 하나씩 한다.** 네 가지를 한꺼번에 요청하면 어디가 깨졌는지 못 찾는다. **Step마다 확인하고 커밋한다.**

### Step 1. 시작 화면 (12분)

소리보다 이것을 먼저 한다. **소리 제한을 풀어 주는 역할**도 하기 때문이다.

```
시작 화면을 추가해 줘.

- gameState에 "start" 상태를 추가하고, 처음 상태를 "start"로 해 줘
- 시작 화면에는 가운데 정렬로:
  - 게임 제목 "(내 게임 제목)" (큰 글씨)
  - 목표 한 줄: "(설명)"
  - 조작법 한 줄: "(예: 방향키로 이동)"
  - 아래쪽에 "아무 키나 눌러 시작" (작은 글씨, 깜빡이면 더 좋아)
- 아무 키를 누르면 "playing"으로 바뀌고 게임이 시작되게 해 줘
- 게임 루프 구조는 그대로 유지하고, gameState로 갈라지게만 해 줘
- 기존 게임 오버 화면과 R키 재시작은 그대로 작동해야 해
```

확인한다.

- [ ] 처음에 시작 화면이 보인다
- [ ] 키를 누르면 게임이 시작된다
- [ ] 게임 오버 → R → **게임이 바로 시작된다** (시작 화면으로 돌아갈지는 취향이다)
- [ ] 조작법이 화면에 적혀 있다

커밋한다 (`시작 화면 추가`).

### Step 2. 효과음 (12분)

**먼저 소리 파일을 구한다.** 2.6을 참고해서 짧은 효과음 1~2개를 받는다.

1. 받은 파일을 `my-game` 폴더에 넣는다. 이름은 **영어로** (`hit.mp3`, `point.mp3`)
2. 출처와 라이선스를 **지금 바로** `README.md`에 적는다 (나중에 못 찾는다)
3. AI에게 요청한다

```
효과음을 추가해 줘.

- 같은 폴더의 hit.mp3를 (충돌할 때) 재생해 줘
- 같은 폴더의 point.mp3를 (점수를 얻을 때) 재생해 줘
- 연속으로 빠르게 나야 하니 재생 전에 currentTime을 0으로 되감아 줘
- 소리 파일이 없어도 게임이 멈추지 않게 해 줘 (에러 방지)
- M 키로 음소거를 켜고 끌 수 있게 해 줘
- 음소거 상태를 화면 구석에 작게 표시해 줘
```

확인한다.

- [ ] 해당 순간에 소리가 난다
- [ ] 빠르게 연속으로 나도 끊기지 않는다
- [ ] M 키로 음소거가 된다
- [ ] 콘솔에 소리 관련 에러가 없다

> **소리가 안 난다면** 순서대로 확인한다. ① 파일 이름과 확장자가 정확한가(대소문자 포함) ② 파일이 같은 폴더에 있는가 ③ **시작 화면에서 키를 누른 뒤인가** ④ 컴퓨터 음량과 브라우저 탭 음소거 ⑤ 콘솔 경고 메시지

커밋한다 (`효과음 추가`).

### Step 3. 난이도 곡선 (10분)

```
시간이 지날수록 어려워지게 해 줘.

- Date.now()로 흐른 시간을 재서, 10초마다 (적의 속도 / 개수 / 등장 간격)을 조금씩 어렵게
  (프레임 수를 세는 방식은 쓰지 마. 120Hz 기기에서 두 배 빨리 어려워지니까)
- 한 번만 올라가게 "다음 상승 시점" 변수를 두고 미뤄 가는 방식으로 해 줘
- 단, 상한을 정해서 그 이상으로는 어려워지지 않게 해 줘 (Math.min 사용)
- 처음 10초는 거의 안 죽을 정도로 쉽게 시작해 줘
- 난이도 관련 숫자(증가량, 상한, 간격)는 변수로 코드 위쪽에 모아 줘
- 재시작하면 난이도와 시작 시각, 다음 상승 시점이 모두 처음으로 돌아가게 resetGame에 넣어 줘
```

마지막 조건을 빠뜨리면 **"재시작했는데 처음부터 엄청 어렵다"** 는 버그가 생긴다. 6장에서 겪은 재시작 문제와 같은 종류다.

**플레이해서 확인한다.**

- [ ] 처음 10초는 쉽다
- [ ] 시간이 지나면 체감이 달라진다
- [ ] 2분을 버텨도 "불가능"하지는 않다
- [ ] 재시작하면 난이도가 처음으로 돌아간다

커밋한다 (`난이도 상승 추가`).

### Step 4. 최고 점수 저장 (10분)

```
최고 점수를 localStorage에 저장해 줘.

- 게임 오버 시 지금 점수가 최고 점수보다 높으면 갱신하고 저장해 줘
- 불러올 때 Number()로 숫자로 변환하고, 없으면 0으로 시작해 줘
- 게임 오버 화면에 "최종 점수"와 "최고 점수"를 함께 보여 줘
- 최고 점수를 새로 세웠을 때는 "신기록!" 같은 표시를 해 줘
- 플레이 중에도 화면 한쪽에 최고 점수를 작게 보여 줘
```

확인한다.

- [ ] 한 판 하고 게임 오버 → 최고 점수가 보인다
- [ ] **페이지를 새로고침해도 최고 점수가 남아 있다** ⭐
- [ ] 더 높은 점수를 내면 갱신된다
- [ ] 낮은 점수를 내면 갱신되지 않는다

> **마지막 항목을 꼭 테스트한다.** `Number()` 변환을 빠뜨리면 글자 비교가 되어서, 예를 들어 `"9" > "100"`이 참이 되는 일이 생긴다. **일부러 낮은 점수로 죽어 보는 것**이 테스트다.

`F12` → Application → Local Storage에서 저장된 값을 직접 확인해 본다.

커밋한다 (`최고 점수 저장`).

### Step 5. 선택: 그림 넣기 (여유가 있으면)

도형을 이미지로 바꾼다. 3장에서 배운 `img.onload`가 필요하다.

```
플레이어를 player.png 이미지로 바꿔 줘.

- 이미지는 img.onload 안에서 그려야 하는 점을 고려해 줘
- 이미지가 없거나 못 불러오면 기존 사각형으로 그려지게 해 줘 (안전장치)
- 충돌 판정은 이미지 크기 기준으로 하되, 판정 영역을 양쪽 4px 작게 해 줘
- showHitbox로 판정 영역을 확인할 수 있게 유지해 줘
```

두 번째 조건이 중요하다. **이미지를 못 불러왔을 때 아무것도 안 보이면** 원인을 찾기 어렵다. 사각형으로라도 보이면 "이미지만 문제"라는 걸 바로 안다.

판정 영역을 작게 하는 이유는 6장에서 다룬 "느낌" 문제다. `showHitbox`를 켜서 눈으로 확인한다.

> **배포하면 이미지가 안 보일 때** — 파일 이름 대소문자 문제가 거의 확실하다. 부록 D.5를 본다.

### Step 6. 정리하고 배포 (6분)

1. `showDebug`, `showHitbox`를 **끈다**
2. `README.md`에 **사용한 에셋 표**를 완성한다
3. `README.md`의 **조작법**을 갱신한다 (M 키 음소거, R 키 재시작 포함)
4. 커밋 → Sync → 배포 주소에서 **처음부터 끝까지 한 판** 플레이
5. **휴대폰으로도 열어 본다** — 소리가 나는지, 시작 화면이 읽히는지

## 4. 내 게임에 적용하기 (과제)

### 과제 1. 네 가지 중 두 가지 이상 추가 (필수)

- [ ] 시작 화면 / 화면 전환
- [ ] 효과음 (또는 배경음악 + 음소거)
- [ ] 난이도 상승 (상한 포함)
- [ ] 최고 점수 저장

**두 개만 해도 만점이다.** 네 개를 억지로 넣어 다 어설픈 것보다, **두 개를 제대로 하는 것**이 낫다. 어떤 것을 왜 골랐는지 회고에 쓴다.

### 과제 2. 에셋 출처 표기 (필수)

`README.md`에 **사용한 에셋 표**를 만든다. 2.6의 양식을 쓴다.

- [ ] 모든 이미지와 소리 파일이 표에 있다
- [ ] 출처 주소가 적혀 있다
- [ ] 라이선스 이름이 적혀 있다
- [ ] **직접 제작**이나 **AI 생성**도 그렇게 적혀 있다
- [ ] 외부 에셋을 하나도 안 썼다면 **"외부 에셋 없음 (도형으로 직접 제작)"** 이라고 적는다

> 이 항목은 **빠지면 감점**이다. 에셋을 안 썼으면 안 썼다고 적는 것까지 포함이다.

### 과제 3. 난이도 체감 기록 (필수)

회고에 넣는다. 4~6장의 튜닝 표와 같은 형식이지만, **시간대별**로 적는다.

```
| 시점 | 내 체감 | 조정한 것 |
|---|---|---|
| 0~10초 | 너무 쉬워서 지루했다 | 시작 속도를 2 → 3으로 |
| 30초 | 적당히 긴장됐다 | 그대로 |
| 1분 이후 | 반응이 불가능했다 | 상한을 15 → 9로 |
```

**내가 버틴 최고 기록**도 함께 적는다.

### 과제 4. 선택 과제

- 그림(스프라이트)으로 교체한다
- 충돌 순간에 **화면 흔들림이나 번쩍임**을 넣는다
- 점수가 오를 때 **숫자가 튀어오르는 효과**를 넣는다
- 배경음악 + M 키 음소거 (음량은 0.3 이하로)
- **일시정지**(P 키)를 만든다 — `gameState`에 `"paused"`를 추가하면 된다
- 적의 종류를 2가지로 늘린다 (속도나 점수가 다른)
- 최고 점수를 **상위 3개**까지 저장한다 (배열을 `localStorage`에 넣으려면 `JSON.stringify`가 필요하다 — AI에게 물어본다)

### 과제 5. 회고 파일 (필수)

양식은 **부록 E**와 같다. 8주차는 아래를 포함한다.

- **1번:** 네 가지 중 고른 것의 요청을 복사한다. **왜 그 두 개를 골랐는지** 한 줄 적는다
- **2번:** 막힌 점. 이번 주 단골 소재 — 소리가 안 났다, 최고 점수가 이상하게 비교됐다, 재시작했는데 난이도가 안 돌아갔다, 배포하니 이미지가 깨졌다
- **3번:** 코드 설명. **이번 주는 `localStorage` 또는 난이도 상승 부분에서 고른다.** `Number()`가 왜 필요한지, `Math.min`이 무엇을 막는지를 설명하면 좋다

## 이번 주 자주 막히는 지점

| 증상 | 원인과 해결 |
|---|---|
| 소리가 전혀 안 난다 | 시작 화면에서 **키를 누른 뒤**인지 / 파일 이름 대소문자 / 같은 폴더에 있는지 |
| 콘솔에 소리 관련 경고가 뜬다 | 브라우저 자동 재생 제한. 사용자 조작 후에 재생하도록 바꾼다 |
| 같은 소리를 연속으로 눌렀는데 두 번째가 안 난다 | `currentTime = 0`으로 되감지 않았다 |
| 소리가 겹쳐 들리지 않고 끊긴다 | 정상이다. 겹침이 필요하면 `cloneNode()`로 사본을 재생한다 |
| 배경음악이 너무 크다 | `volume`을 0.3 이하로. 그리고 음소거를 넣는다 |
| 새로고침하면 최고 점수가 사라진다 | `setItem`을 호출하지 않았다 / 시크릿 모드다 |
| 낮은 점수인데 신기록이 된다 | `Number()` 변환 누락. 글자끼리 비교하고 있다 |
| 최고 점수가 `NaN`으로 나온다 | 저장된 값이 숫자가 아니다. Local Storage를 지우고 다시 테스트 |
| 재시작했더니 처음부터 어렵다 | 난이도 변수를 `resetGame`에서 되돌리지 않았다 |
| 난이도가 끝없이 올라간다 | `Math.min`으로 상한을 둔다 |
| 난이도가 순식간에 폭주한다 | 조건이 매 프레임 참이 되고 있다. "다음 상승 시점"을 미뤄 가는 방식으로 |
| 휴대폰에서 두 배 빨리 어려워진다 | 프레임 수를 세고 있다. `Date.now()` 방식으로 바꾼다 |
| 시작 화면에서 키를 눌러도 시작이 안 된다 | 키 이벤트가 `"start"` 상태에서도 작동하는지 확인 |
| 이미지가 안 보인다 | `img.onload` 안에서 그리는지 / 파일 이름 / 같은 폴더 |
| 로컬은 되는데 배포하면 이미지·소리가 없다 | **파일 이름 대소문자 불일치.** 부록 D.5 |
| 깃허브에 소리 파일이 안 올라갔다 | 파일 크기가 크거나 이름에 한글이 있다. 영어 이름, 짧은 파일로 |
| 게임이 느려졌다 | 소리 객체를 매 프레임 새로 만들고 있지 않은지 확인 (`new Audio`는 위쪽에 한 번만) |

모르는 용어는 **부록 C**, 에러는 **부록 D**, 프롬프트는 **부록 B**를 본다.
