# 4장. 움직이게 하기: 게임 루프

> **이번 주 목표** 멈춰 있던 화면이 **스스로 움직이기 시작한다.** 게임의 심장을 만든다.

---

## 1. 학습 목표

이 장이 끝나면 다음을 할 수 있다.

- 변수가 무엇이고, 게임에서 왜 필요한지 설명할 수 있다.
- "게임의 상태"를 숫자 몇 개로 표현할 수 있다.
- 게임 루프의 세 단계(지우기 → 계산 → 그리기)를 자기 말로 설명할 수 있다.
- `requestAnimationFrame`이 하는 일을 설명할 수 있다.
- 속도를 바꿔서 움직임의 빠르기와 방향을 조절할 수 있다.
- 화면 끝에서 튕기거나 멈추게 만들 수 있다.

## 2. 개념 설명

### 2.1 움직임의 정체 — 애니메이션의 비밀

3장에서 배운 사실 하나. **Canvas에는 "물체를 옮기는 명령"이 없다.** 그려진 것은 그 자리에 남아 있을 뿐이다.

그러면 어떻게 움직이게 하는가. 공책 모서리에 그림을 조금씩 바꿔 그리고 빠르게 넘기는 **플립북**을 떠올리면 된다.

```
1번째 그림: 공이 x=100에 있다
2번째 그림: 공이 x=103에 있다
3번째 그림: 공이 x=106에 있다
...
1초에 60장을 넘긴다  →  사람 눈에는 공이 매끄럽게 날아가는 것으로 보인다
```

게임도 똑같다. **매번 화면을 지우고, 조금 다른 위치에 다시 그린다.** 이것을 1초에 약 60번 반복한다.

그래서 움직임을 만들려면 두 가지가 필요하다.

1. **지금 어디 있는지 기억하는 것** → 변수
2. **반복해서 다시 그리는 장치** → 게임 루프

### 2.2 변수 — 게임이 기억하는 방법

**변수(variable)는 값을 담아 두는 상자이고, 상자마다 이름이 붙어 있다.**

```javascript
let x = 100;    // "x"라는 상자에 100을 담았다
```

이제 `x`라고 쓰면 100을 꺼내 쓸 수 있고, 값을 바꿀 수도 있다.

```javascript
x = 150;        // 상자 내용을 150으로 바꾼다
x = x + 3;      // 지금 값에 3을 더해서 다시 담는다 → 153
```

**`x = x + 3`이 수학처럼 보여서 헷갈린다.** 수학에서는 `x = x + 3`이 성립하지 않는다. 프로그래밍의 `=`은 "같다"가 아니라 **"오른쪽을 계산해서 왼쪽 상자에 넣어라"** 라는 명령이다.

```
x = x + 3   을 읽는 방법
            ↓
"지금 x에 든 값을 꺼내서 3을 더하고, 그 결과를 다시 x에 넣어라"
```

이 한 줄이 이번 주의 모든 움직임을 만든다. **매 프레임마다 x에 3을 더하면, 물체는 오른쪽으로 움직인다.**

> `x = x + 3`은 `x += 3`으로 짧게 쓸 수 있다. AI가 쓴 코드에 `+=`가 나오면 같은 뜻이다.

**`const`와 `let`의 구분**

| | 뜻 | 쓰는 곳 |
|---|---|---|
| `const` | 바뀌지 않는 값 | 도화지, 붓, 크기, 색처럼 고정된 것 |
| `let` | 바뀌는 값 | 위치, 속도, 점수처럼 계속 변하는 것 |

`const`로 선언한 것에 새 값을 넣으려 하면 에러가 난다. **"위치는 `let`"** 만 기억하면 이번 주는 충분하다.

### 2.3 게임의 상태 — 숫자 몇 개로 세상을 표현한다

이번 주에 얻을 가장 중요한 관점이다.

> **게임은 "숫자 몇 개의 묶음"이고, 화면은 그 숫자를 그림으로 보여 주는 것일 뿐이다.**

예를 들어 공 하나가 날아다니는 게임의 상태는 숫자 네 개로 끝난다.

```javascript
let ballX = 400;    // 공의 가로 위치
let ballY = 300;    // 공의 세로 위치
let speedX = 3;     // 가로로 한 프레임에 3씩
let speedY = 2;     // 세로로 한 프레임에 2씩
```

이 네 숫자를 **상태(state)** 라고 부른다. 그리고 게임이 하는 일은 이것뿐이다.

```
① 숫자를 조금 바꾼다       (ballX에 speedX를 더한다)
② 바뀐 숫자대로 그린다      (ballX, ballY 위치에 원을 그린다)
③ ①로 돌아간다
```

6장에서 점수와 생명이 추가되면 상태에 숫자가 두 개 더 늘어난다. 8장에서 최고 점수가 추가되면 하나 더. **게임을 만든다는 것은 "어떤 숫자를 기억하고, 그 숫자를 어떻게 바꿀지" 정하는 일이다.**

이 관점을 가지면 7장의 디버깅이 쉬워진다. 화면이 이상할 때 "그림이 이상하다"가 아니라 **"어느 숫자가 잘못되었나"** 를 보게 되기 때문이다.

### 2.4 속도 = 한 프레임에 더하는 값

`speedX = 3`은 무슨 뜻인가. **"한 번 그릴 때마다 x를 3씩 늘린다"** 는 뜻이다.

1초에 약 60프레임이므로, 실제로는 이렇게 된다.

```
speedX = 3  →  1초에 약 180픽셀 이동 (3 × 60)
speedX = 1  →  1초에 약 60픽셀  (느리다)
speedX = 10 →  1초에 약 600픽셀 (빠르다. 800 폭 화면을 1.3초에 횡단)
```

**방향도 속도의 부호로 정해진다.** 3장에서 배운 좌표계를 기억하면 바로 이해된다.

| 속도 | 움직이는 방향 |
|---|---|
| `speedX = 3` | → 오른쪽 |
| `speedX = -3` | ← 왼쪽 |
| `speedY = 3` | ↓ **아래쪽** |
| `speedY = -3` | ↑ **위쪽** |

> **점프가 `speedY = -10`인 이유가 여기 있다.** Canvas에서 위로 가는 것은 y를 줄이는 것이므로, 위로 솟는 속도는 음수다. 비전공자가 가장 많이 틀리는 부호다.

**적당한 속도는 얼마인가?** 정답은 없다. 숫자를 직접 바꿔 보고 "내 게임에 맞는 느낌"을 찾는 게 유일한 방법이다. 보통 **1~8 사이**에서 시작해 조정한다. 이번 주 실습에서 직접 돌려 본다.

### 2.5 게임 루프 — 심장

이제 반복 장치를 본다. 게임 루프의 코드는 이런 모양이다.

```javascript
function gameLoop() {
  // ① 지운다
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // ② 계산한다 (상태를 바꾼다)
  ballX = ballX + speedX;
  ballY = ballY + speedY;

  // ③ 그린다
  ctx.fillStyle = "white";
  ctx.beginPath();
  ctx.arc(ballX, ballY, 20, 0, Math.PI * 2);
  ctx.fill();

  // ④ 다음 프레임에 나를 또 불러 달라고 부탁한다
  requestAnimationFrame(gameLoop);
}

gameLoop();   // 첫 시동
```

구조만 보면 네 부분이다.

| 단계 | 하는 일 | 빼먹으면 |
|---|---|---|
| ① 지우기 | 이전 그림을 없앤다 | 지나간 자리가 다 남아서 **긴 줄이 그려진다** |
| ② 계산 | 숫자를 바꾼다 | 움직이지 않는다 |
| ③ 그리기 | 바뀐 숫자대로 그린다 | 화면이 비어 있다 |
| ④ 다음 예약 | 자기를 다시 부른다 | **딱 한 번만 그려지고 멈춘다** |

**①을 빼먹으면 생기는 현상이 특히 유명하다.** 공이 지나간 궤적이 그대로 남아서 선을 그린다. 버그처럼 보이지만, 일부러 이걸 이용해 "그림 그리기 게임"을 만들 수도 있다. 실습에서 직접 본다.

### 2.6 `requestAnimationFrame` — 왜 이걸 쓰는가

이름이 길어서 겁나지만, 뜻은 그대로다.

> **request(요청) + animation(애니메이션) + frame(한 장)
> = "다음 한 장을 그릴 때가 되면 이 함수를 불러 줘"**

```javascript
requestAnimationFrame(gameLoop);   // "다음 프레임에 gameLoop를 실행해 줘"
```

브라우저에게 **부탁**하는 것이 핵심이다. 그래서 두 가지 좋은 점이 생긴다.

1. **화면 주사율에 맞춰 준다** — 보통 1초에 60번. 모니터가 더 빠르면 더 자주 불러 준다
2. **다른 탭으로 가면 멈춰 준다** — 보이지 않는 화면을 계산하느라 배터리를 쓰지 않는다

> **왜 `setInterval`을 안 쓰는가?** "0.016초마다 실행해"라고 강제하는 방식도 있다(`setInterval`). 하지만 브라우저 사정과 어긋나서 움직임이 끊기거나 튀는 일이 생긴다. 게임 애니메이션에는 `requestAnimationFrame`이 표준이다. AI가 `setInterval`로 만들어 줬다면 "requestAnimationFrame으로 바꿔 줘"라고 요청한다.

**함수(function)에 대해** — `function gameLoop() { ... }`는 "gameLoop라는 이름의 작업 묶음"을 정의한 것이다. 정의만 하면 실행되지 않고, `gameLoop()`처럼 괄호를 붙여 **부를 때** 실행된다. 맨 아래 `gameLoop();` 한 줄이 시동을 거는 열쇠다. 그 뒤로는 루프가 스스로 자기를 계속 부른다.

### 2.7 화면 끝 처리 — 튕기기와 막기

그냥 두면 물체는 화면 밖으로 나가서 영원히 사라진다. 두 가지 처리 방법이 있다.

**방법 1. 튕기기 (벽에 부딪히면 방향 반대로)**

```javascript
if (ballX + radius > canvas.width || ballX - radius < 0) {
  speedX = -speedX;        // 속도의 부호를 뒤집는다
}
```

**반지름을 더하고 빼는 이유** — 원의 `x`는 **중심**이다. 중심이 벽에 닿을 때 튕기게 하면 공이 벽에 절반 박힌 뒤에 튕긴다. 사각형이라면 `+ 가로` 를 쓴다(5장에서 자세히 본다).

`speedX = -speedX`는 **"오른쪽으로 가던 것을 왼쪽으로 바꿔라"** 는 뜻이다. 3이었으면 -3, -3이었으면 3이 된다. 이 한 줄이 튕김의 전부다.

**방법 2. 막기 (벽을 넘지 못하게)**

```javascript
if (playerX < 0) {
  playerX = 0;             // 왼쪽 벽을 넘었으면 벽에 붙여 놓는다
}
```

5장에서 플레이어를 조작할 때 이 방식을 쓴다.

> `if`는 "만약 ~라면"이다. 5장에서 자세히 다루지만, 지금은 **"조건이 맞을 때만 안쪽을 실행한다"** 정도로 읽으면 된다. `||`는 "또는"이다.

## 3. 따라 하기 실습

작업 폴더는 **`my-game`** 이다.

> **시작 전에 커밋한다.** 소스 제어 → `4장 시작 전 상태` → Commit. 이번 주는 코드가 많이 바뀌니 특히 중요하다.

### Step 1. 공 하나를 움직인다 (10분)

내 게임과 별개로, **연습용 공 하나**부터 시작한다. 가장 단순한 형태로 루프를 체험하는 게 목적이다.

AI 채팅창(에이전트 모드)에 보낸다.

```
script.js를 수정해서, 흰 공 하나가 화면을 가로로 움직이게 해 줘.

- 공의 위치와 속도를 변수로 만들어서 코드 위쪽에 모아 줘
- 게임 루프는 requestAnimationFrame으로 만들고,
  함수 이름은 gameLoop으로 해 줘
- 루프 안을 "지우기 / 계산 / 그리기" 세 부분으로 나누고,
  각 부분에 한국어 주석을 달아 줘
- 화면 좌우 끝에 닿으면 반대 방향으로 튕기게 해 줘
- 기존에 그려 둔 내 게임 화면은 잠시 주석 처리해 둬도 돼
```

Live Server로 확인한다. **공이 좌우로 왕복하면 성공이다.**

> 3장에서 그린 화면이 사라져서 당황할 수 있다. 커밋해 뒀으니 언제든 돌아올 수 있고, Step 4에서 내 게임으로 돌아간다.

### Step 2. 코드를 읽는다 (8분)

움직이는 걸 봤으니, 왜 움직이는지 확인한다. AI에게 묻는다.

```
script.js의 gameLoop 함수를 한 줄씩 설명해 줘.
특히 이 세 가지를 설명해 줘.
1) 맨 아래 gameLoop(); 한 줄은 왜 필요한가
2) 함수 안에서 requestAnimationFrame(gameLoop)을 또 부르는 이유
3) ballX = ballX + speedX 가 무슨 뜻인가
```

설명을 읽고 아래를 직접 짚어 본다.

- [ ] 상태를 담은 변수들 (`let`으로 시작하는 줄)
- [ ] 지우는 줄 (`clearRect`)
- [ ] 계산하는 줄 (`+ speedX`)
- [ ] 다음 프레임을 예약하는 줄 (`requestAnimationFrame`)
- [ ] 시동을 거는 줄 (맨 아래 `gameLoop();`)

### Step 3. 망가뜨려 보면서 원리 확인 (12분)

**이번 주의 핵심 실습이다.** AI를 쓰지 않고 직접 고친다. 하나씩 하고, 확인한 뒤 되돌린다.

**실험 1 — 지우기를 뺀다**

1. `ctx.clearRect(...)` 줄 맨 앞에 `//` 를 붙인다 → 저장
2. 브라우저 확인 → **공이 지나간 자리가 다 남아서 긴 막대가 그려진다**
3. `//` 를 지운다 → 저장 → 정상으로 돌아온다

> 이게 "지우고 다시 그린다"의 증거다. 애니메이션은 매 프레임 새로 그린 결과물이다.

**실험 2 — 다음 프레임 예약을 뺀다**

1. `requestAnimationFrame(gameLoop);` 줄 앞에 `//` 를 붙인다 → 저장
2. 확인 → **공이 처음 위치에 멈춰 있다. 딱 한 프레임만 그려졌다**
3. `//` 를 지운다 → 정상

**실험 3 — 시동 줄을 뺀다**

1. 맨 아래 `gameLoop();` 줄 앞에 `//` 를 붙인다 → 저장
2. 확인 → **화면이 완전히 비어 있다.** 함수를 만들어만 두고 부르지 않았기 때문
3. `//` 를 지운다 → 정상

**실험 4 — 속도를 바꾼다**

| 바꿀 값 | 예상 | 확인 |
|---|---|---|
| `speedX = 1` | 아주 느리다 | |
| `speedX = 20` | 매우 빠르다 | |
| `speedX = -3` | 왼쪽으로 출발한다 | |
| `speedX = 0` | 움직이지 않는다 | |

각각 저장하고 눈으로 확인한다. **예상하고 나서 보는 것**이 중요하다.

**실험 5 — 세로로도 움직이게 한다**

`speedY` 변수가 없으면 직접 만들어 본다. AI 없이 해 본다.

1. 위쪽 변수 모음에 `let speedY = 2;` 를 추가한다
2. 계산 부분에 `ballY = ballY + speedY;` 를 추가한다
3. 저장 → **공이 대각선으로 움직인다**
4. 위아래로도 튕기게 하려면? → 좌우 튕김 코드를 보고 흉내 내 본다

막히면 AI에게 묻는다. 단, **"코드를 주지 말고 어디를 어떻게 고쳐야 하는지 말로 알려 줘"** 라고 부탁한다.

### Step 4. 내 게임으로 가져온다 (10분)

이제 연습을 끝내고 **내 게임**에 적용한다. 3장 기획서 7번에 적어 둔 "4주차에 움직일 것"을 움직인다.

주석 처리해 둔 내 게임 그리기 코드를 살리고, AI에게 요청한다.

```
3장에서 그린 내 게임 화면을 게임 루프 구조로 바꿔 줘.

게임: (내 게임 이름과 한 줄 설명)

이번에 움직여야 하는 것: (예: 위쪽의 빨간 장애물 3개가 아래로 떨어진다)

조건:
- 각 물체의 위치와 속도를 변수로 만들어 코드 위쪽에 모아 줘
- gameLoop 안은 "지우기 / 계산 / 그리기" 순서를 유지해 줘
- (예: 장애물이 화면 아래로 사라지면 다시 위에서 나타나게 해 줘)
- 아직 키보드 조작은 넣지 말아 줘. 다음 주에 할 거야
- 한국어 주석을 달아 줘
```

마지막에서 두 번째 조건이 중요하다. **다음 주 내용을 미리 넣지 말라고 막는 것.** 그러지 않으면 AI가 5~6장 내용을 한꺼번에 만들어 버려서, 내가 이해하지 못하는 코드가 쌓인다.

> **AI가 너무 많이 만들어 줬을 때** — 당황하지 말고 이렇게 요청한다.
> `"너무 많은 기능이 들어갔어. 이번 주에는 ○○만 움직이면 돼. 나머지는 지워 줘."`
> 또는 2장에서 배운 되돌리기로 돌아가서 요청을 다시 쓴다.

### Step 5. 속도를 내 손으로 조정한다 (5분)

**AI 없이** 숫자만 고친다. 내 게임의 느낌을 찾는 과정이다.

1. 움직이는 물체의 속도 값을 찾는다 (코드 위쪽 변수 모음에 있다)
2. 너무 빠르면 줄이고, 너무 느리면 키운다
3. 저장하고 바로 확인한다. **마음에 드는 느낌이 나올 때까지 반복한다**

> 이 과정이 게임 제작에서 **"튜닝"** 이라고 부르는 일이다. 코드를 바꾸는 게 아니라 숫자를 만지는 것만으로 게임의 재미가 결정되는 경우가 많다. 9장에서 플레이테스트할 때 이 작업을 다시 한다.

### Step 6. 커밋하고 배포 (5분)

1. 소스 제어 → `게임 루프 추가, 장애물 움직임 구현` → **Commit**
2. **Sync Changes**
3. 1~2분 뒤 배포 주소에서 확인한다 → **인터넷에서 내 게임이 움직인다**

휴대폰으로도 열어 본다. 움직임이 너무 빠르거나 느리면 메모해 둔다 (기기에 따라 체감이 다르다).

## 4. 내 게임에 적용하기 (과제)

### 과제 1. 내 게임에서 무언가 움직인다 (필수)

- [ ] 게임 루프(`requestAnimationFrame`)가 들어 있다
- [ ] 물체가 **하나 이상** 스스로 움직인다
- [ ] 움직이는 물체의 **위치와 속도가 변수로** 코드 위쪽에 모여 있다
- [ ] 화면 끝 처리가 되어 있다 — 튕기기 / 막기 / 반대편에서 다시 나타나기 중 하나
- [ ] 배포 주소에서도 움직인다

### 과제 2. 속도 튜닝 기록 (필수)

회고의 재료다. 속도 값을 **세 가지 이상** 시도하고 결과를 적는다.

```
| 속도 값 | 느낌 | 판단 |
|---|---|---|
| 1 | 너무 느려서 지루하다 | 탈락 |
| 8 | 눈으로 따라가기 힘들다 | 탈락 |
| 4 | 긴장되지만 반응할 수 있다 | 채택 |
```

> 이 표가 9장 플레이테스트의 예습이다. "왜 이 숫자를 골랐는가"를 설명할 수 있어야 내 게임이 된다.

### 과제 3. 선택 과제 (하나 이상 권장)

여유가 있으면 해 본다. 평가에 가점 요소다.

- 움직이는 물체를 **2개 이상**으로 늘린다 (서로 다른 속도로)
- 물체가 **대각선**으로 움직이고 네 벽에서 모두 튕기게 한다
- 배경에 **천천히 움직이는 것**을 추가한다 (구름, 별 등)
- 물체가 움직이면서 **색이 변하거나 크기가 변하게** 한다
- 실험 1을 응용해서 **궤적이 남는 효과**를 일부러 만든다

> 2개 이상으로 늘릴 때, 변수를 `ball2X`, `ball3X`처럼 복사해서 늘리면 금방 지저분해진다. **6장에서 "배열"을 배우면 이 문제가 깔끔하게 해결된다.** 지금은 복사해서 늘려도 괜찮다. 불편함을 느껴 두는 것이 6장의 준비다.

### 과제 4. 회고 파일 (필수)

양식은 **부록 E**와 같다. 4주차는 아래를 포함한다.

- **1번:** 루프를 만들게 한 요청, 그리고 AI가 너무 많이 만들었을 때 줄이게 한 요청
- **2번:** 막힌 점. 실험 1~5에서 알게 된 것을 써도 좋다. "y를 늘렸는데 위로 안 갔다" 같은 것이 좋은 소재다
- **3번:** 코드 설명. **이번 주는 `gameLoop` 함수에서 고른다.** 네 단계 중 한 부분을 골라, 그게 없으면 어떻게 되는지까지 쓴다 (실험에서 직접 봤으므로 쓸 수 있다)

## 이번 주 자주 막히는 지점

| 증상 | 원인과 해결 |
|---|---|
| 아무것도 안 움직인다 | 맨 아래 `gameLoop();` 시동 줄이 있는지 / 루프 안에 `requestAnimationFrame`이 있는지 |
| 화면이 완전히 비어 있다 | `F12` Console 확인. 변수 이름 오타가 흔하다 (`ballX` vs `ballx`) |
| 궤적이 길게 남는다 | `clearRect`가 없거나, 그리기보다 **나중**에 있다. 순서는 지우기 → 그리기 |
| 물체가 순식간에 사라진다 | 속도가 너무 크다. 숫자를 줄인다 |
| 위로 가라고 했는데 아래로 간다 | `speedY`가 양수다. 위로 가려면 **음수** |
| 벽에서 튕기는데 벽에 끼어 떨린다 | 튕김 조건이 매 프레임 계속 참이 된다. AI에게 "벽에 끼지 않게 위치도 벽 안쪽으로 보정해 줘"라고 요청 |
| 점점 빨라지거나 느려진다 | 속도 변수를 루프 안에서 계속 바꾸고 있다. 속도 변경은 의도한 곳에서만 |
| `const`에 값을 넣으려니 에러가 난다 | 바뀌는 값은 `let`으로 선언한다 |
| AI가 5~6장 내용까지 만들어 버렸다 | "이번 주에는 ○○만 하면 돼"로 범위를 명시하거나, 되돌리기로 돌아가 다시 요청 |
| 휴대폰에서 너무 빠르다/느리다 | 기기별 주사율 차이. **이동 속도는 숫자 조정으로 맞춘다.** 다만 점수나 난이도처럼 "몇 초 지났는가"가 중요한 것은 프레임을 세지 말고 `Date.now()`로 재야 한다 (6·8장) |

모르는 용어는 **부록 C**, 환경 문제는 **부록 D**를 본다.
