# 부록 B. 상황별 프롬프트 모음

> **5장부터 사용한다.** 수업이 진행되면서 항목이 늘어난다. 지금은 1~12장 범위다.
>
> 그대로 복사해서 쓰되, **괄호 안은 내 게임 내용으로 바꾼다.** 베껴 쓴 프롬프트를 회고에 붙이면 점수가 낮다 — 내가 고친 부분이 있어야 한다.

## B.0 좋은 프롬프트의 네 가지 요소

막히면 이 네 가지가 들어 있는지 확인한다.

| 요소 | 나쁜 예 | 좋은 예 |
|---|---|---|
| **무엇을** | "게임 만들어 줘" | "플레이어를 방향키로 움직이게" |
| **어디에** | (생략) | "script.js의 게임 루프 안에서" |
| **어떻게** | "잘" | "꾹 누르면 매끄럽게, 두 키 동시에 대각선으로" |
| **하지 말 것** | (생략) | "충돌 판정은 아직 넣지 마" |

네 번째가 특히 중요하다. **"하지 말 것"을 안 적으면 AI가 다음 주 내용까지 만들어 버린다.** 이해하지 못하는 코드가 쌓이는 가장 큰 원인이다.

**이 수업에서는 모든 요청에 아래 전제가 붙는다고 보면 된다.**

```
- 순수 HTML/CSS/JS만 쓰고, 외부 라이브러리는 쓰지 마
- Canvas와 ctx로 그려 줘
- 한국어 주석을 달아 줘
- 조정할 숫자는 변수로 만들어 코드 위쪽에 모아 줘
```

매번 다 쓰기 번거로우면, 이 네 줄을 메모장에 두고 붙여 쓴다.

## B.1 처음 만들 때

**프로젝트 시작 (1장)**
```
지금 열려 있는 폴더에 index.html, style.css, script.js 세 파일로
(만들 것)을 만들어 줘.

내용:
- (무엇이 들어가는지)

생김새:
- (색, 배치, 크기)

조건:
- 외부 라이브러리는 쓰지 말고 순수 HTML/CSS/JS로만
- style.css와 script.js를 index.html에 제대로 연결해 줘
```

**Canvas 준비 (3장)**
```
index.html을 게임용으로 바꿔 줘.
- (가로)×(세로) 크기의 canvas 하나만 남기고, id는 "game"으로
- style.css에서 배경은 (색), canvas는 화면 가운데에, 테두리는 얇은 흰 선
- script.js는 canvas와 ctx를 가져오는 두 줄만
```

**첫 화면 그리기 (3장)**
```
script.js에 내 게임의 첫 화면을 그려 줘. 아직 움직이지 않아도 돼.

게임: (제목 — 한 줄 설명)

그릴 것:
- 배경: (설명)
- (물체 이름): (색), (모양), (크기), (위치)
- (물체 이름): ...
- 왼쪽 위에 흰 글씨로 "(문구)"

조건:
- 좌표와 크기는 변수로 코드 위쪽에 모아 줘
- 각 부분에 한국어 주석을 달아 줘
```

## B.2 움직임 (4장)

**게임 루프 만들기**
```
(움직일 것)이 (방향)으로 움직이게 해 줘.

- 위치와 속도를 변수로 만들어 코드 위쪽에 모아 줘
- 게임 루프는 requestAnimationFrame으로, 함수 이름은 gameLoop
- 루프 안을 "지우기 / 계산 / 그리기" 세 부분으로 나누고 주석을 달아 줘
- 화면 끝에 닿으면 (튕기게 / 멈추게 / 반대편에서 나타나게) 해 줘
- 키보드 조작은 아직 넣지 마
```

**setInterval을 rAF로 바꾸기**
```
setInterval로 만들어진 애니메이션을 requestAnimationFrame 방식으로 바꿔 줘.
동작은 같게 유지해 줘.
```

**움직임 되살리기 (물체가 사라졌을 때)**
```
(물체)가 화면 아래로 벗어나면 다시 화면 위쪽의 랜덤한 x 위치에서
나타나게 해 줘. 속도도 매번 조금씩 다르게 해 줘.
```

## B.3 조작 (5장)

**제대로 된 키보드 조작 (방식 B)**
```
플레이어를 방향키로 움직이게 해 줘.

- keys 라는 객체를 만들어서 keydown에서 true, keyup에서 false를 기록하고,
  게임 루프 안에서 keys를 보고 위치를 계산하는 방식으로 해 줘
  (키를 꾹 누르면 매끄럽게, 두 키를 같이 누르면 대각선으로 가야 해)
- 방향키와 스페이스바로 페이지가 스크롤되지 않게 preventDefault를 넣어 줘
- 플레이어가 화면 밖으로 나가지 않게 네 벽에서 막아 줘
  (오른쪽과 아래쪽은 플레이어 크기를 고려해서)
- 이동 속도는 변수로 위쪽에 모아 줘
```

**끊기는 조작을 고칠 때**
```
키를 꾹 누르면 움직임이 끊기고, 두 키를 같이 누르면 대각선으로 안 가.
눌린 상태를 기억했다가 게임 루프에서 움직이는 방식으로 바꿔 줘.
```

**마우스 조작**
```
플레이어가 마우스의 x 좌표를 따라가게 해 줘.
getBoundingClientRect를 써서 캔버스 기준 좌표로 변환하고,
플레이어가 마우스 위치의 가운데에 오게 해 줘.
```

**점프와 중력**
```
스페이스바를 누르면 플레이어가 위로 뛰어오르고, 중력으로 내려오게 해 줘.

- 위로 솟는 속도는 음수로 (Canvas에서 위는 y가 작아지는 방향)
- 매 프레임 세로 속도에 중력 값을 더해 줘
- 바닥에 닿으면 멈추고 다시 점프할 수 있게
- 공중에서는 다시 점프할 수 없게
- 중력과 점프력은 변수로 위쪽에 모아 줘
```

**어떤 키가 눌리는지 확인**
```
키를 누를 때마다 눌린 키 이름을 콘솔에 출력하는 코드를 추가해 줘.
```

## B.4 규칙 만들기 (6장)

> **이번 주 원칙: 한 번에 다 요청하지 않는다.** 아래 네 개를 하나씩, 작동을 확인하고 커밋한 뒤에 다음으로 간다.

**여러 개를 배열로 바꾸기**
```
(적 / 장애물 / 아이템)을 배열과 객체로 바꿔 줘.

- enemies 라는 배열에 { x, y, speed, size } 형태의 객체를 담아 줘
- 처음에 (개수)개를 서로 다른 위치, 서로 다른 속도로 배치해 줘
- 게임 루프에서 for 반복문으로 전부 이동시키고 전부 그려 줘
- 화면 밖으로 벗어나면 다시 (어디)에서 나타나게 해 줘
- 개수와 크기는 변수로 위쪽에 모아 줘
- 아직 충돌 판정은 넣지 마
```

**충돌 판정 (판정 영역을 눈으로 확인하면서)**
```
플레이어와 enemies 배열의 적들 사이에 충돌 판정을 넣어 줘.

- 사각형끼리 겹치는지 판정하는 방식으로
- 판정 부분을 checkCollision 함수로 따로 만들어 줘
- 충돌하면 일단 콘솔에 "충돌!"만 출력해 줘 (게임 오버는 다음에)
- 판정에 쓰는 영역을 빨간 테두리로 그려 주고,
  showHitbox 변수로 켜고 끌 수 있게 해 줘
```

**점수 — 시간형**
```
버틴 시간을 점수로 만들어 줘.

- Date.now()로 시작 시각을 기록해 두고, 흐른 시간(초)을 점수로 써 줘
  (프레임 수를 세는 방식은 쓰지 마. 120Hz 기기에서 점수가 두 배가 되니까)
- Math.floor로 정수로 만들고, 왼쪽 위에 "점수: 12" 형태로 표시해 줘
- resetGame에서 시작 시각도 초기화해 줘
```

**점수 — 획득형**
```
플레이어가 (아이템)에 닿으면 점수가 (몇)점 오르고,
그 아이템은 배열에서 제거한 뒤 (어디)에 새로 만들어 줘.
```

**게임 오버와 재시작**
```
게임 오버와 재시작을 넣어 줘.

- gameState 변수로 "playing"과 "gameover"를 구분해 줘
- (조건)이면 gameState를 "gameover"로 바꿔 줘
- 게임 오버 상태에서는 모두 멈추고, 가운데에 "GAME OVER",
  그 아래 "최종 점수: ○○", 그 아래 작게 "R 키를 눌러 다시 시작"
- R 키로 처음 상태로 되돌려 다시 시작 (resetGame 함수로 만들어 줘)
- 게임 루프는 멈추지 말고, gameState에 따라 다르게 그리는 구조로 해 줘
```

**판정이 안 맞을 때**
```
그림과 충돌 판정 영역이 어긋나 있어.
그리는 좌표와 판정하는 좌표가 같은 변수를 쓰도록 고쳐 줘.
```

**충돌이 너무 자주 일어날 때**
```
한 번 닿았는데 충돌이 계속 반복돼서 점수(또는 생명)가 폭주해.
한 번 닿으면 그 적을 제거하거나, 짧은 무적 시간을 주는 방식으로 고쳐 줘.
```

**재시작이 제대로 안 될 때**
```
재시작하면 (현상)이 생겨.
resetGame에서 되돌려야 하는 값을 전부 점검해서 빠진 것을 찾아 줘.
```

**적을 제거하면 하나를 건너뛸 때**
```
반복문 안에서 배열에서 적을 제거하니까 하나를 건너뛰어.
뒤에서 앞으로 반복하는 방식으로 바꿔 줘.
```

## B.5 게임답게 만들기 (8장)

> **하나씩 요청하고, 확인하고, 커밋한다.** 네 가지를 한꺼번에 요청하면 어디가 깨졌는지 못 찾는다.

**시작 화면**
```
시작 화면을 추가해 줘.

- gameState에 "start" 상태를 추가하고, 처음 상태를 "start"로
- 시작 화면에 가운데 정렬로: 제목 "(제목)", 목표 한 줄, 조작법 한 줄,
  아래에 "아무 키나 눌러 시작" (작은 글씨, 깜빡이면 좋음)
- 아무 키를 누르면 "playing"으로 바뀌게
- 게임 루프 구조는 그대로 두고 gameState로 갈라지게만 해 줘
- 기존 게임 오버 화면과 R키 재시작은 그대로 작동해야 해
```

**효과음**
```
효과음을 추가해 줘.

- 같은 폴더의 (파일명)을 (어느 순간)에 재생해 줘
- 재생 전에 currentTime을 0으로 되감아 줘 (재생 중에는 play()가 무시되니까)
- 소리 파일이 없어도 게임이 멈추지 않게 해 줘
- M 키로 음소거를 켜고 끌 수 있게, 상태를 화면 구석에 작게 표시해 줘
```

**배경음악**
```
배경음악을 추가해 줘. (파일명)을 반복 재생하고, 음량은 0.3으로.
시작 화면에서 키를 누른 뒤에 재생되게 하고, M 키로 끌 수 있게 해 줘.
```

**난이도 상승**
```
시간이 지날수록 어려워지게 해 줘.

- Date.now()로 흐른 시간을 재서 10초마다 (적의 속도 / 개수 / 등장 간격)을 조금씩 어렵게
  (프레임 수를 세는 방식은 쓰지 마. 120Hz 기기에서 두 배 빨리 어려워지니까)
- 한 번만 올라가게 "다음 상승 시점" 변수를 두고 미뤄 가는 방식으로
- 단, Math.min으로 상한을 정해서 그 이상 어려워지지 않게
- 처음 10초는 거의 안 죽을 정도로 쉽게
- 난이도 숫자(증가량, 상한, 간격)는 변수로 위쪽에 모아 줘
- 재시작하면 난이도·시작 시각·다음 상승 시점이 모두 초기화되게 resetGame에 넣어 줘
```

**최고 점수 저장**
```
최고 점수를 localStorage에 저장해 줘.

- 게임 오버 시 지금 점수가 더 높으면 갱신해서 저장
- 불러올 때 Number()로 숫자 변환하고, 없으면 0으로
- 게임 오버 화면에 "최종 점수"와 "최고 점수"를 함께, 신기록이면 표시도
- 플레이 중에도 화면 한쪽에 최고 점수를 작게
```

**도형을 그림으로 바꾸기**
```
(물체)를 (파일명).png 이미지로 바꿔 줘.

- img.onload 안에서 그려야 하는 점을 고려해 줘
- 이미지를 못 불러오면 기존 도형으로 그려지게 해 줘 (안전장치)
- 충돌 판정은 이미지 크기 기준으로 하되 양쪽 4px 작게
- showHitbox로 판정 영역을 확인할 수 있게 유지해 줘
```

**일시정지**
```
P 키로 일시정지를 만들어 줘.
gameState에 "paused"를 추가하는 방식으로, 화면 가운데에 "PAUSED"를 표시해 줘.
```

**에셋 사이트 찾기**
```
2D 웹 게임용 무료 효과음과 스프라이트를 구할 수 있는 사이트를 알려 줘.
각 사이트의 라이선스 조건(출처 표기 필요 여부)도 함께 알려 주고,
내가 직접 확인해야 할 부분이 어디인지 알려 줘.
```
> AI가 알려 준 라이선스를 그대로 믿지 않고 **그 작품 페이지에서 직접 확인한다.**

## B.6 다듬기와 모바일 (9장)

> **리팩터링은 위험하다.** 먼저 커밋하고, 한 번에 하나만, **"동작은 절대 바꾸지 마"** 를 반드시 넣고, 끝나면 체크리스트로 전부 확인한다.

**그리기 분리 (가장 안전한 정리)**
```
script.js를 정리해 줘. 동작은 절대 바꾸지 마.
게임 루프 안의 그리기 부분을 draw() 함수로 분리해 줘.
다른 것은 건드리지 마.
```

**조정용 숫자 모으기**
```
script.js를 정리해 줘. 동작은 절대 바꾸지 마.
흩어져 있는 조정용 숫자(속도, 크기, 개수, 간격, 점수)를
코드 맨 위에 모아서 주석을 달아 줘. 값은 바꾸지 말고 위치만 옮겨 줘.
```

**중복 제거**
```
script.js를 정리해 줘. 동작은 절대 바꾸지 마.
같은 코드가 두 번 이상 반복되는 곳이 있으면 함수로 묶어 줘.
그 외에는 건드리지 마.
```

**모바일 — 화면에 맞게 보이기 (필수)**
```
휴대폰에서도 화면이 제대로 보이게 해 줘.

- index.html에 viewport meta 태그를 추가해 줘
- canvas가 화면 폭을 넘지 않게 CSS로 max-width: 100%를 적용해 줘
- 단, canvas의 width/height 속성 값은 바꾸지 마 (좌표 계산이 깨지니까)
- 마우스/터치 좌표를 쓰는 부분이 있으면,
  canvas의 실제 크기와 보이는 크기의 비율로 보정해 줘
- 세로 화면에서도 게임 화면이 잘리지 않게 해 줘
```

**모바일 — 터치 조작 (조작이 단순한 경우만)**

```
- 키보드 조작은 그대로 유지해 줘
```

**모바일을 포기할 때 (정직한 해결)**

**피드백을 반영할 때 (범위 좁히기)**

## B.7 온라인으로 확장하기 (11장 · 심화)

> **이 절의 프롬프트는 키를 다룬다.** 요청에 **"공개용 키만 쓴다"** 를 명시하고, 결과 코드에 `secret`·`service`가 들어 있지 않은지 직접 확인한다.

**fetch 연습 (서비스 가입 전)**
```
script.js에 fetch 연습용 코드를 추가해 줘.

- 키가 필요 없는 공개 API 하나를 호출해서 결과를 콘솔에 출력해 줘
- async/await를 쓰고, try/catch로 실패를 처리해 줘
- 각 줄에 한국어 주석을 달아 줘
- 게임 코드는 건드리지 마. 연습용 함수 하나만 추가해 줘
```

**RLS 정책 SQL 만들기**
```
Supabase의 scores 표에 RLS 정책을 만드는 SQL을 알려 줘.

- 누구나(anon) SELECT 할 수 있게
- 누구나(anon) INSERT 할 수 있게
- UPDATE와 DELETE는 아무도 할 수 없게 (정책을 만들지 않는 방식으로)

SQL Editor에 붙여넣을 형태로 주고, 각 줄이 무슨 뜻인지 설명해 줘.
```

**점수 등록**
```
게임 오버 시 점수를 Supabase에 등록하는 기능을 추가해 줘.

- REST API를 fetch로 직접 호출해 줘 (라이브러리는 쓰지 말고)
- 표 이름은 scores, 열은 name(text)과 score(int)
- 프로젝트 URL과 공개용 키는 코드 위쪽에 변수로 모으고,
  "공개용 키 — 비밀 키를 넣지 말 것" 주석을 달아 줘
- 이름은 공백 제거 후 1~8글자로 제한, 비어 있으면 "익명"
- 점수가 비정상적으로 크면(예: 100만 초과) 보내지 마
- try/catch로 감싸서 등록이 실패해도 게임은 계속되게 해 줘
- "등록 중..." / "등록 완료" / "등록 실패 — 오프라인일 수 있어요"를 화면에 표시
- 게임 오버 상태에서 중복으로 여러 번 보내지 않게 한 번만 보내 줘
```

**랭킹 읽기**
```
상위 랭킹을 불러와 화면에 표시해 줘.

- scores 표에서 score 내림차순 상위 10개
- 게임 오버 화면에 "1. 지민 — 120" 형태로, Canvas의 ctx.fillText로 그려 줘
- 불러오는 동안 "랭킹 불러오는 중...", 실패하면 "랭킹을 불러올 수 없습니다"
- 실패해도 게임은 정상 작동하게
- 게임 오버될 때마다 다시 불러오게 해 줘
```

**서버 쪽에 제한 걸기 (브라우저 제한은 효과가 없다)**
```
Supabase scores 표의 INSERT 정책에 with check 조건을 추가하는 SQL을 알려 줘.
- score는 0 이상 100만 이하
- name은 1~8글자
그리고 created_at이 브라우저가 보낸 값이 아니라 서버 시각으로 기록되게 하는 방법도
함께 알려 줘. 각 줄이 무슨 뜻인지 설명해 줘.
```

**삭제가 막혔는지 테스트**
```
내 Supabase scores 표에서 id가 (번호)인 행 하나를 지우는 DELETE 요청을
브라우저 콘솔에서 보내 보는 fetch 코드를 알려 줘.
응답 코드와 응답 본문을 둘 다 출력하게 해 줘.
```
> **판단은 응답 코드가 아니라 표의 행 수로 한다.** RLS에서 삭제 차단은 에러가 아니라 "0개 처리"로 오기 때문에, `204`가 와도 아무것도 지워지지 않은 것일 수 있다. Table Editor를 새로고침해서 행 수가 그대로면 정상이다.
>
> **내 표에 대해서만** 한다. 남의 서비스에 같은 시도를 하는 것은 공격이다.

**커밋 이력에 키가 있는지 확인**
```
git log -p 에서 secret이나 service_role 키가 들어간 적이 있는지 확인하고 싶어.
VS Code에서 확인하는 방법과 터미널 명령어를 함께 알려 줘.
```

**403 / 401이 날 때**
```
Supabase REST API를 fetch로 호출했는데 (401 / 403)이 나와.
RLS 정책과 키 종류를 포함해서 원인을 가능성 높은 순서로 알려 주고,
각각 확인 방법을 알려 줘. 코드는 아직 고치지 마.
```

## B.14 쓰면 안 되는 프롬프트

| 쓰지 말 것 | 이유 |
|---|---|
| "게임 전체를 완성해 줘" | 이해 못 하는 코드가 쌓인다. 평가에서 걸러진다 |
| "회고 파일을 써 줘" | 회고는 본인이 쓴다. 회고 항목 전체 0점 |
| "알아서 멋있게 만들어 줘" | 내 의도와 다른 결과가 나오고 고칠 곳이 많아진다 |
| "(남의 게임) 똑같이 만들어 줘" | 표절이다. 참고는 괜찮지만 내 것으로 바꾼다 |
| 에러 메시지를 요약해서 전달 | 한 글자 차이로 원인이 달라진다. **그대로 복사한다** |
