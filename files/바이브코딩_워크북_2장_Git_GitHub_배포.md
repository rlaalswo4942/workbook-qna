## 2. 개념 설명

### 2.1 이번 주가 왜 2주차인가

게임을 만들기도 전에 Git을 배우는 게 이상해 보일 수 있다. 이유는 둘이다.

**첫째, AI와 일하면 반드시 망가진다.** 바이브 코딩의 현실은 이렇다.

```
3주차: 잘 돌아간다
4주차: AI에게 "움직이게 해 줘" 요청 → 움직이는데 화면이 깨졌다
      "아까 상태로 돌려 줘" → AI가 기억을 못 한다
      Ctrl+Z를 100번 눌러 본다 → 더 이상하게 된다
      처음부터 다시 만든다 😭
```

Git이 있으면 이렇게 된다.

```
4주차: AI 요청 → 망가졌다
      "3주차 커밋으로 되돌리기" 클릭 → 1초
      다시 요청한다
```

**"다시 만들지 않기"** 가 이 수업의 생존 전략이고, Git이 그 도구다.

**둘째, 혼자 보는 것으로는 끝까지 못 간다.** 내 컴퓨터에만 있는 파일은 동기가 생기지 않는다. 링크가 있으면 친구에게 보낼 수 있고, 친구가 플레이하면 다음 주에 더 만들고 싶어진다. 9장의 플레이테스트도 링크가 있어야 가능하다.

### 2.2 Git과 GitHub는 다른 것이다

가장 많이 헷갈리는 부분이다.

| | Git | GitHub |
|---|---|---|
| 무엇인가 | 내 컴퓨터에 설치하는 **프로그램** | 인터넷상의 **웹사이트** |
| 하는 일 | 변경 이력을 기록하고 되돌린다 | 그 기록을 인터넷에 보관하고 공개한다 |
| 비유 | 작업 일지를 쓰는 펜 | 그 일지를 보관하는 도서관 |
| 인터넷 | 없어도 된다 | 필요하다 |

둘은 짝으로 쓰이지만 별개다. **Git으로 기록하고, GitHub에 올린다.**

### 2.3 커밋 = 저장 지점

Git의 핵심 개념은 하나뿐이다. **커밋(commit)**.

커밋은 **"지금 이 순간의 파일 상태 전체를 통째로 사진 찍어 두는 것"** 이다. 게임의 세이브 포인트와 똑같다.

```
커밋 1 ─── 커밋 2 ─── 커밋 3 ─── 커밋 4 ─── (지금)
"첫 페이지"  "색 바꿈"  "공 추가"  "움직임"
                 ↑
          여기로 언제든 돌아갈 수 있다
```

`Ctrl+Z`(되돌리기)와의 차이가 중요하다.

| | Ctrl+Z | 커밋 |
|---|---|---|
| 범위 | 지금 열린 파일 하나 | 폴더 전체 |
| 유지 | VS Code를 닫으면 사라진다 | 영구히 남는다 |
| 이름 | 없음 | 내가 설명을 붙인다 |
| 되돌리기 | 한 단계씩 더듬어서 | 원하는 지점으로 바로 |

### 2.4 커밋 메시지 쓰는 법

커밋할 때는 **무엇을 했는지 한 줄 설명**을 붙인다. 이게 나중에 나를 구해 준다.

❌ **나쁜 메시지** — 나중에 어디로 돌아가야 할지 알 수 없다
```
수정
ㅇㅇ
asdf
2
완료
```

⭕ **좋은 메시지** — 목록만 보고도 그 시점의 상태를 알 수 있다
```
자기소개 페이지 첫 버전 완성
배경색을 남색으로 변경
게임 아이디어 3개 추가
마우스 올리면 글씨 커지는 효과 추가
```

규칙은 간단하다. **"무엇을 했는가"를 한 줄로.** 완벽하게 쓰려고 고민하지 말고, 미래의 내가 읽어서 알아볼 정도면 충분하다.

> **언제 커밋해야 하나?** 초보자가 가장 많이 묻는 질문이다. 기준은 하나다. **"여기까지는 잘 돌아간다"고 확인한 순간.** 기능 하나가 완성될 때마다, 수업 시간에 한 단계가 끝날 때마다, AI에게 큰 요청을 보내기 **직전에** 커밋한다. 하루에 다섯 번 커밋해도 전혀 많지 않다.

### 2.5 저장소(repository)와 세 곳의 저장 위치

파일이 어디에 있는지가 헷갈리기 쉽다. 세 단계가 있다.

```
① 작업 폴더          ② 내 컴퓨터의 Git 기록       ③ GitHub
   (파일을 고친다)        (커밋으로 남긴다)            (인터넷에 올린다)

   파일 수정 ──커밋──→ 로컬 저장소 ──푸시(Push)──→ 원격 저장소
                                                         ↓
                                                   GitHub Pages
                                                   (누구나 보는 링크)
```

세 단어만 기억하면 된다.

- **커밋(Commit)** — 내 컴퓨터에 저장 지점을 만든다
- **푸시(Push)** — 그 기록을 GitHub로 올린다
- **배포(GitHub Pages)** — 올라간 파일을 웹페이지로 공개한다

커밋만 하고 푸시를 안 하면 GitHub에는 아무것도 없다. **이번 주에 가장 많이 하는 실수**이니 기억해 둔다.

### 2.6 GitHub Pages — 공짜 웹 호스팅

보통 웹사이트를 공개하려면 서버를 빌리고 도메인을 사야 한다. 그런데 GitHub는 **정적인 웹페이지(HTML/CSS/JS로만 된 것)를 공짜로 공개해 준다.** 우리가 만들 것이 정확히 그런 것이다.

주소는 이런 모양으로 정해진다.

```
https://(내 GitHub 아이디).github.io/(저장소 이름)/

예) 아이디가 jimin-park, 저장소 이름이 my-game 이면
    https://jimin-park.github.io/my-game/
```

그래서 **GitHub 아이디와 저장소 이름이 내 게임의 주소가 된다.** 1장에서 아이디를 영어 소문자로 정하라고 한 이유다.

여기서 세 가지 제약이 따라온다. 10주 내내 지켜야 한다.

| 제약 | 이유 |
|---|---|
| 파일·폴더 이름에 **한글·공백 금지** | 주소에 들어가면 깨진다 |
| **`index.html`** 이라는 이름이 필요하다 | 대문 역할. 이 파일이 없으면 404가 난다 |
| 저장소가 **공개(Public)** 여야 한다 | 비공개 저장소는 무료 Pages가 안 된다 |

> **공개가 걱정되나요?** 내 코드가 전 세계에 보인다는 뜻이다. 그래서 1장의 원칙 2가 중요하다 — **비밀번호, API 키, 개인정보는 코드에 쓰지 않는다.** 본과정에서는 그런 걸 쓸 일이 없으니 괜찮다. 심화 11장에서 이 문제를 제대로 다룬다.

## 3. 따라 하기 실습

### Step 1. Git 설치 (5분)

1. [git-scm.com](https://git-scm.com) 접속 → **Download for Windows**
2. 설치 프로그램 실행 → 옵션이 많이 나오는데 **전부 기본값으로 다음**을 누른다
3. 설치가 끝나면 **VS Code를 완전히 닫고 다시 켠다** (중요: 안 그러면 Git을 못 찾는다)

**설치 확인** — VS Code 왼쪽 세로 막대에 **소스 제어(Source Control)** 아이콘(갈라지는 가지 모양)이 있다. 클릭했을 때 "Git을 찾을 수 없습니다"가 아니면 성공이다.

### Step 2. GitHub 계정 확인 (3분)

지난주 과제로 만들어 왔어야 한다. 아직이면 지금 만든다.

1. [github.com](https://github.com) → **Sign up**
2. 아이디(Username)는 **영어 소문자 + 하이픈**으로. 이게 내 게임 주소가 된다
3. 이메일 인증까지 끝낸다

### Step 3. 이번 주 작업 폴더 준비 (5분)

이번 주부터는 **하나의 폴더를 10주 동안 계속 쓴다.** 매주 새 폴더를 만들지 않는다.

1. `Documents\vibe-coding` 안에 폴더를 새로 만든다 → 이름은 **`my-game`**
2. 1장에서 만든 `week01` 폴더의 **파일들을** `my-game` 안으로 복사한다
   (`index.html`, `style.css`, `script.js`, `회고.md`)
3. `my-game` 폴더에서 마우스 오른쪽 → **Code로 열기**

```
Documents/
└── vibe-coding/
    ├── week01/          ← 1장 제출용. 그냥 둔다
    └── my-game/         ← 앞으로 10주 동안 쓸 폴더 ⭐
        ├── index.html
        ├── style.css
        ├── script.js
        └── 회고.md
```

> **왜 폴더를 하나로 합치는가?** 과제가 누적 구조이기 때문이다. 매주 폴더를 새로 만들면 지난주 코드를 복사해 오느라 시간을 쓰고, Git 이력이 끊긴다. 하나의 폴더에서 10주 동안 커밋을 쌓으면 그 자체가 과정 증거가 된다.

### Step 4. 첫 커밋 만들기 (10분)

터미널 명령어는 쓰지 않는다. VS Code 화면에서 버튼으로 한다.

1. 왼쪽 세로 막대에서 **소스 제어** 아이콘 클릭 (또는 `Ctrl+Shift+G`)
2. **Initialize Repository**(저장소 초기화) 버튼 클릭
   → 이제 이 폴더가 Git의 관리 대상이 되었다
3. **Changes** 목록에 파일들이 나타난다. 이게 "아직 커밋되지 않은 변경"이다
4. 맨 위 입력창에 커밋 메시지를 쓴다

   ```
   1장 자기소개 페이지 완성
   ```

5. **Commit** 버튼 클릭
6. "스테이지에 올라간 변경이 없습니다. 모두 추가할까요?" 같은 안내가 나오면 **Yes / 항상** 선택

커밋이 끝나면 Changes 목록이 비워진다. **첫 세이브 포인트가 생겼다.**

> **처음 커밋할 때 이름/이메일을 물어볼 수 있다.** 그럴 때는 안내에 따라 GitHub 가입에 쓴 이름과 이메일을 넣는다. 한 번만 하면 된다.

### Step 5. 되돌리기 연습 — 일부러 망가뜨린다 (10분)

이번 주의 핵심 실습이다. **안전망이 실제로 작동하는지 직접 확인한다.**

1. AI 채팅창(에이전트 모드)에 이렇게 보낸다

   ```
   style.css의 배경색을 형광 분홍색으로, 글씨 색을 형광 초록색으로 바꿔 줘.
   글씨 크기도 세 배로 키워 줘.
   ```

2. 브라우저를 본다 → **눈이 아플 정도로 망가졌다.** 이게 "AI가 내 코드를 망쳤을 때"의 상황이다

3. 이제 되돌린다. **소스 제어** 패널을 보면 `style.css`가 Changes에 올라와 있다

4. `style.css` 위에 마우스를 올리면 아이콘 몇 개가 나타난다 → **되돌리기(Discard Changes, 구부러진 화살표)** 클릭

5. "변경 내용이 영구히 사라집니다" 경고가 나오면 **Discard Changes** 확인

6. 브라우저를 본다 → **커밋했던 상태로 정확히 돌아왔다.**

이게 전부다. **커밋해 둔 지점이 있으면, 그 이후에 망가진 것은 무엇이든 1초에 되돌릴 수 있다.**

> **변경 내용을 눈으로 비교하기** — Changes 목록에서 파일 이름을 **클릭**하면 왼쪽(커밋된 상태)과 오른쪽(지금 상태)이 나란히 보인다. 빨간색은 지워진 줄, 초록색은 추가된 줄이다. **AI가 뭘 바꿨는지 확인하는 가장 빠른 방법**이니, 앞으로 AI 요청 후에 습관적으로 열어 본다.

### Step 6. GitHub에 올리기 (10분)

1. 소스 제어 패널에서 **Publish Branch**(브랜치 게시) 버튼을 찾아 클릭
   — 안 보이면 패널 위쪽의 `⋯` 메뉴 → **Publish to GitHub**
2. GitHub 로그인 창이 뜬다 → **Allow / Sign in with browser** → 브라우저에서 승인
3. 저장소 이름과 공개 여부를 묻는다
   - 이름: **`my-game`**
   - **Publish to GitHub public repository** 를 고른다 ⭐ (private 아님)
4. 잠시 기다리면 업로드가 끝난다
5. [github.com](https://github.com) 에 가서 내 프로필을 보면 `my-game` 저장소가 보인다

이제 내 코드가 인터넷에 있다. 아직 **웹페이지로는 열리지 않는다.** 다음 단계가 필요하다.

### Step 7. GitHub Pages로 배포 (7분)

1. GitHub에서 `my-game` 저장소를 연다
2. 위쪽 탭에서 **Settings**(설정) 클릭
3. 왼쪽 메뉴에서 **Pages** 클릭
4. **Source** 또는 **Build and deployment** 항목에서
   - Source: **Deploy from a branch**
   - Branch: **`main`** / 폴더: **`/ (root)`**
5. **Save** 클릭
6. 1~3분 기다린다. 페이지를 새로고침하면 위쪽에 주소가 나타난다

   ```
   Your site is live at https://(내아이디).github.io/my-game/
   ```

7. 그 주소를 클릭한다 → **내 페이지가 인터넷에 떴다** 🎉

**휴대폰으로도 열어 본다.** 데이터로 접속해서 보이면 진짜 공개된 것이다.

> **404가 나오면?** 아래 셋 중 하나다.
> - `index.html`이라는 이름의 파일이 저장소 **맨 위**에 없다 (하위 폴더에 있으면 안 된다)
> - 아직 배포가 끝나지 않았다 → 2~3분 더 기다린 뒤 **Ctrl+F5**로 강력 새로고침
> - 저장소가 Private이다 → Settings 맨 아래에서 Public으로 바꾼다

### Step 8. 수정 → 배포 사이클 체험 (5분)

앞으로 10주 동안 매주 반복할 흐름이다. 한 번 돌려 본다.

1. AI에게 작은 변경을 요청한다

   ```
   페이지 맨 아래에 "GitHub Pages로 배포됨" 이라는 작은 글씨를 추가해 줘.
   ```

2. 브라우저(Live Server)에서 확인한다
3. 소스 제어 → 메시지 쓰기 → **Commit**

   ```
   배포 안내 문구 추가
   ```

4. **Sync Changes**(변경 내용 동기화) 버튼 클릭 → GitHub로 올라간다
5. 1~2분 뒤 **배포 주소**를 새로고침한다 → 변경이 반영되어 있다

```
고친다 → Live Server로 확인 → 커밋 → Sync → 1~2분 → 배포 주소에 반영
```

이 다섯 단계가 이번 주에 가져갈 전부다.

## 4. 내 게임에 적용하기 (과제)

### 과제 1. 배포 완료 (필수)

- [ ] `my-game` 저장소가 GitHub에 **Public**으로 올라가 있다
- [ ] GitHub Pages 주소로 내 페이지가 열린다
- [ ] **다른 사람도 열린다** — 로그아웃 상태 또는 휴대폰 데이터로 확인한다
- [ ] 커밋이 **3개 이상** 있다 (한 번에 몰아 커밋하지 않는다)

### 과제 2. 제출 체계 세팅 (필수)

앞으로 10주 동안 쓸 저장소를 정리한다.

**(1) `README.md` 만들기**

저장소 맨 위에 `README.md`를 만든다. GitHub에서 저장소를 열면 이 파일이 자동으로 보인다. AI에게 요청해도 되지만, **내용은 내가 정한다.**

```markdown
# (게임 제목 또는 "제작 중")

프로그래밍 입문 수업에서 만드는 웹 게임입니다.

- 학번 / 이름:
- 플레이: https://(내아이디).github.io/my-game/

## 게임 아이디어
(1장에서 낸 아이디어 3개 중 지금 마음이 가는 것과 그 이유)

## 진행 상황
- [ ] 1주차: 자기소개 페이지
- [ ] 2주차: GitHub 배포
- [ ] 3주차: 게임 화면 그리기
```

**(2) `회고.md` 위치 확인**

`my-game` 폴더 맨 위에 `회고.md`가 있어야 한다. 1주차 내용 위에 2주차를 **추가**한다 (1주차를 지우지 않는다).

**(3) 폴더 정리**

- [ ] 한글·공백이 들어간 파일 이름이 없다 (`회고.md` 같은 **`.md` 문서는 예외**)
- [ ] `복사본`, `test`, `새 폴더` 같은 잔해가 없다

### 과제 3. 되돌리기 경험 1회 이상 (필수)

이번 주 회고의 "막힌 점" 항목에 쓸 재료다. **일부러라도 한 번 해 본다.**

1. 커밋을 한다
2. AI에게 뭔가 요청해서 변경을 만든다
3. 그 변경을 되돌리기(Discard Changes)로 취소한다
4. 회고에 **무엇을 되돌렸고, 어떤 화면에서 어떤 버튼을 눌렀는지** 쓴다

> 이 경험이 없으면 4~6장에서 코드가 망가졌을 때 Git을 쓰지 못한다. 손이 기억하게 만드는 것이 목적이다.

### 과제 4. 회고 파일 (필수)

양식은 **부록 E**와 같다. 2주차는 아래를 반드시 포함한다.

- **1번 항목:** 이번 주에 AI에게 보낸 요청 (Step 5의 망가뜨리기 요청도 괜찮다)
- **2번 항목:** 되돌리기 경험 또는 배포 중 막힌 점. 404가 났다면 그 과정을 쓴다
- **3번 항목:** 코드 설명. 1장에서 고른 것과 **다른 부분**을 고른다

---

## 5. 제출 체크리스트

이번 주부터 **압축 파일 제출은 끝이다.** 링크 두 개를 제출한다.

```
① 저장소 링크: https://github.com/(내아이디)/my-game
② 배포 링크:   https://(내아이디).github.io/my-game/
```

제출 전 확인한다.

- [ ] 두 링크가 **로그아웃 상태에서도** 열린다
- [ ] 배포 링크에서 페이지가 정상으로 보인다 (깨진 글씨, 흑백 화면 아님)
- [ ] 저장소에 `index.html`, `style.css`, `script.js`, `README.md`, `회고.md`가 있다
- [ ] 커밋이 3개 이상이고, 메시지가 "수정", "ㅇㅇ" 같은 것이 아니다
- [ ] `회고.md`에 1주차와 2주차가 모두 있다
- [ ] 저장소가 **Public**이다

## 이번 주 자주 막히는 지점

| 증상 | 원인과 해결 |
|---|---|
| 소스 제어에 "Git을 찾을 수 없습니다" | Git 설치 후 VS Code를 재시작하지 않았다 |
| Initialize Repository 버튼이 없다 | 폴더를 열지 않고 파일만 열었다 |
| Publish Branch가 안 보인다 | 커밋을 한 번도 안 했다. 먼저 커밋한다 |
| GitHub 로그인이 계속 실패한다 | 학교 와이파이 문제일 수 있다. 테더링으로 한 번 성공시킨다 |
| GitHub에 파일이 안 보인다 | 커밋만 하고 Sync/Push를 안 했다 |
| 배포 주소에서 404 | `index.html`이 저장소 최상단에 있는지 / Public인지 / 2분 기다렸는지 |
| 배포 주소는 열리는데 흑백이다 | CSS 경로 문제. AI에게 "style.css 경로를 상대 경로로 고쳐 줘" 요청 |
| 고쳤는데 배포 주소가 그대로다 | 커밋+Sync 했는지 확인 → `Ctrl+F5`로 강력 새로고침 (브라우저 캐시) |
| 배포는 됐는데 글씨가 □로 깨진다 | `index.html`에 `<meta charset="UTF-8">` 확인 |
| 되돌리기를 눌렀는데 아무 일도 안 난다 | 그 변경이 이미 커밋되어 있다. 되돌릴 "변경"이 없는 상태다 |

Git 관련 더 자세한 문제는 **부록 D**를 본다.
