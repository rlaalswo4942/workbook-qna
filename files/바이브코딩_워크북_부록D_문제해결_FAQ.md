## D.0 어디에도 없을 때 — AI에게 물어보는 양식

막혔을 때 "안 돼요"라고만 하면 AI도 못 고친다. 아래 양식에 맞춰 물어보면 대부분 해결된다.

```
Windows에서 VS Code로 순수 HTML/CSS/JS 웹 게임을 만들고 있어.
(Node.js나 빌드 도구는 쓰지 않아.)

하려던 것:
(예: GitHub Pages로 배포한 주소를 열려고 했다)

실제로 일어난 것:
(예: 404 페이지가 나온다)

에러 메시지 (있으면 그대로 복사):
```
(여기에 붙여넣기)
```

이미 시도한 것:
(예: 2분 기다렸다 / 새로고침했다)

원인으로 의심되는 것을 가능성이 높은 순서로 알려 주고,
각각 확인 방법을 알려 줘.
```

**에러 메시지는 요약하지 말고 그대로 복사한다.** 한 글자 차이로 원인이 달라진다. 단, 복사할 때 개인정보(이름, 경로에 들어간 실명 등)가 섞이지 않았는지 한 번 본다.

## D.1 VS Code

### 왼쪽에 폴더 이름이 안 보인다 / AI가 다른 파일을 못 찾는다
파일 하나만 열었다. **파일 → 폴더 열기**로 폴더째 연다. 왼쪽 맨 위에 폴더 이름이 대문자로 보이는 게 정상이다.

### 저장했는데 브라우저가 그대로다
- `Ctrl+S`로 저장했는지 확인한다. 탭 제목에 점(●)이 있으면 저장 안 된 상태다
- Live Server로 열었는지 확인한다 (주소가 `127.0.0.1:5500`)
- 브라우저 캐시일 수 있다 → `Ctrl+F5`

### "Go Live" 글자가 사라졌다
Live Server 확장이 비활성화되었다. `Ctrl+Shift+X` → Live Server 검색 → Enable 또는 재설치 후 VS Code 재시작.

### 한글이 □ 또는 ???로 보인다
HTML 파일에 아래 줄이 있는지 확인한다. 없으면 AI에게 "`index.html`에 UTF-8 meta 태그를 추가해 줘"라고 요청한다.
```html
<meta charset="UTF-8">
```

### 파일이 자동으로 안 보이거나 사라진 것 같다
OneDrive 동기화 폴더(`문서`가 OneDrive로 연결된 경우)에서 작업하면 파일이 클라우드로 올라가 있을 수 있다. 가능하면 OneDrive 밖의 경로(예: `C:\dev\vibe-coding`)를 쓴다.

## D.2 Git 설치와 설정

### 소스 제어에 "Git을 찾을 수 없습니다 (Git not found)"
1. [git-scm.com](https://git-scm.com) 에서 Git을 설치했는지 확인
2. **설치 후 VS Code를 완전히 종료하고 다시 실행한다** (가장 흔한 원인)
3. 그래도 안 되면 컴퓨터를 재부팅한다

### "Make sure you configure your user.name and user.email"
Git에 내가 누군지 알려 주지 않았다. VS Code 터미널(`Ctrl+\``)에 아래를 한 번만 입력한다.
```
git config --global user.name "내 이름"
git config --global user.email "github가입이메일@example.com"
```
> 이 수업에서 터미널을 쓰는 거의 유일한 경우다.

### Initialize Repository 버튼이 안 보인다
폴더를 열지 않았다. 폴더를 열면 나타난다.

### 이미 Git 저장소인데 또 초기화했다
`my-game` 안에 또 다른 저장소를 만들면 이력이 꼬인다. 폴더를 하나만 쓴다. 꼬였으면 폴더에서 숨김 폴더 `.git`을 삭제하고 처음부터 다시 초기화한다. (파일 자체는 안 지워진다. 단, **커밋 이력은 사라진다**)

## D.3 커밋과 되돌리기

### 커밋 버튼을 눌렀는데 "스테이지에 올라간 변경이 없습니다"
변경 파일을 Git에 알려 주지 않은 상태다. 나오는 안내에서 **Yes / Always** 를 고르면 전부 올라간다.

### 되돌리기(Discard Changes)를 눌렀는데 아무 변화가 없다
되돌릴 "변경"이 없는 상태다. 이미 커밋되었기 때문이다. 커밋된 지점으로 돌아가려면 **D.3의 아래 항목**을 본다.

### 커밋까지 한 뒤에 망가진 걸 발견했다
직전 커밋을 취소하고 싶을 때, VS Code 소스 제어 패널의 `⋯` 메뉴 → **Commit → Undo Last Commit**. 파일 내용은 그대로 남고 커밋만 취소되므로, 이후 되돌리기를 쓸 수 있다.

여러 단계 전으로 돌아가야 한다면 **AI에게 물어보는 게 가장 빠르다.**
```
Git으로 "3번째 커밋 전 상태"로 돌아가고 싶어.
VS Code의 소스 제어 화면에서 클릭으로 할 수 있는 방법을 알려 주고,
없으면 터미널 명령어를 한 줄씩 설명과 함께 알려 줘.
작업 중인 파일을 잃지 않는 방법을 우선으로 해 줘.
```

### 실수로 되돌려서 작업한 걸 날렸다
커밋하지 않은 변경은 되돌리면 복구할 수 없다. 그래서 **"잘 돌아간다"고 확인한 순간마다 커밋한다.** 다음부터 AI에게 큰 요청을 보내기 직전에 커밋하는 습관을 들인다.

### 커밋 목록을 어디서 보나
소스 제어 패널의 **Graph** 또는 **Commits** 섹션에서 볼 수 있다. 보기 좋게 보려면 확장 **Git Graph** 또는 **GitLens**를 설치한다 (선택).

## D.4 GitHub 업로드

### GitHub 로그인이 계속 실패한다
- 학교 와이파이가 인증 통신을 막는 경우가 있다 → **휴대폰 테더링으로 한 번만** 로그인 성공시키면 이후 유지된다
- 브라우저에서 GitHub에 이미 로그인되어 있는지 확인한다

### Publish Branch / Publish to GitHub 가 안 보인다
커밋을 한 번도 하지 않았다. 먼저 커밋한다.

### GitHub에 파일이 하나도 안 보인다
커밋만 하고 올리지 않았다. **Sync Changes** 또는 **Push**를 누른다.

### "Authentication failed" 또는 권한 오류
저장된 로그인 정보가 만료됐다. Windows **자격 증명 관리자**에서 `git:https://github.com` 항목을 삭제한 뒤 다시 Push하면 로그인 창이 뜬다.

### 저장소를 잘못된 이름으로 만들었다
GitHub 저장소 → **Settings** → 맨 위 **Repository name** 에서 바꿀 수 있다. 바꾸면 **배포 주소도 같이 바뀐다**는 점에 주의한다. (제출한 링크를 다시 알려야 한다)

### 실수로 Private으로 만들었다
저장소 → **Settings** → 맨 아래 **Danger Zone** → **Change visibility** → Public.

## D.5 GitHub Pages 배포

### 배포 주소에서 404가 나온다
가능성이 높은 순서대로 확인한다.

1. **`index.html`이 저장소 최상단에 있는가** — 하위 폴더에 있으면 안 열린다. GitHub 저장소 첫 화면에서 `index.html`이 바로 보여야 한다
2. **파일 이름이 정확히 `index.html`인가** — `Index.html`, `index.HTML`, `index.html.txt` 모두 안 된다
3. **Settings → Pages에서 Branch가 `main`, 폴더가 `/ (root)`로 되어 있는가**
4. **아직 배포 중인가** — 처음 배포는 최대 3~5분 걸린다. 2분 기다리고 `Ctrl+F5`
5. **저장소가 Public인가**

### 주소 끝에 `/`를 빼면 안 열린다
정상이다. `https://아이디.github.io/my-game/` 처럼 **끝에 슬래시를 붙여서** 공유한다.

### 배포 주소는 열리는데 CSS가 적용되지 않는다 (흑백 화면)
경로 문제다. `index.html` 안에서 CSS를 **절대 경로**로 불렀을 가능성이 높다.

```html
<link rel="stylesheet" href="/style.css">   <!-- ❌ 배포에서 깨진다 -->
<link rel="stylesheet" href="style.css">    <!-- ⭕ 이렇게 -->
```

AI에게 이렇게 요청한다.
```
GitHub Pages에 배포했는데 CSS와 JS가 적용되지 않아.
index.html의 모든 파일 경로를 상대 경로로 바꿔 줘.
맨 앞의 / 를 없애는 방식으로.
```

### 이미지가 로컬에서는 보이는데 배포하면 안 보인다
세 가지를 확인한다.

1. **이미지 파일이 저장소에 올라갔는가** — GitHub 저장소에서 직접 눈으로 확인한다
2. **파일 이름의 대소문자가 정확한가** — Windows는 `Cat.png`와 `cat.png`를 같은 것으로 보지만, **GitHub Pages는 다른 것으로 본다.** 배포에서만 이미지가 깨지는 가장 흔한 원인이다
3. **파일 이름에 한글·공백이 없는가** — `내 캐릭터.png` ❌ → `player.png` ⭕

### 고쳤는데 배포 주소에 반영되지 않는다
1. 커밋했는가
2. Sync/Push 했는가 (GitHub 저장소에서 파일 내용을 직접 확인하면 확실하다)
3. 1~2분 기다렸는가
4. `Ctrl+F5` (강력 새로고침) — 브라우저가 옛 파일을 기억하고 있을 수 있다
5. 그래도 안 되면 저장소 → **Actions** 탭에서 배포가 실패(빨간 X)했는지 본다

### 휴대폰에서는 안 열린다
- 와이파이를 끄고 데이터로 열어 본다 (학교 와이파이 문제 구분용)
- 주소를 직접 타이핑하지 말고 복사해서 보낸다 (대소문자 오타가 흔하다)
- 저장소가 Public인지 다시 확인한다

## D.6 브라우저

### 변경이 반영되지 않는다 (캐시)
`Ctrl+F5` 또는 `Ctrl+Shift+R`. 개발 중에는 개발자 도구(`F12`)를 열어 두면 캐시가 덜 문제 된다.

### 어디서 에러를 보나
`F12` → **Console** 탭. 빨간 글씨가 에러다. 7장에서 본격적으로 다루지만, 지금부터 "뭔가 안 될 때 F12를 눌러 본다"는 습관을 들이면 좋다.

### 콘솔에 빨간 에러가 있는데 무슨 말인지 모르겠다
그 줄을 **그대로 복사해서** AI에게 보낸다. D.0의 양식을 쓴다. 영어 에러 메시지도 그대로 붙이면 된다.

## D.7 에러 메시지별 대처 (7장부터)

> 콘솔(`F12`)의 **맨 위 첫 번째 에러**부터 본다. 루프 안에서 에러가 나면 수백 개가 쌓이지만, 원인은 하나다.
> 에러 뒤의 `script.js:47` 부분을 **클릭하면 그 줄로 바로 간다.**

### `SyntaxError` / `Unexpected end of input` / `Unexpected token`
**문법이 깨졌다. 코드 전체가 실행되지 않아 화면이 아예 안 뜬다.**

1. 괄호 `()`, 중괄호 `{}`, 대괄호 `[]`의 **짝**을 확인한다. VS Code에서 괄호를 클릭하면 짝이 표시된다
2. 직접 코드를 고치다 생긴 경우가 대부분이다 → `Ctrl+Z` 또는 2장의 되돌리기
3. 어디인지 모르겠으면: `"SyntaxError가 나는데 괄호 짝이 안 맞는 곳을 찾아 줘. 동작은 바꾸지 마."`

### `ReferenceError: ○○ is not defined`
**그 이름을 모른다.** 가장 흔한 에러.

1. **오타 확인** — `ballX`와 `ballx`는 다른 이름이다 (대소문자 구분)
2. **선언 확인** — `let ○○ = ...` 줄이 있는지, 지워지지 않았는지
3. **순서 확인** — 선언보다 먼저 쓰고 있지 않은지

### `TypeError: Cannot read properties of null (reading 'getContext')`
**도화지를 못 찾았다.**

1. `index.html`의 `<canvas id="game">`와 `getElementById("game")`의 이름이 같은지
2. `<canvas>` 태그가 지워지지 않았는지
3. `script.js`가 HTML보다 먼저 실행되고 있지 않은지 → `"script 태그를 body 맨 끝으로 옮겨 줘"`

### `TypeError: Cannot read properties of undefined (reading 'x')`
**없는 칸의 속을 보려 했다.** 배열 문제가 대부분.

1. 배열 번호가 범위를 넘었다 — 번호는 **0부터**, 마지막은 `length - 1`
2. 반복 중에 배열에서 요소를 제거했다 → `"뒤에서 앞으로 반복하는 방식으로 바꿔 줘"`
3. 객체에 그 속성이 없다 — `enemy.size`인데 만들 때는 `radius`로 넣었다거나

### 화면에 `NaN`이 표시된다
**숫자가 아닌 값으로 계산했다.**

1. 숫자에 글자가 섞였다 (`score + "1"`)
2. 초기값을 넣지 않은 변수로 계산했다
3. `console.log`로 계산 직전 값을 찍어 본다 → 어느 값이 `undefined`인지 보인다

### `Uncaught (in promise)` / 소리 관련 에러 (8장)
브라우저가 **사용자 조작 전에는 소리를 막는다.** 8장에서 다룬다. "클릭이나 키 입력 후에 소리를 재생하게 해 줘"로 해결한다.

### 에러가 수백 개 쌓인다
루프 안에서 에러가 나고 있다. **맨 위 첫 에러 하나만** 보고 고치면 전부 사라진다.

### 에러는 없는데 결과가 이상하다 (조용한 버그)
에러 메시지가 없으면 **값을 직접 봐야 한다.**

| 증상 | 먼저 확인할 값 |
|---|---|
| 안 보인다 | 좌표(화면 밖인지), 크기(0인지), 색(배경과 같은지) |
| 안 움직인다 | 속도 값, 계산이 루프 안에 있는지 |
| 너무 빠르다 | `gameLoop()`를 두 번 부르지 않았는지 (루프 중복) |
| 판정이 안 맞는다 | `showHitbox`를 켜서 테두리를 눈으로 확인 |
| 점수가 폭주한다 | 증가하는 줄에 조건이 걸려 있는지 |
| 재시작 후 이상하다 | `resetGame`에서 안 되돌린 값이 있는지 |

그다음 `console.log`로 **범위를 반으로 좁혀 간다** (7장 2.4).

## D.8 API와 온라인 랭킹 (11장 · 심화)

### 먼저 알아 둘 것 — RLS 차단은 에러로 오지 않는 경우가 있다

| 동작 | 정책이 없을 때 |
|---|---|
| 읽기(SELECT) | **`200` + 빈 목록 `[]`** — 에러가 아니다 |
| 등록(INSERT) | `403` 에러 |
| 수정·삭제(UPDATE/DELETE) | **`204`** — 성공처럼 보이고 0개가 처리된다 |

그래서 **응답 코드로 "막혔는지"를 판단하면 거꾸로 읽는다.** 삭제가 막혔는지는 **표의 행 수가 그대로인지**로 확인한다.

### `401 Unauthorized`
**키/헤더 문제이고 RLS와 무관하다.**

1. `apikey` 헤더가 빠졌는지
2. 키가 복사 중 잘렸는지 (키는 길다 — 앞뒤가 온전한지 확인)
3. 다른 프로젝트의 키를 쓰고 있지 않은지

### `403 Forbidden`
**등록(INSERT)이 거부된 것이다.**

1. INSERT 정책이 있는가
2. 정책의 대상이 **anon/public**인가 (로그인 사용자만으로 되어 있지 않은가)
3. 정책의 `with check` 조건에 걸렸는가 — 점수 범위, 이름 길이 제한을 벗어난 값을 보내지 않았는지
4. 보내지 않아야 할 열(`id`, `created_at`)을 보내고 있지 않은지

### 랭킹이 **빈 목록**으로 온다 (에러는 없다)
**SELECT 정책이 없는 것이다.** 표에 행이 있는데도 `[]`가 오면 거의 확실하다. Table Editor에서 행이 실제로 있는지 먼저 확인하고, 있으면 SELECT 정책을 만든다.

### `CORS` 에러
CORS는 **상대 서버가 "브라우저에서 직접 부르는 것을 허용하는가"** 를 정한 정책이다. **내 코드로는 고칠 수 없다.**

1. **키 없는 공개 API 연습(11장 Step 1)에서 났다면** → 그 API가 브라우저 호출을 허용하지 않는 것이다. **허용하는 다른 API로 바꾼다.** 코드를 고쳐도 해결되지 않는다
2. Supabase 호출에서 났다면 → 주소가 아예 다른 곳을 가리키고 있을 가능성이 크다. 프로젝트 URL과 경로(`/rest/v1/표이름`)를 확인한다
3. 브라우저 **Network 탭**에서 실제로 어느 주소로 보내는지 본다

> 주소를 틀리면 보통 `404`, 키를 틀리면 `401`이 온다. **CORS 에러는 그것들과 다른 문제**이고, "상대가 허락하지 않았다"는 뜻이다.

### `undefined`가 나온다
`await`을 빠뜨렸다. 요청이 끝나기 전에 값을 쓰고 있다.

```javascript
const res = fetch(url);          // ❌ 아직 안 온 답
const res = await fetch(url);    // ⭕
```

### 랭킹이 안 뜨는데 콘솔에 에러도 없다
`try/catch`가 에러를 삼키고 있다. `catch` 블록 안에 `console.log(e)`를 넣어 실제 오류를 본다.

### 점수가 글자로 저장되거나 정렬이 이상하다
표의 열 형식이 `text`다. `int`로 만들고, 보낼 때 `Number()`로 변환한다. 8장 `localStorage`의 `"9" > "100"` 문제와 같은 뿌리다.

### 등록이 여러 번 중복된다
게임 오버 상태에서 **매 프레임** 등록 요청이 나가고 있다. "이번 게임에서 이미 등록했는가"를 기억하는 변수를 두고 한 번만 보낸다.

### 게임이 아예 안 뜬다
요청 코드에 문법 오류가 있을 가능성이 크다. 콘솔의 **첫 번째 에러**를 보고, 안 되면 **시작 전 커밋으로 되돌린다**.

### 로컬은 되는데 배포하면 안 된다
1. 키·주소 오타 (복사 중 잘림)
2. 파일 커밋·Sync 누락
3. 외부 서비스가 HTTPS만 허용하는 경우 — GitHub Pages는 HTTPS이므로 보통 문제없다

### 비밀 키를 실수로 올렸다
**순서가 중요하다.**

1. **서비스 대시보드에서 그 키를 즉시 재발급·폐기한다**
2. 코드에서 지우고 커밋한다

2번만 하면 안 된다. **Git은 모든 이력을 보관하므로, 지운 키도 커밋 이력에서 조회할 수 있다.**

### 무료 범위를 넘었다는 알림이 온다
요청을 너무 자주 보내고 있을 가능성이 있다. 게임 루프 안에서 랭킹을 불러오고 있지 않은지 확인한다 — **랭킹은 게임 오버 시점에 한 번만** 불러온다.
