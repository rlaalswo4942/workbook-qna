# 6장. 규칙 만들기: 충돌, 점수, 승패

> **이번 주 목표** **처음부터 끝까지 플레이할 수 있는 게임**을 완성한다. 이번 과정의 분수령이다.

---

## 1. 학습 목표

이 장이 끝나면 다음을 할 수 있다.

- 배열과 객체로 여러 개의 물체를 한 번에 다룰 수 있다.
- 반복문(`for`)이 하는 일을 읽을 수 있다.
- 두 물체가 부딪혔는지 계산해서 알아낼 수 있다.
- 점수를 올리고 화면에 표시할 수 있다.
- 게임 오버와 재시작을 만들 수 있다.
- **플레이 가능한 게임 한 편**을 남에게 보여 줄 수 있다.

---

## 2. 개념 설명

### 2.1 이번 주가 분수령인 이유

지금까지 만든 것은 "움직이고 조작되는 화면"이었다. 게임이 되기 위해 빠진 것은 **규칙**이다.

```
움직인다 + 조작된다          →  장난감
움직인다 + 조작된다 + 규칙   →  게임
```

규칙은 세 가지로 이루어진다.

| 규칙 | 질문 | 이번 주에 만드는 것 |
|---|---|---|
| **상호작용** | 무엇이 무엇에 닿으면 어떻게 되는가 | 충돌 판정 |
| **보상** | 잘하면 무엇을 얻는가 | 점수 |
| **실패** | 못하면 어떻게 되는가 | 게임 오버 |

이 셋이 들어가면 사람들이 "다시 한 번"을 누른다. 그 순간부터 게임이다.

### 2.2 배열 — 같은 것이 여러 개일 때

4장 선택 과제에서 물체를 2개 이상으로 늘려 본 사람은 이미 불편함을 느꼈을 것이다.

```javascript
let enemy1X = 100, enemy1Y = 0;
let enemy2X = 300, enemy2Y = 0;
let enemy3X = 500, enemy3Y = 0;
// 10개로 늘리려면? 30줄?
// 게임 중에 적이 하나 늘어나면? 코드를 고쳐야 한다?
```

**배열(array)은 같은 종류의 것을 줄 세워 담는 상자**다. 사물함 한 칸이 아니라, 번호가 붙은 사물함 한 줄이다.

```javascript
let scores = [10, 25, 40];     // 숫자 세 개를 담은 배열
```

| 쓰는 법 | 뜻 |
|---|---|
| `scores[0]` | 첫 번째 칸 → `10` |
| `scores[1]` | 두 번째 칸 → `25` |
| `scores.length` | 칸의 개수 → `3` |
| `scores.push(50)` | 맨 뒤에 하나 추가 |
| `scores.splice(1, 1)` | 두 번째 칸을 **빼낸다** |

**번호가 0부터 시작한다.** 프로그래밍에서 첫 번째는 0번이다. 이것이 이번 주 두 번째로 흔한 실수의 원인이다.

### 2.3 객체 — 하나의 물체가 가진 여러 값

적 하나에는 위치, 속도, 크기가 함께 붙어 다닌다. 이것들을 흩어 놓지 말고 **한 덩어리로 묶는 것**이 객체다.

```javascript
let enemy = { x: 100, y: 0, speed: 3, size: 20 };
```

꺼내 쓸 때는 점(`.`)을 쓴다. 점은 **"~의"** 라고 읽으면 된다.

```javascript
enemy.x           // enemy의 x → 100
enemy.y = enemy.y + enemy.speed;   // enemy의 y에 속도를 더한다
```

**배열과 객체를 합치면 이번 주의 핵심 도구가 된다.**

```javascript
let enemies = [
  { x: 100, y: 0,    speed: 3, size: 20 },
  { x: 300, y: -100, speed: 4, size: 20 },
  { x: 500, y: -200, speed: 2, size: 20 }
];
```

**"적들"이라는 이름 하나로 세 개(또는 백 개)를 다룰 수 있다.** 적이 늘어나도 코드는 그대로다.

### 2.4 반복문 — 배열 전체를 한 번에 처리한다

배열에 담았으니, 담긴 것 전부에 같은 일을 시켜야 한다. 그 도구가 **반복문**이다.

```javascript
for (let i = 0; i < enemies.length; i++) {
  enemies[i].y = enemies[i].y + enemies[i].speed;   // 적 하나를 아래로 이동
}
```

읽는 방법은 이렇다.

```
for (let i = 0;          i를 0부터 시작해서
     i < enemies.length; 적의 개수보다 작을 동안
     i++) {              i를 1씩 늘리면서
  ...                    중괄호 안을 반복한다
}
```

`i`는 **지금 몇 번째를 보고 있는지** 나타내는 번호다. 적이 3개면 `i`가 0, 1, 2로 바뀌면서 세 번 실행된다.

**이 다섯 줄이 적이 3개일 때도, 100개일 때도 똑같이 작동한다.** 배열을 쓰는 이유가 이것이다.

> **더 짧은 표기** — AI는 `enemies.forEach(enemy => {...})` 같은 형태를 쓸 수도 있다. 같은 일을 하는 다른 표기법이다. 어느 쪽이든 **"배열에 담긴 것 전부에 같은 일을 한다"** 로 읽으면 된다. 읽기 어려우면 AI에게 `"for 반복문 형태로 바꿔 줘"`라고 요청한다.

### 2.5 충돌 판정 — 부딪혔는지 계산으로 알아낸다

이번 주에서 가장 중요한 개념이다. 컴퓨터는 눈이 없어서, "닿았다"를 **숫자 비교로** 판단해야 한다.

**사각형끼리 — 네 조건이 모두 참이면 겹쳤다**

두 사각형이 겹치지 **않는** 경우를 생각하면 쉽다. 겹치지 않으려면 둘 중 하나는 상대의 **완전히 왼쪽, 완전히 오른쪽, 완전히 위, 완전히 아래**에 있어야 한다.

```
   A                          A가 B의 완전히 왼쪽에 있으면 → 안 겹친다
 ┌────┐    ┌────┐
 │ A  │    │ B  │
 └────┘    └────┘

   A와 B가 겹치려면, 그 네 가지가 모두 아니어야 한다
```

코드로 쓰면 이렇다.

```javascript
if (a.x < b.x + b.width &&      // A의 왼쪽이 B의 오른쪽보다 왼쪽에 있고
    a.x + a.width > b.x &&      // A의 오른쪽이 B의 왼쪽보다 오른쪽에 있고
    a.y < b.y + b.height &&     // A의 위가 B의 아래보다 위에 있고
    a.y + a.height > b.y) {     // A의 아래가 B의 위보다 아래에 있으면
  // 겹쳤다!
}
```

**네 줄을 외우지 않는다.** 대신 이것만 기억한다.

> **가로로도 겹치고, 세로로도 겹치면 → 부딪힌 것이다.**

`&&`(그리고)로 네 조건이 모두 참이어야 한다는 점, 그리고 **`+ width`가 들어가는 이유**(x는 왼쪽 위 꼭짓점이므로 오른쪽 끝은 x + 가로)는 5장에서 벽을 막을 때 이미 본 계산이다.

**원끼리 — 거리가 반지름 합보다 작으면 겹쳤다**

원은 훨씬 직관적이다.

```javascript
const dx = a.x - b.x;                      // 가로 거리 차이
const dy = a.y - b.y;                      // 세로 거리 차이
const distance = Math.sqrt(dx * dx + dy * dy);   // 두 중심 사이의 거리

if (distance < a.radius + b.radius) {
  // 겹쳤다!
}
```

`Math.sqrt`는 제곱근이고, 이 식은 중학교에서 배운 **피타고라스 정리**다. 두 점 사이의 거리를 구하는 것이다.

```
    중심 거리  <  반지름 합   →   겹쳤다
       ●━━━━━━●
      (  )  (  )
```

**어느 것을 쓸까?** 내 게임의 모양에 맞춰 고른다.

| 물체 모양 | 쓰는 방식 |
|---|---|
| 사각형 + 사각형 | 사각형 방식 |
| 원 + 원 | 원 방식 |
| 사각형 + 원 | 둘 다 사각형으로 취급해도 괜찮다 (초보 수준에서는 충분). 단 **원을 사각형으로 바꿀 때 좌표를 변환해야 한다** — 중심 `(x, y)`, 반지름 `r`인 원은 왼쪽 위가 `(x - r, y - r)`이고 가로·세로가 `2r`인 사각형이다 |
| 그림 이미지 | 그림을 감싸는 **사각형**으로 취급한다 |

> **중요: 정확도보다 "느낌"이 우선이다.** 그림이 어떤 모양이든, 보통은 그 그림을 감싸는 사각형으로 판정한다. 실제 게임들도 대부분 그렇게 한다. 판정이 너무 빡빡하면 **판정용 사각형을 그림보다 조금 작게** 만들면 훨씬 할 만해진다. 이것도 튜닝이다.

**판정이 눈에 보이게 하는 기술** — 7장에서 쓸 디버깅 기법이지만 이번 주에 미리 쓴다. 판정용 사각형을 **테두리로 그려 두면** 왜 안 맞는지 눈으로 보인다.

```
AI에게: "충돌 판정에 쓰는 영역을 빨간 테두리 사각형으로 그려 줘.
         나중에 끌 수 있게 showHitbox 라는 변수로 켜고 끌 수 있게 해 줘."
```

### 2.6 게임 상태 — 지금 플레이 중인가, 끝났는가

게임 오버를 만들려면 게임이 **지금 어떤 상태인지** 기억해야 한다. 4장에서 배운 "상태"가 확장되는 것이다.

```javascript
let gameState = "playing";     // "playing" 또는 "gameover"
let score = 0;
```

그리고 루프가 상태에 따라 다르게 행동한다.

```javascript
function gameLoop() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  if (gameState === "playing") {
    // 계산: 적 이동, 충돌 검사, 점수 증가
    // 그리기: 플레이어, 적, 점수
  } else {
    // 게임 오버 화면: "GAME OVER", 최종 점수, "R키로 재시작"
  }

  requestAnimationFrame(gameLoop);
}
```

**루프는 멈추지 않는다.** 게임 오버가 되어도 `requestAnimationFrame`은 계속 돌면서 "게임 오버 화면"을 그린다. 이 구조가 8장의 시작 화면 전환으로 바로 이어진다.

> **왜 루프를 멈추지 않는가?** 멈춰 버리면 재시작할 방법이 없다. 루프는 계속 돌면서 `gameState`만 바꿔 주는 것이 훨씬 다루기 쉽다. 8장에서 `"start"` 상태를 하나 더 추가하면 시작 화면이 된다.

### 2.7 점수와 게임 오버 조건

**점수가 오르는 방식은 세 가지 중 하나다.**

| 방식 | 코드로는 | 어울리는 게임 |
|---|---|---|
| 시간이 지나면 | 매 프레임 조금씩 더한다 | 피하기, 버티기 |
| 무언가에 닿으면 | 충돌 시 더한다 | 아이템 먹기 |
| 무언가를 없애면 | 충돌 시 더하고 적을 제거한다 | 맞추기, 슈팅 |

시간 점수는 주의할 점이 두 가지 있다.

**① 매 프레임 1을 더하면 1초에 60점이 된다.** 숫자가 금방 터무니없이 커진다.

**② 프레임 수를 세서 60으로 나누면 기기마다 점수가 달라진다.** 4장에서 본 것처럼 `requestAnimationFrame`은 화면 주사율에 맞춰 돌기 때문에, 120Hz 노트북이나 휴대폰에서는 1초에 120번 돌아 점수가 **두 배로** 오른다.

그래서 **프레임을 세지 않고, 실제로 흐른 시간을 쓴다.**

```javascript
let startTime = Date.now();                              // 게임 시작 순간을 기록

// 매 프레임
const elapsed = Math.floor((Date.now() - startTime) / 1000);   // 흐른 시간(초)
score = elapsed;                                               // 1초에 1점
```

`Date.now()`는 **지금 시각을 밀리초로** 돌려준다. 시작 시각을 빼면 흐른 시간이고, 1000으로 나누면 초다. **어느 기기에서든 1초는 1초**이므로 점수가 같다.

`Math.floor`는 소수점을 버리는 명령이다. 점수를 표시할 때는 정수로 만들어야 보기 좋다.

> **`resetGame`에서 `startTime`도 되돌려야 한다.** 빠뜨리면 재시작했을 때 점수가 이전 판에서 이어진다.

**게임 오버 조건도 세 가지 중 하나다.**

- 부딪히면 즉시 끝 (가장 간단하다. 첫 버전에 권장)
- 생명(목숨)이 0이 되면 끝 (`let lives = 3;`)
- 시간이 다 되면 끝 (제한 시간형)

**재시작**은 상태를 처음 값으로 되돌리는 것이다.

```javascript
function resetGame() {
  score = 0;
  player.x = 400;
  enemies = [ /* 처음 배치 */ ];
  gameState = "playing";
}
```

"처음으로 돌려놓는 함수 하나"를 만들어 두면, 8장에서 시작 화면을 만들 때도 그대로 쓴다.

## 3. 따라 하기 실습

작업 폴더는 **`my-game`** 이다.

> **시작 전에 반드시 커밋한다.** 소스 제어 → `6장 시작 전 상태` → Commit. **이번 주는 코드가 가장 많이 바뀐다.** 커밋 없이 시작하면 되돌릴 곳이 없다.

> **이번 주 전략: 한 번에 다 요청하지 않는다.** Step 1~4를 하나씩, 각 단계가 작동하는 걸 확인하고 **커밋한 뒤에** 다음으로 간다. 한꺼번에 요청하면 어디가 잘못됐는지 찾을 수 없다.

### Step 1. 여러 개를 배열로 바꾼다 (12분)

```
지금 script.js에서 (적 / 장애물 / 아이템)을 배열과 객체로 바꿔 줘.

- enemies 라는 배열에 { x, y, speed, size } 형태의 객체를 담아 줘
- 처음에 3개를 서로 다른 x 위치, 서로 다른 속도로 배치해 줘
- 게임 루프에서 for 반복문으로 전부 이동시키고 전부 그려 줘
- 화면 아래로 벗어나면 다시 위쪽의 랜덤한 x 위치에서 나타나게 해 줘
- 개수와 크기는 변수로 코드 위쪽에 모아 줘
- 아직 충돌 판정은 넣지 마
- 한국어 주석을 달아 줘
```

확인한다.

- [ ] 적 3개가 각각 다른 속도로 움직인다
- [ ] 아래로 사라지면 위에서 다시 나타난다
- [ ] 플레이어 조작이 여전히 된다

**개수를 바꿔 본다.** 배열 쪽 숫자를 3 → 8로 고치면 적이 8개로 늘어난다. **코드를 늘리지 않고 숫자만 바꿔서 늘어나는 것**을 확인한다. 이게 배열의 힘이다.

확인했으면 **커밋한다** (`적을 배열로 변경`).

### Step 2. 충돌 판정을 넣는다 (15분)

이번 주의 핵심이다.

```
플레이어와 enemies 배열의 적들 사이에 충돌 판정을 넣어 줘.

- 사각형끼리 겹치는지 판정하는 방식으로 (가로도 겹치고 세로도 겹치면 충돌)
- 판정하는 부분을 checkCollision 이라는 함수로 따로 만들어 줘
- 충돌하면 일단 콘솔에 "충돌!" 이라고만 출력해 줘
  (게임 오버는 다음 단계에서 할 거야)
- 충돌 판정에 쓰는 영역을 빨간 테두리로 그려 줘.
  showHitbox 라는 변수로 켜고 끌 수 있게 해 줘
- 한국어 주석을 달아 줘
```

`F12` 콘솔을 열어 두고 **일부러 적에게 부딪혀 본다.** "충돌!"이 찍히면 판정이 작동하는 것이다.

**빨간 테두리를 보면서 확인한다.**

- [ ] 테두리가 플레이어와 적을 **정확히 감싸고 있는가**
- [ ] 닿기 전에 충돌이 뜨지 않는가 (테두리가 너무 크다)
- [ ] 겹쳤는데 충돌이 안 뜨지 않는가 (판정 코드 문제)

> 테두리와 그림이 어긋나 있으면, 그림 그리는 좌표와 판정하는 좌표가 다르다는 뜻이다. **같은 변수를 쓰도록** AI에게 요청한다.

커밋한다 (`충돌 판정 추가`).

### Step 3. 점수를 넣는다 (8분)

기획서 5번에 정한 방식으로 요청한다.

**시간형이라면**
```
버틴 시간을 점수로 만들어 줘.
- Date.now()로 시작 시각을 기록해 두고, 흐른 시간(초)을 점수로 써 줘
  (프레임 수를 세는 방식은 쓰지 마. 120Hz 기기에서 점수가 두 배가 되니까)
- Math.floor로 정수로 만들어 줘
- resetGame에서 시작 시각도 초기화해 줘
- 왼쪽 위에 "점수: 12" 형태로 흰 글씨로 표시해 줘
```

**닿으면 오르는 형태라면**
```
플레이어가 (아이템)에 닿으면 점수가 10점 오르고,
그 아이템은 배열에서 제거한 뒤 위쪽의 랜덤한 위치에 새로 만들어 줘.
점수는 왼쪽 위에 "점수: 0" 형태로 표시해 줘.
```

확인한다.

- [ ] 점수가 화면에 보인다
- [ ] 의도한 조건에서 오른다
- [ ] 숫자가 소수점 없이 깔끔하다

커밋한다 (`점수 시스템 추가`).

### Step 4. 게임 오버와 재시작 (12분)

```
게임 오버와 재시작을 넣어 줘.

- gameState 변수로 "playing"과 "gameover"를 구분해 줘
- 플레이어가 적에 닿으면 gameState를 "gameover"로 바꿔 줘
- 게임 오버 상태에서는:
  - 적과 플레이어가 멈춘다
  - 화면 가운데에 큰 글씨로 "GAME OVER"
  - 그 아래에 "최종 점수: ○○"
  - 그 아래에 작은 글씨로 "R 키를 눌러 다시 시작"
- R 키를 누르면 점수와 위치를 처음 상태로 되돌리고 다시 시작하게 해 줘
  (처음으로 되돌리는 부분은 resetGame 함수로 만들어 줘)
- 게임 루프는 멈추지 말고, gameState에 따라 다르게 그리는 구조로 해 줘
- 한국어 주석을 달아 줘
```

**여기까지 하면 플레이 가능한 게임이다.** 끝까지 한 판 해 본다.

- [ ] 조작한다 → 피한다 → 부딪힌다 → GAME OVER가 뜬다
- [ ] 최종 점수가 보인다
- [ ] R을 누르면 처음부터 다시 시작된다
- [ ] 재시작 후 점수가 0으로 돌아간다

> **재시작했는데 점수가 안 돌아가거나 적이 이상한 위치에 있으면**, `resetGame`에서 되돌려야 할 값을 빠뜨린 것이다. "재시작할 때 되돌려야 하는 값을 전부 점검해 줘"라고 요청한다.

커밋한다 (`게임 오버와 재시작 구현`).

### Step 5. 코드를 읽는다 (8분)

```
script.js를 구역별로 설명해 줘. 특히 이 네 가지를.
1) enemies 배열과 for 반복문이 하는 일
2) checkCollision 함수의 네 조건이 각각 무슨 뜻인가
3) gameState가 왜 필요한가
4) resetGame이 되돌리는 값들은 무엇이고, 왜 그것들인가
```

읽고 나서 직접 짚어 본다.

- [ ] 상태 변수들이 모여 있는 곳 (`score`, `gameState`, `enemies`)
- [ ] 반복문으로 적을 움직이는 곳
- [ ] 충돌을 검사하는 곳
- [ ] 게임 오버 화면을 그리는 곳

### Step 6. 난이도 튜닝 (8분)

**AI 없이** 숫자만 만진다. 한 판씩 플레이하면서 조정한다.

| 만질 숫자 | 너무 쉬울 때 | 너무 어려울 때 |
|---|---|---|
| 적의 개수 | 늘린다 | 줄인다 |
| 적의 속도 | 올린다 | 내린다 |
| 적의 크기 | 키운다 | 줄인다 |
| 플레이어 속도 | 내린다 | 올린다 |
| 판정 영역 크기 | 그대로 | 조금 줄인다 |

**목표: 내가 플레이해서 10~30초 정도 버티는 수준.** 3초에 죽으면 아무도 다시 안 하고, 5분을 버티면 지루하다.

조정이 끝나면 `showHitbox`를 꺼 둔다 (`false`). **7장에서 다시 켤 일이 있으니 코드는 지우지 않는다.**

### Step 7. 커밋하고 배포, 그리고 남에게 보여 준다 (5분)

1. 소스 제어 → `난이도 조정` → **Commit** → **Sync Changes**
2. 배포 주소에서 한 판 플레이한다
3. **친구나 가족에게 링크를 보낸다**

> 이번 주 과제에 플레이테스트가 들어 있다. 9장에서 본격적으로 하지만, **처음 남에게 보여 주는 경험은 이번 주에 한다.** 내가 만든 것을 남이 플레이하는 것을 보면, 고쳐야 할 것이 한꺼번에 보인다.

## 4. 내 게임에 적용하기 (과제)

### 과제 1. 플레이 가능한 최소 버전 완성 (필수 — 이번 주 핵심)

아래 다섯 가지가 **모두** 되어야 한다.

- [ ] 시작하면 바로 플레이할 수 있다
- [ ] 플레이어를 조작할 수 있다
- [ ] 충돌(또는 상호작용)이 판정된다
- [ ] 점수가 오르고 화면에 보인다
- [ ] 게임 오버가 되고, 재시작할 수 있다

> **"최소 버전"의 의미** — 멋지지 않아도 된다. 소리도, 시작 화면도, 예쁜 그림도 없어도 된다. **처음부터 끝까지 한 판이 돌아가면 된다.** 꾸미기는 8장의 일이다. 반대로 이번 주에 이 다섯 개가 안 되면, 8~10장에서 할 일이 없어진다.

### 과제 2. 난이도 조정 기록 (필수)

플레이해 보고 조정한 내역을 표로 적는다. 4장·5장의 튜닝 표와 같은 형식이다.

```
| 바꾼 것 | 전 | 후 | 이유 |
|---|---|---|---|
| 적 개수 | 3 | 5 | 너무 쉬워서 30초 넘게 버텨졌다 |
| 적 속도 | 5 | 3 | 5는 반응할 틈이 없었다 |
| 판정 영역 | 그림과 같게 | 양쪽 4px 작게 | 스치기만 해도 죽는 느낌이었다 |
```

**내가 한 판에 버티는 시간**도 함께 적는다.

### 과제 3. 다른 사람에게 1회 이상 플레이시키기 (필수)

친구, 가족, 룸메이트 누구든 좋다. **옆에서 지켜보면서** 기록한다.

- 설명 없이 시작했을 때, **무엇을 해야 하는지 바로 알았는가?**
- 어디서 멈칫했는가?
- 몇 점을 받았는가? (내 점수와 비교)
- 그 사람이 한 말 중 가장 쓸모 있었던 것 한 줄

> 9장에서 이걸 제대로 한다. 이번 주는 **"남이 플레이하면 내 예상과 다르다"** 를 경험하는 것이 목적이다.

### 과제 4. 선택 과제

- 생명(목숨) 3개를 만들고, 부딪히면 하나 줄어들게 한다
- 시간이 지나면 **적이 점점 빨라지게** 한다 (8장 난이도 조절의 예습)
- 아이템을 추가한다 (먹으면 점수 추가 또는 일시 무적)
- 적이 **화면 밖에서 랜덤한 간격으로** 등장하게 한다
- 충돌 순간에 **화면이 살짝 흔들리거나 색이 번쩍이게** 한다

### 과제 5. 회고 파일 (필수)

양식은 **부록 E**와 같다. 6주차는 아래를 포함한다.

- **1번:** Step 1~4 중 두 개의 요청을 복사한다. **한꺼번에 요청하지 않고 단계별로 나눈 이유**도 한 줄 적는다
- **2번:** 막힌 점. 이번 주는 소재가 많다 — 판정이 안 맞았다, 재시작했는데 값이 안 돌아갔다, 적이 겹쳐서 나왔다 등
- **3번:** 코드 설명. **이번 주는 `checkCollision` 함수에서 고른다.** 네 조건 중 하나를 골라 "이 조건이 없으면 어떤 경우에 잘못 판정되는가"까지 쓴다

## 이번 주 자주 막히는 지점

| 증상 | 원인과 해결 |
|---|---|
| 적이 하나만 움직인다 | 반복문 안에서 `enemies[i]`를 쓰지 않고 특정 하나만 건드리고 있다 |
| 적이 전부 같은 자리에 겹쳐 있다 | 처음 위치를 모두 같게 줬다. x와 y를 다르게 또는 랜덤으로 |
| `undefined` 에러가 난다 | 배열 번호가 범위를 벗어났다. 0부터 시작하므로 **마지막은 `length - 1`** |
| 닿기 전에 죽는다 | 판정 영역이 그림보다 크다. `showHitbox`를 켜서 눈으로 확인 |
| 겹쳤는데 아무 일도 없다 | 판정에서 `&&`가 `\|\|`로 되어 있거나, `+ width`가 빠졌다 |
| 충돌이 1초에 수십 번 일어난다 | 정상이다. 매 프레임 판정하기 때문. 점수가 폭주하면 "한 번 닿으면 그 적은 제거하거나 무적 시간을 줘"로 요청 |
| 점수가 1초에 60점씩 오른다 | 매 프레임 1을 더하고 있다. `Date.now()`로 흐른 시간을 쓴다 |
| 휴대폰에서 점수가 두 배로 오른다 | 프레임 수를 세고 있다. 주사율이 다르면 달라진다 → `Date.now()` 방식으로 |
| 점수에 소수점이 길게 붙는다 | `Math.floor()`로 정수로 만든다 |
| 게임 오버 후에도 적이 움직인다 | 이동 코드가 `if (gameState === "playing")` 안에 들어 있지 않다 |
| R을 눌러도 재시작이 안 된다 | 게임 오버 상태에서도 키 이벤트가 작동해야 한다. 대소문자 확인 (`"r"`과 `"R"` 둘 다 받게) |
| 재시작하면 점수가 그대로다 | `resetGame`에서 `score = 0`을 빠뜨렸다 |
| 재시작할수록 게임이 빨라진다 | 루프가 여러 개 돌고 있다. 재시작에서 `gameLoop()`를 또 부르면 안 된다 — `gameState`만 바꾼다 |
| 적을 제거했는데 하나를 건너뛴다 | 반복 중에 배열에서 빼면 번호가 밀린다. "뒤에서 앞으로 반복하는 방식으로 바꿔 줘"로 요청 |
| 코드가 너무 길어져서 AI가 엉뚱한 곳을 고친다 | "(어느 함수)만 고쳐 줘. 다른 부분은 건드리지 마"를 붙인다 |

모르는 용어는 **부록 C**, 프롬프트는 **부록 B**, 환경 문제는 **부록 D**를 본다.
