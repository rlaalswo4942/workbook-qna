> **이번 주 목표** 작업 도구를 갖추고, AI에게 말을 걸어 첫 웹페이지를 띄운다.
> **시간 배분** 설명 25분 · 실습 40분 · 과제 안내 10분 (총 90분)

## 1. 학습 목표

이 장이 끝나면 다음을 할 수 있다.

- VS Code를 설치하고, 작업 폴더를 열어 파일을 만들 수 있다.
- 내 AI 도구를 에디터에 연결하고 **에이전트 모드**를 켤 수 있다.
- Live Server로 내 HTML 파일을 브라우저에 띄울 수 있다.
- AI에게 요청해서 웹페이지를 만들고, 마음에 안 드는 곳을 말로 고칠 수 있다.
- 파일 하나가 어디에 있고 무슨 역할인지 설명할 수 있다.

## 2. 개념 설명

### 2.1 우리가 쓸 도구 세 가지

웹 게임을 만드는 데 필요한 것은 생각보다 단순하다.

| 도구 | 역할 | 비유 |
|---|---|---|
| **VS Code** | 파일을 만들고 고치는 작업실 | 작업 책상 |
| **AI (에이전트 모드)** | 코드를 써 주는 동료 | 옆자리 선배 |
| **브라우저 + Live Server** | 결과를 바로 보여 주는 화면 | 거울 |

설치할 것은 VS Code와 확장(extension) 두세 개가 전부다. Node.js, 빌드 도구, 프레임워크 — 이런 건 이 수업 끝까지 쓰지 않는다.

### 2.2 에이전트 모드가 왜 필수인가

AI와 코딩하는 방식에는 크게 두 가지가 있다.

**방식 A — 채팅으로 받아 복사하기**
```
브라우저에서 AI에게 물어본다
  → AI가 코드를 보여 준다
  → 내가 드래그해서 복사한다
  → VS Code에 붙여넣는다
  → 어디에 붙여넣어야 하는지 헷갈린다
  → 엉뚱한 곳에 붙여서 망가진다
```

**방식 B — 에이전트 모드 (이 수업에서 쓰는 방식)**
```
VS Code 안에서 AI에게 말한다
  → AI가 파일을 직접 열어서 고친다
  → 무엇을 바꿨는지 색으로 보여 준다
  → 내가 확인하고 승인한다
```

방식 A로 10주를 버티는 것은 거의 불가능하다. 파일이 여러 개가 되고 코드가 수백 줄이 되면, "어디에 붙여넣지"가 가장 큰 장애물이 된다. 그래서 이 수업은 **에이전트 모드를 최소 조건으로 한다.**

에이전트 모드는 보통 이런 특징으로 구분할 수 있다.

- 채팅 입력창 근처에 모드 선택(예: Ask / Edit / Agent 같은 이름)이 있다
- AI가 답할 때 "파일 ○○을 수정했습니다" 같은 표시가 나온다
- 수정된 부분이 초록/빨강으로 표시되고, 승인(Accept) 또는 되돌리기(Discard)를 고를 수 있다

> **도구별 설치·연결 방법은 부록 A를 보세요.** 어떤 도구를 쓰든 본문은 똑같이 따라올 수 있다.

### 2.3 파일과 폴더 — 이것만은 알고 가자

비전공자가 1~2주차에 가장 많이 겪는 문제는 **코드가 어려운 게 아니라, 파일이 어디 있는지 몰라서 생기는 문제**다. 그래서 이 부분을 먼저 확실히 한다.

**폴더(folder)는 서랍이고, 파일(file)은 서랍 안의 종이다.**

우리가 만들 것은 이런 모양이다.

```
my-game/                  ← 프로젝트 폴더 (서랍). 이걸 VS Code로 연다
├── index.html            ← 웹페이지의 뼈대
├── style.css             ← 생김새 (색, 크기, 배치)
└── script.js             ← 동작 (움직이고, 반응하고)
```

여기서 꼭 기억할 네 가지.

**(1) VS Code는 "폴더"를 연다.** 파일 하나만 열면 AI가 다른 파일을 찾지 못한다. 반드시 폴더째로 연다.

**(2) `index.html`이라는 이름은 특별하다.** 웹에서 "대문" 역할을 하는 약속된 이름이다. 10장에서 배포할 때 이 이름이 아니면 페이지가 안 열린다. 그래서 처음부터 이 이름을 쓴다.

**(3) 확장자(`.html`, `.css`, `.js`)가 파일의 종류를 결정한다.** `index.html`을 `index.txt`로 바꾸면 브라우저는 더 이상 웹페이지로 읽지 않는다.

**(4) 폴더 이름과 파일 이름에 한글과 공백을 쓰지 않는다.** 나중에 배포할 때 깨진다. `내 게임` ❌ → `my-game` ⭕

> **왜 `내 게임`이 안 되는가?** 인터넷 주소(URL)에는 한글과 공백을 그대로 넣을 수 없어서, `%EB%82%B4%20...` 같은 암호문으로 바뀐다. 당장은 되는 것처럼 보이지만 배포 단계에서 문제가 터진다. 처음부터 **영어 소문자 + 하이픈(-)** 으로 간다.

### 2.4 Live Server가 하는 일

HTML 파일은 더블클릭해도 브라우저에서 열린다. 그런데 우리는 Live Server를 쓴다. 이유가 두 개다.

1. **자동 새로고침** — 코드를 저장하면 브라우저가 알아서 다시 그린다. 새로고침 버튼을 누를 필요가 없다. 저장 → 화면 확인이 1초가 된다.
2. **나중에 필요해진다** — 3장에서 Canvas에 이미지를 불러오기 시작하면, 더블클릭으로 연 페이지에서는 브라우저 보안 때문에 이미지가 안 나오는 일이 생긴다. Live Server는 작은 웹 서버처럼 동작해서 이 문제가 없다.

지금부터 습관을 들이자. **파일을 더블클릭하지 않는다. 항상 Live Server로 연다.**

### 2.5 AI에게 말하는 법 — 첫 번째 원칙

이번 주에 익힐 프롬프트 원칙은 하나다.

> **무엇을, 어디에, 어떤 모습으로 — 세 가지를 말한다.**

비교해 보자.

❌ **나쁜 요청**
```
자기소개 페이지 만들어 줘
```
→ AI가 멋대로 만든다. 내 의도와 다를 확률이 높고, 고칠 곳이 너무 많아진다.

⭕ **좋은 요청**
```
index.html, style.css, script.js 세 파일로 자기소개 페이지를 만들어 줘.

내용:
- 맨 위에 큰 제목으로 내 이름 "박지민"
- 그 아래 한 줄 소개 "게임 만들고 싶은 경영학과 2학년"
- 그 아래 좋아하는 게임 3개를 목록으로

생김새:
- 배경은 어두운 남색, 글씨는 흰색
- 내용은 화면 가운데로 모아 주고, 폭은 너무 넓지 않게
```

차이는 **구체성**이다. 지금은 길게 쓰는 게 번거로워 보이지만, 요청이 구체적일수록 고치는 시간이 줄어든다. 결국 더 빠르다.

상황별 프롬프트 예시는 **부록 B**에 계속 쌓아 갈 것이다.

## 3. 따라 하기 실습

수업 시간에 같이 한다. 각 단계가 끝나면 옆 사람과 서로 확인한다.

### Step 1. VS Code 설치 (5분)

1. [code.visualstudio.com](https://code.visualstudio.com) 접속 → **Download for Windows**
2. 설치 프로그램 실행 → 계속 **다음**
3. 설치 중 아래 항목이 보이면 **반드시 체크**한다
   - [ ] "Code(으)로 열기" 작업을 Windows 탐색기 파일 상황에 맞는 메뉴에 추가
   - [ ] "Code(으)로 열기" 작업을 Windows 탐색기 디렉터리 상황에 맞는 메뉴에 추가
   - [ ] PATH에 추가

> 세 번째 체크박스를 켜 두면, 나중에 폴더에서 마우스 오른쪽 버튼 → "Code로 열기"로 바로 열 수 있다. 매주 쓰게 된다.

**한글 메뉴로 바꾸기(선택):** VS Code를 처음 열면 오른쪽 아래에 한국어 언어 팩을 설치할지 묻는 알림이 뜬다. 설치하면 메뉴가 한글이 된다. 영어가 편하면 그냥 둔다.

### Step 2. 작업 폴더 만들기 (5분)

1. `C:\Users\(내 이름)\Documents` 안에 폴더를 만든다 → 이름은 **`vibe-coding`**
2. 그 안에 다시 폴더를 만든다 → 이름은 **`week01`**
3. `week01` 폴더에서 마우스 오른쪽 → **Code로 열기**

> **왜 이렇게 나누는가?** `vibe-coding`은 이 수업 전체의 집, `week01`은 이번 주 방이다. 다음 주에는 `week02`를 만든다. 2장에서 GitHub에 올릴 때 이 구조가 그대로 쓰인다.
>
> 바탕화면이나 다운로드 폴더는 쓰지 않는다. 금방 다른 파일에 섞여 사라진다.

VS Code 왼쪽에 `WEEK01`이라고 나오면 성공이다. 아직 파일은 없다.

### Step 3. AI 연결하고 에이전트 모드 켜기 (15분)

여기는 쓰는 도구마다 다르다. **부록 A**에서 자기 도구 항목을 찾아 따라 한다. 끝났으면 아래 두 가지를 확인한다.

- [ ] VS Code(또는 Cursor) 안에 AI 채팅창이 열린다
- [ ] 그 채팅창에서 **Agent(에이전트)** 모드를 고를 수 있다

**연결 확인 테스트** — 채팅창에 이렇게 보낸다.

```
지금 열려 있는 폴더에 test.txt 파일을 만들고, 안에 "연결 성공"이라고 써 줘.
```

왼쪽 파일 목록에 `test.txt`가 생기고 내용이 들어 있으면 에이전트 모드가 작동하는 것이다. (AI가 "이 파일을 만들까요?" 하고 승인을 요구하면 승인한다.) 확인했으면 `test.txt`는 지운다.

파일이 생기지 않고 채팅창에 코드만 보여 준다면, 아직 에이전트 모드가 아니다. 모드 선택을 다시 확인한다. 안 되면 **부록 A**의 문제 해결 부분으로.

### Step 4. Live Server 설치 (3분)

1. VS Code 왼쪽 세로 막대에서 **확장(Extensions)** 아이콘 클릭 (블록 네 개 모양) — 또는 `Ctrl+Shift+X`
2. 검색창에 `Live Server` 입력
3. 만든 사람이 **Ritwick Dey**인 것을 찾아 **Install**

설치되면 VS Code 오른쪽 아래 상태 바에 **"Go Live"** 라는 글자가 생긴다.

### Step 5. 첫 페이지를 AI에게 만들게 하기 (12분)

채팅창을 **Agent 모드**로 두고, 아래 요청을 **자기 내용으로 바꿔서** 보낸다.

```
지금 열려 있는 폴더에 index.html, style.css, script.js 세 파일로
자기소개 페이지를 만들어 줘.

내용:
- 맨 위에 큰 제목으로 내 이름 "(여기에 내 이름)"
- 그 아래 한 줄 소개 "(여기에 한 줄 소개)"
- 그 아래 "좋아하는 게임" 제목과 게임 3개 목록

생김새:
- 배경은 어두운 색, 글씨는 밝은 색
- 내용은 화면 가운데로 모으고, 좌우 여백을 넉넉하게
- 글꼴 크기는 읽기 편하게

조건:
- 외부 라이브러리는 쓰지 말고 순수 HTML/CSS/JS로만
- style.css와 script.js를 index.html에서 제대로 연결해 줘
```

AI가 만든 파일 세 개가 왼쪽에 나타나면 된다.

### Step 6. 브라우저에 띄우기 (3분)

1. 왼쪽에서 `index.html`을 클릭해서 연다
2. 오른쪽 아래 **Go Live** 클릭 — 또는 `index.html`에서 마우스 오른쪽 → **Open with Live Server**
3. 브라우저가 열리고 주소가 `http://127.0.0.1:5500/...` 으로 시작하면 성공

> 주소가 `file:///C:/...`로 시작하면 Live Server가 아니라 그냥 파일을 연 것이다. 다시 Go Live를 누른다.

### Step 7. 말로 고쳐 보기 (12분)

이게 이번 주의 핵심 경험이다. 브라우저를 한쪽에 띄워 둔 채로, 채팅창에 아래를 하나씩 보낸다. **보낼 때마다 브라우저를 본다.**

```
제목 글씨를 더 크게 하고, 색을 노란색으로 바꿔 줘.
```

```
좋아하는 게임 목록의 각 항목에 마우스를 올리면 글씨가 살짝 커지게 해 줘.
```

```
페이지 맨 아래에 오늘 날짜가 자동으로 표시되게 해 줘. script.js에서 처리해 줘.
```

세 번째 요청이 끝났으면 **잠깐 멈추고 이걸 해 본다.**

```
script.js에 방금 추가한 코드가 하는 일을 한 줄씩 설명해 줘.
초등학생에게 설명하듯이 쉽게.
```

이 질문이 7장까지 이어지는 가장 중요한 습관이다. **AI가 쓴 코드를 받고 나서 한 번 더 물어보는 것.** 오늘 과제 회고에 이 설명을 쓸 것이다.

### Step 8. 세 파일이 무슨 역할인지 눈으로 확인 (7분)

확인용 실험을 해 본다. 망가뜨려 보고 되돌리는 것이 가장 빠른 공부다.

1. `index.html`을 열고, `<link ... style.css ...>` 로 보이는 줄을 찾는다
2. 그 줄 맨 앞에 `<!--` 를 붙이고 줄 끝에 `-->` 를 붙인다 → 저장
3. 브라우저를 본다 → **색과 배치가 전부 사라진다.** 글자는 남아 있다
4. 방금 붙인 `<!--` 와 `-->` 를 지운다 → 저장 → 돌아온다

| 파일 | 없으면 어떻게 되는가 | 그래서 하는 일 |
|---|---|---|
| `index.html` | 아무것도 안 나온다 | **내용** — 무엇이 있는가 |
| `style.css` | 글자만 남고 꾸밈이 사라진다 | **생김새** — 어떻게 보이는가 |
| `script.js` | 보이긴 하지만 반응이 없다 | **동작** — 무엇을 하는가 |

이 세 줄이 앞으로 10주 동안 쓸 전부다. 3장에서 Canvas를 배우면 게임 화면이 `index.html` 안에, 게임 규칙이 `script.js` 안에 들어간다.

## 4. 내 게임에 적용하기 (과제)

### 과제 1. 자기소개 페이지 완성 (필수)

실습에서 만든 페이지를 자기 것으로 다듬는다. 아래 네 가지는 반드시 들어간다.

- [ ] 내 이름과 한 줄 소개
- [ ] **수업 시간에 하지 않은 변경 두 가지 이상.** 스스로 생각해서 AI에게 요청한다
  (예: 버튼을 누르면 색이 바뀐다 / 내 사진을 넣는다 / 글꼴을 바꾼다 / 좋아하는 게임에 링크를 건다)
- [ ] 페이지 맨 아래에 **"만든 게임 아이디어" 칸** (과제 2의 내용을 여기에 쓴다)
- [ ] 파일은 `index.html`, `style.css`, `script.js` 세 개 구조를 유지

### 과제 2. 게임 아이디어 3개 (필수)

10주 동안 만들 게임을 아직 정하지 않아도 된다. 지금은 **후보를 세 개 내는 것**이 과제다. 3장에서 이 중 하나를 골라 기획서를 쓴다.

각 아이디어는 아래 네 줄로 쓴다.

```
제목:
한 줄 설명:
플레이어가 하는 일:
게임이 끝나는 조건:
```

**예시**

```
제목: 지각 탈출
한 줄 설명: 1교시에 늦은 학생이 캠퍼스를 달려 강의실까지 가는 게임
플레이어가 하는 일: 좌우 방향키로 피하면서 계속 앞으로 달린다
게임이 끝나는 조건: 사람 세 명과 부딪히면 지각 확정, 강의실에 도착하면 승리
```

**아이디어를 낼 때 지킬 선** — 이 세 가지를 지키면 10주 안에 완성할 수 있다.

| 지킬 것 | 이유 |
|---|---|
| 2D 화면 하나로 끝나는 게임 | 3D, 여러 스테이지는 10주에 안 끝난다 |
| 조작은 방향키나 마우스 클릭 수준 | 복잡한 조작은 5장에서 막힌다 |
| 혼자 하는 게임 | 온라인 대전은 서버가 필요하다 (심화) |

막히면 AI에게 물어봐도 된다. 단, 그때도 **조건을 주고 물어본다.**

```
웹 브라우저에서 돌아가는 2D 게임 아이디어를 제안해 줘.
조건:
- 화면 하나로 끝나고, 방향키 조작만 쓴다
- 프로그래밍을 처음 배우는 사람이 10주 안에 만들 수 있는 수준
- 대학생활을 소재로
5개를 짧게 제안해 줘.
```

받은 제안을 그대로 베끼지는 않는다. 마음에 드는 걸 골라 **내 것으로 바꿔서** 쓴다.

### 과제 3. 회고 파일 (필수)

프로젝트 폴더 안에 **`회고.md`** 파일을 만들어 아래 양식을 채운다. 양식 원본은 **부록 E**에 있다.

```markdown
# 1주차 회고

## 1. 이번 주에 쓴 핵심 프롬프트
(AI에게 보낸 요청 중 가장 중요했던 것 2~3개를 그대로 복사해서 붙인다)

## 2. 막힌 점과 해결 방법
(무엇이 안 됐는지 / 왜 그랬는지 / 어떻게 뚫었는지. 아직 못 뚫었으면 그렇게 쓴다)

## 3. 코드 한 부분을 내 말로 설명
(script.js에서 한 조각을 골라, 무슨 일을 하는지 내 문장으로. AI 설명을 그대로 붙이지 않는다)
```

> **회고 파일은 직접 쓴다.** AI에게 쓰게 하지 않는다. 이게 평가의 핵심이다.

## 5. 제출 체크리스트

이번 주는 **GitHub를 아직 배우지 않았으므로** 폴더를 압축해서 제출한다. 2장부터는 GitHub 저장소 링크로 바뀐다.

제출 파일: **`week01_학번_이름.zip`**

압축 전에 확인한다.

- [ ] `week01` 폴더 안에 `index.html`, `style.css`, `script.js`가 있다
- [ ] Live Server로 열었을 때 에러 없이 보인다
- [ ] 내 이름과 한 줄 소개가 들어 있다
- [ ] 수업에서 하지 않은 변경이 두 가지 이상 있다
- [ ] 게임 아이디어 3개가 페이지 아래 또는 회고 파일에 있다
- [ ] `회고.md`의 세 항목이 모두 채워져 있다
- [ ] 폴더·파일 이름에 한글과 공백이 없다 (`회고.md`는 예외로 허용)
- [ ] `test.txt` 같은 연습 파일은 지웠다

## 이번 주 자주 막히는 지점

| 증상 | 원인과 해결 |
|---|---|
| AI가 파일을 안 만들고 코드만 보여 준다 | 에이전트 모드가 아니다. 모드 선택을 Agent로 (부록 A) |
| 왼쪽에 폴더 이름이 안 보인다 | 파일만 열었다. 폴더째로 다시 연다 |
| Go Live 글자가 없다 | Live Server 설치 안 됨 또는 VS Code 재시작 필요 |
| 브라우저에 아무것도 안 나온다 | 주소가 `file:///`로 시작하는지 확인 → Live Server로 다시 |
| 수정했는데 화면이 그대로다 | 저장 안 함 (`Ctrl+S`). Live Server는 저장된 것만 반영한다 |
| 글씨가 네모(□)로 깨진다 | `index.html`에 `<meta charset="UTF-8">`이 있는지 AI에게 확인 요청 |
| 화면이 흑백이고 꾸밈이 없다 | `style.css` 연결이 끊겼다. Step 8의 주석을 안 지웠는지 확인 |

더 많은 Windows 관련 문제는 **부록 D**에 정리해 둔다.
