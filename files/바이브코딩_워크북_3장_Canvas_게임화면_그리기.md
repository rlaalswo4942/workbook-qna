# 3장. 게임 화면 그리기: Canvas

> **이번 주 목표** 게임을 그릴 **도화지**를 만들고, 그 위에 내 게임의 첫 화면을 그린다. 그리고 10주 동안 만들 게임을 **하나로 정한다.**

---

## 1. 학습 목표

이 장이 끝나면 다음을 할 수 있다.

- HTML / CSS / JavaScript가 각각 무슨 일을 하는지 자기 말로 구분할 수 있다.
- Canvas가 무엇이고 왜 게임에 쓰는지 설명할 수 있다.
- Canvas 좌표계를 읽고, 원하는 위치에 도형을 놓을 수 있다.
- AI에게 "무엇을, 어디에, 어떤 색으로" 그릴지 지시해서 화면을 만들 수 있다.
- 게임 기획서를 한 페이지로 쓸 수 있다.

## 2. 개념 설명

### 2.1 세 파일의 역할 — 이제 정확히 구분한다

1장에서 CSS 연결을 끊어 보며 감을 잡았다. 이번에는 말로 정리한다.

| 파일 | 역할 | 사람에 비유하면 | 게임에서는 |
|---|---|---|---|
| `index.html` | **구조** — 무엇이 있는가 | 뼈대 | 도화지를 놓을 자리 |
| `style.css` | **모양** — 어떻게 보이는가 | 옷 | 화면 배치, 여백, 테두리 |
| `script.js` | **동작** — 무엇을 하는가 | 뇌 | 게임의 전부 |

**중요한 변화가 이번 주에 생긴다.** 지금까지는 `index.html`에 글자와 목록을 썼다. 하지만 게임을 만들기 시작하면 이렇게 바뀐다.

```
index.html  →  거의 안 건드린다 (도화지 한 장만 놓는다)
style.css   →  거의 안 건드린다 (도화지를 화면 가운데 놓는 정도)
script.js   →  여기에 게임의 99%가 들어간다 ⭐
```

4장부터 10장까지 우리가 고칠 파일은 사실상 `script.js` 하나다. 게임의 캐릭터, 움직임, 규칙, 점수가 모두 여기에 있다.

### 2.2 Canvas — 도화지 한 장

**Canvas(캔버스)** 는 "JavaScript로 그림을 그릴 수 있는 사각형 영역"이다. 이름 그대로 **그림을 그리는 천(캔버스)** 이다.

HTML에 이 한 줄을 넣으면 도화지가 생긴다.

```html
<canvas id="game" width="800" height="600"></canvas>
```

| 부분 | 뜻 |
|---|---|
| `id="game"` | 이 도화지의 **이름**. JavaScript가 이 이름으로 도화지를 찾는다 |
| `width="800"` | 도화지의 **가로 크기** 800칸 |
| `height="600"` | 도화지의 **세로 크기** 600칸 |

그런데 왜 글자나 그림 태그를 쓰지 않고 Canvas를 쓰는가?

| | HTML 태그로 만들기 | Canvas로 만들기 |
|---|---|---|
| 물체 10개 | 태그 10개를 관리 | 그리는 명령 10번 |
| 물체 500개 | 느려서 못 쓴다 | 문제없다 |
| 1초에 60번 다시 그리기 | 버벅인다 | 이걸 위해 만들어졌다 |
| 자유로운 위치 | CSS로 고생해야 한다 | 좌표를 그냥 숫자로 준다 |

게임은 **"1초에 60번 화면 전체를 다시 그리는 일"** 이다. Canvas는 정확히 그 용도로 만들어진 도구다.

### 2.3 좌표계 — 이번 주에서 가장 중요한 것

Canvas에서 위치는 **(x, y) 숫자 두 개**로 정한다. 그런데 **학교에서 배운 좌표와 y축 방향이 반대다.**

```
수학 시간의 좌표                  Canvas의 좌표
                                 (0,0) ──────────→ x (오른쪽)
        y ↑                        │
          │                        │
    ──────┼──────→ x               │
          │                        ↓
                                   y (아래쪽)
```

**원점 (0, 0)은 왼쪽 위 구석이고, y가 커지면 아래로 내려간다.**

| 좌표 | 위치 (800×600 도화지에서) |
|---|---|
| `(0, 0)` | 왼쪽 위 구석 |
| `(800, 0)` | 오른쪽 위 구석 |
| `(0, 600)` | 왼쪽 아래 구석 |
| `(400, 300)` | 정확히 가운데 |
| `(400, 0)` | 위쪽 가운데 |

이걸 몸으로 익혀 두면 앞으로 7주가 편해진다. 반대로 모르면 이런 일이 생긴다.

> "캐릭터를 위로 점프시키려고 `y`를 늘렸는데 바닥으로 가라앉았어요."
> → **위로 가려면 `y`를 줄여야 한다.** Canvas에서 y는 아래쪽이 양수다.

### 2.4 그리는 명령 — 읽을 수만 있으면 된다

외우지 않는다. **AI가 써 준 코드를 보고 "아, 이건 사각형을 그리는 줄이구나"를 알아보는 수준**이 목표다.

먼저 도화지를 찾아오는 두 줄로 시작한다. 이 두 줄은 모든 Canvas 게임의 첫머리에 똑같이 나온다.

```javascript
const canvas = document.getElementById("game");  // 이름이 "game"인 도화지를 찾는다
const ctx = canvas.getContext("2d");             // 그 도화지에 그릴 "붓"을 가져온다
```

`ctx`는 **붓**이다. 앞으로 모든 그리기는 `ctx.` 으로 시작한다.

**사각형 그리기**

```javascript
ctx.fillStyle = "red";            // 붓에 빨간색을 묻힌다
ctx.fillRect(100, 50, 200, 80);   // (100,50)에서 가로 200, 세로 80 사각형
```

`fillRect(x, y, 가로, 세로)` — **숫자 네 개의 순서만 알면 된다.** 앞의 둘은 왼쪽 위 꼭짓점의 위치, 뒤의 둘은 크기다.

**원 그리기**

```javascript
ctx.fillStyle = "blue";
ctx.beginPath();                        // 선 그리기 시작
ctx.arc(400, 300, 40, 0, Math.PI * 2);  // (400,300)을 중심으로 반지름 40인 원
ctx.fill();                             // 색칠한다
```

원은 네 줄이 필요해서 번거롭다. **`Math.PI * 2`는 "한 바퀴 전체"라는 뜻**이고, 원을 그릴 때는 늘 이렇게 쓴다. 그 이상은 지금 몰라도 된다.

> **중요한 차이: 사각형의 `x, y`는 왼쪽 위 꼭짓점이고, 원의 `x, y`는 중심이다.** 같은 `(400, 300)`을 줘도 놓이는 자리가 다르다. 6장에서 충돌 판정을 할 때 이 차이를 모르면 판정 영역이 반지름만큼 어긋난다.

**글자 쓰기**

```javascript
ctx.fillStyle = "white";
ctx.font = "30px sans-serif";       // 글씨 크기 30
ctx.fillText("점수: 0", 20, 40);    // (20,40) 위치에 글자
```

6장에서 점수를 표시할 때 이 명령을 쓴다.

**이미지 그리기**

```javascript
const img = new Image();
img.src = "player.png";             // 파일을 불러온다
img.onload = function () {          // 다 불러온 뒤에
  ctx.drawImage(img, 100, 100, 64, 64);  // (100,100)에 64×64 크기로 그린다
};
```

`img.onload`가 필요한 이유는 **그림 파일을 불러오는 데 시간이 걸리기 때문**이다. 다 불러오기 전에 그리라고 하면 아무것도 안 나온다. 이미지가 안 보이는 가장 흔한 원인이 이것이다.

> **색은 어떻게 쓰나?** `"red"`, `"blue"` 같은 영어 이름을 쓸 수 있고, `"#1e3a5f"` 같은 코드도 쓸 수 있다. 원하는 색의 코드는 AI에게 물어보면 된다. "밤하늘 같은 어두운 남색의 색상 코드를 알려 줘."

### 2.5 "지우고 다시 그린다" — 4장으로 가는 다리

Canvas에는 중요한 성질이 있다. **한 번 그린 것은 덮어쓰기 전까지 그대로 남는다.** 그래서 물체를 움직이려면 이렇게 해야 한다.

```
❌ 캐릭터를 옆으로 옮긴다          → 그런 명령은 없다
⭕ 화면을 다 지운다 → 옆자리에 다시 그린다 → 이걸 1초에 60번 반복
```

지우는 명령은 한 줄이다.

```javascript
ctx.clearRect(0, 0, canvas.width, canvas.height);  // 도화지 전체를 지운다
```

**지우기 → 그리기**를 아주 빠르게 반복하면 사람 눈에는 움직이는 것으로 보인다. 애니메이션이 원래 그런 원리다. 이게 **게임 루프**이고, 다음 주 4장의 주제다.

이번 주는 **움직이지 않는 첫 화면 한 장**만 그린다.

### 2.6 게임 기획서 쓰는 법

이번 주에 코드만큼 중요한 과제다. 그리고 바이브 코딩에서는 **기획서가 특별히 중요하다.**

**왜 기획서를 쓰는가**

AI는 내가 말한 만큼만 만들어 준다. "재미있는 게임 만들어 줘"로는 아무것도 안 나온다. 기획서는 **AI에게 줄 설계도**이자, 10주 동안 길을 잃지 않게 해 주는 지도다.

실제로 기획서가 없으면 이렇게 된다.

> 5주차: "조작을 추가했는데... 이 게임이 뭘 하는 게임이었지?"
> 7주차: "매주 기능을 넣었는데 다 따로 놀아요"
> 9주차: "플레이테스트를 했는데 친구가 규칙을 이해하지 못했어요"

**기획서는 한 페이지면 충분하다**

길게 쓰는 게 목적이 아니다. **아래 7개 질문에 답할 수 있는가**가 목적이다.

```markdown
# 게임 기획서

## 1. 제목
(한 줄)

## 2. 한 줄 설명
"____가 ____하면서 ____하는 게임"
(이 틀에 넣어 본다. 안 들어가면 아직 덜 정해졌다는 뜻이다)

## 3. 플레이어가 하는 일
- 조작: (방향키 / 마우스 클릭 / 스페이스바 중에서)
- 목표: (무엇을 하려고 하는가)

## 4. 화면에 있는 것
| 이름 | 생김새 | 역할 |
|---|---|---|
| 예: 플레이어 | 파란 사각형 32×32 | 방향키로 움직인다 |
| 예: 장애물 | 빨간 원 20 | 위에서 떨어진다 |
| 예: 점수 | 왼쪽 위 흰 글씨 | 버틴 시간 |

## 5. 규칙
- 점수가 오르는 조건:
- 게임이 끝나는 조건:
- (있으면) 난이도가 올라가는 방식:

## 6. 화면 스케치
(손으로 그려서 사진을 찍어도 되고, 글로 위치를 설명해도 된다)

## 7. 만들 순서
- [ ] 4주차: 무엇을 움직이게 할까
- [ ] 5주차: 무엇을 조작하게 할까
- [ ] 6주차: 어떻게 점수를 주고 어떻게 끝낼까
```

**4번 표가 이번 주 실습의 재료다.** 여기에 쓴 것을 그대로 Canvas에 그린다.

**기획서를 AI와 함께 다듬기**

처음부터 완벽하게 쓰지 못한다. 초안을 쓴 뒤 AI에게 검토를 맡기는 게 좋다. 단, **내용을 대신 쓰게 하지 않는다.**

```
아래는 내가 쓴 웹 게임 기획서야.

(기획서 붙여넣기)

프로그래밍을 처음 배우는 사람이 순수 HTML/CSS/JS로 7주 안에 만든다고 할 때,
1) 너무 어려워서 빼야 할 요소
2) 설명이 애매해서 더 정해야 할 부분
3) 지금 빠져 있는데 반드시 정해야 하는 것
이 세 가지를 지적해 줘. 기획서를 다시 써 주지는 말고 지적만 해 줘.
```

마지막 문장이 중요하다. **"다시 써 주지 마"** 라고 해야 내 기획서로 남는다.

**게임을 하나로 정하는 주다**

1장에서 아이디어 3개를 냈다. 이번 주에 **하나를 고른다.** 고르는 기준은 "가장 멋진 것"이 아니라 **"7주 동안 질리지 않을 것"** 이다. 매주 1.5시간씩 같은 게임을 붙잡게 되므로, 내가 재미있어하는 쪽을 고른다.

범위가 걱정되면 **작은 쪽**을 고른다. 8~9장에서 살을 붙일 시간이 있지만, 너무 큰 것을 고르면 6장에서 플레이 가능한 상태를 못 만든다.

## 3. 따라 하기 실습

작업 폴더는 2장에서 만든 **`my-game`** 이다. 새 폴더를 만들지 않는다.

> **시작 전에 커밋한다.** 소스 제어 → 메시지 `3장 시작 전 상태` → Commit. 망가뜨렸을 때 돌아올 지점을 만들어 둔다. 앞으로 매주 수업 시작 전에 이걸 한다.

### Step 1. 도화지 만들기 (8분)

AI 채팅창(에이전트 모드)에 아래를 보낸다.

```
지금 폴더의 index.html을 게임용으로 바꿔 줘.

- 기존 자기소개 내용은 지우고, 800×600 크기의 canvas 하나만 남겨 줘.
- canvas의 id는 "game"으로 해 줘.
- style.css에서 배경은 어두운 회색으로, canvas는 화면 가운데에 놓고
  테두리를 얇은 흰 선으로 그려 줘.
- script.js는 canvas와 ctx를 가져오는 두 줄만 남기고 비워 줘.

외부 라이브러리는 쓰지 말고 순수 HTML/CSS/JS로만.
```

Live Server로 확인한다. **화면 가운데에 빈 사각형(테두리만 보이는 도화지)이 나타나면 성공이다.**

> 자기소개 페이지가 사라지는 게 아쉬우면, 지우기 전에 커밋해 두면 언제든 꺼내 볼 수 있다. 2장에서 배운 게 이런 때 쓰인다.

### Step 2. 좌표 감각 익히기 (12분)

이번 주의 핵심 실습이다. **좌표를 몸으로 익힌다.**

AI에게 요청한다.

```
script.js에 아래를 그려 줘. 좌표를 확인하는 연습용이야.

1. (0, 0)에 빨간 사각형, 가로 50 세로 50
2. (750, 0)에 노란 사각형, 가로 50 세로 50
3. (0, 550)에 초록 사각형, 가로 50 세로 50
4. (400, 300)에 흰 사각형, 가로 20 세로 20
5. 각 사각형 옆에 좌표를 흰 글씨로 작게 써 줘

코드에 각 줄이 무슨 뜻인지 한국어 주석을 달아 줘.
```

**예상하고 나서 확인한다.** 브라우저를 보기 전에 머릿속으로 그려 본다.

- 빨간 것은 어디에? → 왼쪽 **위**
- 노란 것은? → 오른쪽 **위**
- 초록 것은? → 왼쪽 **아래**
- 흰 것은? → 가운데

예상과 맞는지 확인한다. **특히 "0, 0이 왼쪽 위"와 "y가 커지면 아래"를 눈으로 확인하는 것**이 목적이다.

이어서 직접 숫자를 고쳐 본다. **이번에는 AI를 쓰지 않고 내가 고친다.**

1. `script.js`를 열고 `fillRect(` 로 시작하는 줄을 찾는다
2. 흰 사각형의 두 번째 숫자(y)를 `300` → `100`으로 바꾼다 → 저장 → **위로 올라간다**
3. 다시 `300` → `500`으로 바꾼다 → 저장 → **아래로 내려간다**
4. 첫 번째 숫자(x)를 바꿔 본다 → **좌우로 움직인다**

> 숫자 네 개의 순서는 `fillRect(x, y, 가로, 세로)`다. 세 번째와 네 번째를 바꾸면 크기가 변한다. 이것도 해 본다.

### Step 3. 내 게임의 물체 그리기 (12분)

기획서 4번 표에 쓴 것을 그린다. **기획서를 안 썼으면 지금 간단히 정한다.**

AI에게 요청할 때 **내 게임의 내용으로 바꿔서** 보낸다.

```
script.js에 내 게임의 첫 화면을 그려 줘. 아직 움직이지는 않아도 돼.

게임: 지각 탈출 — 캠퍼스를 달려 강의실까지 가는 게임

그릴 것:
- 배경: 아래쪽 1/4은 회색 길, 위쪽 3/4은 하늘색
- 플레이어: 화면 아래 가운데에 파란 사각형 32×32
- 장애물: 위쪽에 빨간 원 3개, 반지름 20, 서로 떨어진 위치에
- 왼쪽 위에 흰 글씨로 "지각까지 10초"

조건:
- 각 부분이 무엇을 그리는지 한국어 주석을 달아 줘
- 좌표와 크기는 나중에 내가 바꾸기 쉽게, 코드 위쪽에 모아 줘
```

마지막 조건이 중요하다. **숫자를 코드 위쪽에 모아 두면** 나중에 위치를 조정할 때 찾기 쉽다. 4장에서 이 숫자들이 "변수"라는 이름으로 다시 등장한다.

### Step 4. 코드를 읽어 본다 (8분)

이번 주도 멈추고 읽는 시간을 갖는다. AI에게 이렇게 묻는다.

```
script.js 전체를 위에서 아래로 한 줄씩, 무슨 일을 하는지 설명해 줘.
프로그래밍을 처음 배우는 사람에게 설명하듯이.
특히 ctx가 무엇인지, 왜 모든 줄이 ctx로 시작하는지 알려 줘.
```

설명을 읽으면서 아래 세 가지를 직접 찾아 본다.

- [ ] 도화지를 찾아오는 줄 (`getElementById`)
- [ ] 붓을 가져오는 줄 (`getContext`)
- [ ] 내 플레이어를 그리는 줄

이 세 줄을 짚을 수 있으면 이번 주 목표는 달성이다.

### Step 5. 직접 손으로 고치기 (7분)

AI를 쓰지 않고 내가 고친다. 세 가지를 바꿔 본다.

1. 플레이어의 **색**을 바꾼다 (`"blue"` → 다른 색)
2. 플레이어의 **크기**를 바꾼다 (32 → 60)
3. 장애물 하나의 **위치**를 바꾼다

> 손으로 숫자를 고치는 경험이 필요한 이유 — 7장에서 디버깅을 할 때, "어느 숫자를 바꿔야 하는지" 아는 사람만 빠르게 고칠 수 있다. AI에게 전부 맡기면 이 감각이 생기지 않는다.

### Step 6. 커밋하고 배포 확인 (5분)

2장에서 익힌 사이클을 돌린다.

1. 소스 제어 → 메시지 `게임 첫 화면 그리기` → **Commit**
2. **Sync Changes**
3. 1~2분 뒤 배포 주소를 열어 본다 → **내 게임 화면이 인터넷에 떠 있다**

## 4. 내 게임에 적용하기 (과제)

### 과제 1. 게임 기획서 (필수)

`my-game` 폴더에 **`기획서.md`** 파일을 만들어 2.6의 7개 항목을 모두 채운다.

- [ ] 1장의 아이디어 3개 중 **하나를 골랐다**
- [ ] 7개 항목이 다 채워져 있다 (빈칸 없음)
- [ ] 4번 표에 **화면에 나올 것이 3개 이상** 적혀 있다
- [ ] 6번 화면 스케치가 있다 (손그림 사진, 또는 글로 쓴 배치 설명)
- [ ] AI에게 검토를 받고, **지적받은 것 중 하나 이상을 반영**했다

> 스케치를 사진으로 넣는 방법: 사진을 `my-game` 폴더에 `sketch.jpg` 같은 이름으로 넣고, `기획서.md`에 `![스케치](sketch.jpg)` 라고 쓴다. 파일 이름에 한글·공백은 쓰지 않는다.

### 과제 2. 내 게임 첫 화면 (필수)

기획서 4번 표에 쓴 것을 Canvas에 그린다.

- [ ] Canvas가 보이고, 배경이 내 게임 분위기에 맞다
- [ ] 기획서 4번 표의 물체가 **3개 이상** 그려져 있다
- [ ] 글자가 하나 이상 있다 (점수, 남은 시간, 안내 문구 등)
- [ ] **수업에서 하지 않은 시도 한 가지 이상** — 예: 이미지 파일 넣기 / 그라데이션 / 도형 겹치기 / 반투명
- [ ] 배포 주소에서도 정상으로 보인다

> **이미지를 넣고 싶은 사람에게** — 무료 게임 에셋은 [kenney.nl](https://kenney.nl), [opengameart.org](https://opengameart.org) 등에서 구할 수 있다. 파일 이름은 영어로 바꿔서 넣고, `img.onload` 안에서 그려야 보인다(2.4 참고). **저작권과 출처 표기는 8장에서 제대로 다룬다.** 지금 쓴 에셋의 출처 주소는 `README.md`에 메모해 둔다.

### 과제 3. 회고 파일 (필수)

양식은 **부록 E**와 같다. 3주차는 아래를 포함한다.

- **1번:** 첫 화면을 그리게 한 요청. 기획서 검토 요청도 좋다
- **2번:** 막힌 점. "좌표를 잘못 줘서 화면 밖으로 나갔다", "이미지가 안 보였다" 같은 것이 좋은 소재다
- **3번:** 코드 설명. **이번 주는 Canvas 그리기 부분에서 고른다.** `ctx`가 무엇인지, 숫자 네 개가 각각 무슨 뜻인지를 자기 말로 쓴다

## 이번 주 자주 막히는 지점

| 증상 | 원인과 해결 |
|---|---|
| 화면이 완전히 비어 있다 | `F12` → Console에 빨간 에러가 있는지 본다. 보통 `id`가 안 맞다 (`"game"` 확인) |
| 도형이 안 보인다 | ① 색이 배경과 같다 ② 좌표가 도화지 밖이다 (x>800 또는 y>600) ③ 크기가 0이다 |
| 위로 올리려는데 아래로 간다 | y는 **아래**가 양수다. 위로 가려면 y를 **줄인다** |
| 도형이 테두리 밖으로 삐져나간다 | `style.css`의 canvas 크기와 `index.html`의 `width/height`가 다르다. CSS로 크기를 바꾸면 그림이 늘어난다 |
| 이미지가 안 보인다 | `img.onload` 안에서 그렸는지 / 파일 이름 대소문자 / 파일이 같은 폴더에 있는지 |
| 로컬에선 이미지가 보이는데 배포하면 안 보인다 | 파일 이름 대소문자 불일치. 부록 D.5 참고 |
| 글자가 안 보인다 | `ctx.fillStyle`을 글자 그리기 **전에** 설정했는지 / 색이 배경과 같지 않은지 |
| 코드를 고쳤는데 화면이 그대로다 | `Ctrl+S` 저장 → Live Server 확인 |
| AI가 Canvas 대신 HTML 태그로 만들어 줬다 | 요청에 "canvas에 ctx로 그려 줘"를 명시한다 |
| 그림이 흐릿하다 | CSS로 canvas를 확대했다. `index.html`의 `width/height` 숫자를 직접 키운다 |

모르는 용어가 나오면 **부록 C 용어집**을 본다.
