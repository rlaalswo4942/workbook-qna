## C.1 도구와 환경

**VS Code**
코드를 쓰고 고치는 프로그램. "작업 책상". 무료다.

**Cursor**
VS Code를 기반으로 만든, AI 기능이 처음부터 들어 있는 에디터. 생김새와 조작법이 VS Code와 거의 같다.

**확장 (Extension)**
VS Code에 기능을 추가하는 부품. Live Server, Copilot 등이 모두 확장이다. `Ctrl+Shift+X`에서 설치한다.

**에이전트 모드 (Agent mode)**
AI가 **채팅창에 코드를 보여 주는 대신, 내 파일을 직접 열어서 고치는** 작동 방식. 이 수업의 최소 조건이다. 자세한 설정은 부록 A.

**프롬프트 (Prompt)**
AI에게 보내는 요청 문장. "무엇을, 어디에, 어떤 모습으로"를 담는다.

**Live Server**
내 HTML 파일을 작은 웹 서버처럼 띄워 주는 확장. 저장하면 브라우저가 자동으로 새로고침된다. 주소가 `127.0.0.1:5500`으로 시작한다.

**localhost / 127.0.0.1**
"내 컴퓨터 자신"을 가리키는 주소. Live Server가 쓰는 주소이며, 다른 사람은 이 주소로 내 페이지를 볼 수 없다.

**개발자 도구 (DevTools)**
브라우저에서 `F12`로 여는 창. **Console** 탭에서 에러를 볼 수 있다. 7장에서 본격적으로 쓴다.

**콘솔 (Console)**
개발자 도구의 한 탭. 에러 메시지와 `console.log()`로 출력한 내용이 여기 보인다. 빨간 글씨가 에러다.

## C.2 파일과 폴더

**폴더 (Folder / Directory)**
파일을 담는 서랍. VS Code는 **폴더를 열어야** AI가 파일들을 찾을 수 있다.

**확장자 (Extension)**
파일 이름 끝의 `.html`, `.css`, `.js`. 파일의 종류를 결정한다. (VS Code 확장과 영어 단어가 같지만 다른 것이다.)

**`index.html`**
웹에서 **대문** 역할을 하는 약속된 파일 이름. 이 이름이 아니면 배포한 주소에서 페이지가 열리지 않는다.

**`README.md`**
저장소 설명 파일. GitHub에서 저장소를 열면 자동으로 보인다.

**`.md` (마크다운, Markdown)**
글을 간단한 기호로 꾸미는 형식. `#`은 제목, `-`은 목록, `**굵게**` 같은 식이다. 회고와 기획서를 이 형식으로 쓴다.

**상대 경로 / 절대 경로**
`style.css`처럼 **내 위치를 기준으로** 가리키는 것이 상대 경로, `/style.css`처럼 **맨 위를 기준으로** 가리키는 것이 절대 경로. 이 수업에서는 **상대 경로를 쓴다.** 절대 경로는 배포하면 깨진다.

## C.3 웹의 세 가지 언어

**HTML**
페이지의 **구조**를 적는 언어. "무엇이 있는가". 뼈대.

**CSS**
페이지의 **모양**을 정하는 언어. "어떻게 보이는가". 옷.

**JavaScript (JS)**
페이지의 **동작**을 적는 언어. "무엇을 하는가". 뇌. 게임의 99%가 여기 들어간다.

**태그 (Tag)**
HTML에서 `<canvas>`, `<p>`처럼 꺾쇠로 감싼 표시. 무엇이 있는지를 나타낸다.

**속성 (Attribute)**
태그 안에 쓰는 추가 정보. `<canvas id="game" width="800">`에서 `id`와 `width`가 속성이다.

**`id`**
태그에 붙이는 **이름표**. JavaScript가 이 이름으로 그 태그를 찾아온다. 같은 이름을 두 번 쓰지 않는다.

**주석 (Comment)**
코드에 쓰는 설명. 컴퓨터는 무시한다.
- JavaScript / CSS: `// 한 줄` 또는 `/* 여러 줄 */`
- HTML: `<!-- 이렇게 -->`

AI에게 "한국어 주석을 달아 줘"라고 요청하면 코드를 읽기 훨씬 쉬워진다.

**UTF-8 / `<meta charset="UTF-8">`**
글자를 어떤 방식으로 읽을지 정하는 설정. 이게 없으면 한글이 □나 ???로 깨진다.

## C.4 Canvas

**Canvas (캔버스)**
JavaScript로 그림을 그릴 수 있는 사각형 영역. 게임 화면이 여기 그려진다.

**`ctx` (컨텍스트, Context)**
Canvas에 그릴 때 쓰는 **붓**. `canvas.getContext("2d")`로 가져온다. 모든 그리기 명령이 `ctx.`으로 시작한다. 이름은 관례이고 다른 이름을 써도 되지만, 거의 모두 `ctx`라고 쓴다.

**좌표 (x, y)**
위치를 나타내는 숫자 두 개. Canvas에서는 **(0,0)이 왼쪽 위**이고, **y가 커지면 아래로** 내려간다. 수학 시간의 좌표와 y축 방향이 반대다.

**`fillRect(x, y, 가로, 세로)`**
색칠된 사각형을 그린다. 앞의 두 숫자는 왼쪽 위 꼭짓점 위치, 뒤의 두 숫자는 크기.

**`fillStyle`**
붓에 묻히는 색. `"red"` 같은 이름이나 `"#1e3a5f"` 같은 코드를 쓴다. **그리기 전에** 설정해야 적용된다.

**`arc()`**
원이나 호를 그린다. `beginPath()` → `arc()` → `fill()` 순서로 쓴다. `Math.PI * 2`는 "한 바퀴"라는 뜻이다.

**`fillText(글자, x, y)`**
글자를 그린다. 점수나 안내 문구를 표시할 때 쓴다.

**`drawImage(이미지, x, y, 가로, 세로)`**
그림 파일을 그린다. **`img.onload` 안에서 그려야** 보인다. 파일을 불러오는 데 시간이 걸리기 때문이다.

**`clearRect(0, 0, 가로, 세로)`**
지정한 영역을 지운다. 움직임을 만들려면 "지우고 다시 그리기"를 반복해야 하므로, 4장부터 매 프레임 쓰인다.

**픽셀 (px, pixel)**
화면을 구성하는 가장 작은 점. Canvas의 좌표와 크기는 모두 픽셀 단위다. `width="800"`은 가로 800픽셀이라는 뜻이다.

## C.5 Git과 GitHub

**Git**
내 컴퓨터에 설치하는 프로그램. 변경 이력을 기록하고 되돌린다. 일지를 쓰는 **펜**.

**GitHub**
Git 기록을 인터넷에 보관하고 공개하는 웹사이트. 일지를 보관하는 **도서관**.

**저장소 (Repository, 레포)**
한 프로젝트의 파일과 이력을 담는 단위. 우리의 저장소 이름은 `my-game`이다.

**커밋 (Commit)**
그 순간의 파일 상태 전체를 통째로 기록하는 것. **게임의 세이브 포인트.** 설명 한 줄(커밋 메시지)을 붙인다.

**커밋 메시지**
그 커밋에서 무엇을 했는지 쓴 한 줄. "수정", "ㅇㅇ"처럼 쓰면 나중에 돌아갈 지점을 찾을 수 없다.

**스테이지 (Stage)**
커밋에 포함할 변경을 골라 담는 단계. VS Code에서는 보통 "모두 추가할까요?"에 Yes를 누르면 자동으로 처리된다.

**푸시 (Push) / Sync Changes**
내 컴퓨터의 커밋을 GitHub로 올리는 것. **커밋만 하고 푸시를 안 하면 GitHub에는 아무것도 없다.**

**풀 (Pull)**
GitHub에 있는 변경을 내 컴퓨터로 가져오는 것. 혼자 작업하는 이 수업에서는 거의 쓰지 않는다.

**브랜치 (Branch)**
작업 줄기. 이 수업에서는 `main` 하나만 쓴다.

**`main`**
기본 브랜치의 이름. GitHub Pages가 기본으로 바라보는 브랜치다.

**되돌리기 (Discard Changes)**
커밋하지 않은 변경을 버리고, 마지막 커밋 상태로 돌아가는 것. **AI가 코드를 망쳤을 때 쓰는 구조대.** 단, 되돌리면 복구할 수 없으니 커밋을 자주 해 둔다.

**diff (차이 보기)**
커밋된 상태와 지금 상태를 나란히 비교해 보여 주는 화면. 소스 제어에서 파일 이름을 클릭하면 열린다. 빨간색은 지워진 줄, 초록색은 추가된 줄. **AI가 뭘 바꿨는지 확인하는 가장 빠른 방법.**

**Public / Private**
저장소 공개 여부. 무료 GitHub Pages를 쓰려면 **Public**이어야 한다. 그래서 비밀번호나 개인정보를 코드에 쓰지 않는다.

**GitHub Pages**
GitHub가 정적 웹페이지를 무료로 공개해 주는 기능. 주소는 `https://(아이디).github.io/(저장소이름)/` 형태다.

**정적 (Static) / 동적 (Dynamic)**
HTML/CSS/JS 파일만으로 끝나는 것이 **정적**, 서버가 매번 내용을 만들어 주는 것이 **동적**. 우리가 만드는 것은 정적이라서 무료 배포가 된다. 서버가 필요한 것(온라인 랭킹 등)은 심화에서 다룬다.

**404**
"그 주소에 파일이 없다"는 뜻의 에러. 배포에서 404가 나면 보통 `index.html`이 저장소 맨 위에 없는 것이다. (부록 D.5)

**캐시 (Cache)**
브라우저가 한 번 받은 파일을 기억해 두는 것. 고친 내용이 반영되지 않을 때는 `Ctrl+F5`로 강력 새로고침한다.

## C.6 프로그래밍 기본

> 4장 이후 용어는 그 주차에 추가된다. 지금은 3장까지 나온 것만 있다.

**변수 (Variable)**
값을 담아 두는 상자. `const canvas = ...`에서 `canvas`가 변수 이름이다. 4장에서 게임의 상태(위치, 점수)를 기억하는 데 본격적으로 쓴다.

**`const` / `let`**
변수를 만들 때 쓰는 말. `const`는 **바뀌지 않는 값**, `let`은 **바뀌는 값**에 쓴다. 캐릭터의 위치처럼 계속 변하는 것은 `let`이다.

**함수 (Function)**
"이름이 붙은 작업 묶음". `function 이름() { ... }` 형태. 한 번 만들어 두고 여러 번 부를 수 있다.

**호출 (Call)**
함수를 실행시키는 것. `ctx.fillRect(...)`처럼 이름 뒤에 괄호를 붙이면 호출이다.

**인자 / 매개변수 (Argument / Parameter)**
함수 괄호 안에 넣는 값. `fillRect(100, 50, 200, 80)`의 네 숫자가 인자다.

**객체 (Object)**
관련된 값을 묶어 놓은 것. `ctx`도 객체이고, `ctx.fillRect`는 "ctx 객체가 가진 기능"이라는 뜻이다. 점(`.`)은 "~의"라고 읽으면 된다.

**에러 (Error)**
코드에 문제가 있어 실행이 멈추는 것. `F12` → Console에 빨간 글씨로 나온다. **에러 메시지는 요약하지 말고 그대로 복사해서** AI에게 보낸다.

**프레임 (Frame)**
화면을 한 번 그린 것. 1초에 60프레임이면 1초에 60번 다시 그린다는 뜻이다. 4장의 주제.

**라이브러리 / 프레임워크**
남이 미리 만들어 둔 코드 묶음. 이 수업은 본과정에서 쓰지 않는다(순수 HTML/CSS/JS). 심화 12장에서 Phaser 같은 게임 라이브러리를 맛본다.

## C.7 게임 루프와 상태 (4장)

**상태 (State)**
게임이 기억하고 있는 값들의 묶음. 위치, 속도, 점수, 생명 같은 숫자다. **게임은 "숫자 몇 개"이고, 화면은 그 숫자를 그림으로 보여 주는 것일 뿐이다.** 화면이 이상할 때는 "어느 숫자가 잘못되었나"를 본다.

**게임 루프 (Game Loop)**
"지우기 → 계산 → 그리기"를 1초에 약 60번 반복하는 장치. 게임의 심장. 보통 `gameLoop`이라는 이름의 함수로 만든다.

**`requestAnimationFrame(함수)`**
"다음 한 장을 그릴 때가 되면 이 함수를 불러 줘"라고 브라우저에 **부탁**하는 명령. 화면 주사율에 맞춰 주고, 다른 탭으로 가면 알아서 멈춰 준다. 게임 애니메이션의 표준 방식이다.

**`setInterval`**
"몇 초마다 실행해"라고 강제하는 다른 방식. 브라우저 사정과 어긋나 움직임이 튈 수 있어서 **게임에는 쓰지 않는다.** AI가 이걸로 만들어 주면 `requestAnimationFrame`으로 바꿔 달라고 요청한다.

**프레임 (Frame)**
화면을 한 번 그린 것. "1초에 60프레임"은 1초에 60번 다시 그린다는 뜻이다.

**주사율 (Refresh rate)**
모니터가 1초에 화면을 몇 번 갱신하는지. 보통 60Hz(초당 60번)이고, 게이밍 모니터는 120Hz 이상이다. 기기마다 달라서 같은 속도 값이 다르게 느껴질 수 있다.

**`x = x + 3` / `x += 3`**
"지금 x에 든 값을 꺼내서 3을 더하고, 그 결과를 다시 x에 넣어라". 수학의 등호가 아니라 **대입 명령**이다. 두 표기는 같은 뜻이다. 이 한 줄이 모든 움직임을 만든다.

**속도 (Speed / Velocity)**
한 프레임에 위치에 더하는 값. **부호가 방향을 정한다** — `speedX`가 양수면 오른쪽, 음수면 왼쪽. `speedY`가 양수면 **아래**, 음수면 **위**. 점프가 음수인 이유다.

**`speedX = -speedX`**
속도의 부호를 뒤집는 것. 오른쪽으로 가던 것이 왼쪽으로 바뀐다. **벽에서 튕기는 동작의 전부**다.

**튜닝 (Tuning)**
코드 구조는 그대로 두고 **숫자만 조정해서** 게임의 느낌을 맞추는 작업. 속도, 크기, 간격, 난이도가 대상이다. 게임의 재미가 대부분 여기서 결정된다. 9장에서 본격적으로 한다.

**델타 타임 (Delta time)**
프레임 사이에 실제로 흐른 시간. 기기 주사율이 달라도 같은 속도로 움직이게 만드는 정식 방법이다. **이 수업에서는 이동 속도에는 쓰지 않는다**(숫자 조정으로 맞춘다). 다만 **"몇 초 지났는가"가 중요한 것 — 점수, 난이도 상승 — 은 프레임을 세지 말고 `Date.now()`로 재야 한다.** 120Hz 기기에서 프레임은 두 배로 돌지만 1초는 어디서나 1초다 (6·8장).

**`if` (조건문)**
"만약 ~라면 안쪽을 실행한다". `if (ballX > 800) { ... }` 처럼 쓴다. 5장에서 제대로 다룬다.

**`||` / `&&`**
`||`는 "또는", `&&`는 "그리고". `if (x < 0 || x > 800)`은 "x가 0보다 작거나 800보다 크면"이라는 뜻이다.

**`//` (주석 처리)**
코드 줄 앞에 붙이면 그 줄이 실행되지 않는다. **지우지 않고 잠시 끄는** 방법이라, 원리를 확인하는 실험에 유용하다. 실험이 끝나면 지운다.

## C.8 입력과 조건문 (5장)

**이벤트 (Event)**
"어떤 일이 생겼다"는 사건. 키가 눌림, 마우스가 클릭됨, 창 크기가 바뀜 등. 언제 생길지 미리 알 수 없으므로, **생기면 실행할 작업을 미리 등록해 둔다.** 식당의 호출벨과 같다.

**`addEventListener("이벤트", 함수)`**
"이 일이 생기면 이 작업을 해 줘"라고 등록하는 명령. 키보드는 `document`에, 마우스는 `canvas`에 거는 것이 보통이다.

**`keydown` / `keyup`**
키를 누르는 순간 / 키에서 손을 떼는 순간에 생기는 이벤트.

**`e` (이벤트 객체)**
일어난 일에 대한 정보 묶음. `e.key`로 눌린 키 이름을, `e.clientX`로 마우스 위치를 꺼낼 수 있다. 이름은 관례이고 `event`라고 써도 된다.

**`e.key`**
눌린 키의 이름. `"ArrowLeft"`, `"ArrowRight"`, `"ArrowUp"`, `"ArrowDown"`, `" "`(스페이스바), `"Enter"`, `"a"` 등. **대소문자를 구분한다.** 헷갈리면 `console.log(e.key)`로 확인한다.

**`keys` 객체 (눌린 키 메모장)**
지금 눌려 있는 키를 기록해 두는 상자. `keydown`에서 `true`, `keyup`에서 `false`를 적고, **게임 루프가 그 기록을 보고 움직인다.** 이 방식이라야 꾹 눌렀을 때 매끄럽게 움직이고, 두 키를 같이 눌렀을 때 대각선으로 간다.

**`e.preventDefault()`**
"브라우저야, 네 기본 동작은 하지 마". 방향키나 스페이스바로 **페이지가 스크롤되는 것을 막을 때** 쓴다. 게임 화면이 흔들리면 이걸 떠올린다.

**`click` / `mousedown` / `mousemove`**
마우스를 클릭할 때 / 버튼을 누르는 순간 / 움직일 때 생기는 이벤트.

**`getBoundingClientRect()`**
Canvas가 화면에서 어디에 있는지 알아내는 명령. 마우스 좌표는 **브라우저 창 기준**으로 오기 때문에, 이걸로 **Canvas 기준 좌표로 변환**해야 한다. 빼먹으면 마우스와 플레이어 위치가 어긋난다.

**`if` / `else if` / `else` (조건문)**
"만약 ~라면 / 아니고 ~라면 / 둘 다 아니면". 조건이 맞을 때만 중괄호 안이 실행된다.

**`=` vs `===`**
`=`는 **넣어라**(대입), `===`는 **같은가?**(비교). 조건 안에는 `===`를 쓴다. 이걸 섞어 쓰는 것이 5장에서 가장 흔한 실수다.

**비교 기호**
`===` 같다 / `!==` 다르다 / `>` 크다 / `<` 작다 / `>=` 크거나 같다 / `<=` 작거나 같다.

**`true` / `false` (불리언, Boolean)**
"예 / 아니오"를 나타내는 값. `keys["ArrowLeft"]`가 `true`면 지금 왼쪽 키가 눌려 있다는 뜻이다.

**`console.log(값)`**
값을 콘솔(`F12`)에 출력하는 명령. **지금 어느 숫자가 어떤 값인지 확인하는 가장 빠른 방법**이고, 7장 디버깅의 주역이다.

**중력 (Gravity)**
매 프레임 세로 속도에 더하는 작은 값(보통 0.5~1). 이걸 더하면 올라가던 물체가 서서히 느려지다 떨어진다. 점프의 핵심이다.

**점프력 (Jump power)**
점프할 때 세로 속도에 넣는 값. Canvas에서 위는 y가 작아지는 방향이므로 **음수**(보통 -10~-15)다.

## C.9 배열, 충돌, 게임 규칙 (6장)

**배열 (Array)**
같은 종류의 것을 줄 세워 담는 상자. `[10, 25, 40]` 형태. 번호가 붙은 사물함 한 줄이라고 보면 된다. **번호는 0부터 시작한다.**

**인덱스 (Index)**
배열의 칸 번호. `enemies[0]`은 첫 번째 적. 마지막은 `length - 1`이다. 범위를 벗어나면 `undefined` 에러가 난다.

**`length`**
배열에 담긴 개수. `enemies.length`가 5면 적이 5마리다.

**`push()` / `splice()`**
배열 맨 뒤에 하나 추가 / 중간에서 빼내기. 적을 새로 만들거나 없앨 때 쓴다.

**객체 (Object)**
관련된 값을 한 덩어리로 묶은 것. `{ x: 100, y: 0, speed: 3 }` 형태. 점(`.`)으로 꺼내 쓴다 — `enemy.x`는 "enemy의 x".

**객체 배열**
객체를 담은 배열. `enemies = [{x,y,speed}, {x,y,speed}, ...]`. **"적들"이라는 이름 하나로 몇 개든 다룰 수 있다.** 6장의 핵심 도구다.

**반복문 / `for`**
배열에 담긴 것 전부에 같은 일을 시키는 장치. `for (let i = 0; i < 개수; i++)`로 쓴다. `i`는 지금 몇 번째를 보고 있는지 나타내는 번호다.

**`forEach`**
`for`와 같은 일을 하는 다른 표기법. AI가 이걸 쓸 수도 있다. 읽기 어려우면 "for 반복문으로 바꿔 줘"라고 요청한다.

**충돌 판정 (Collision detection)**
두 물체가 겹쳤는지를 **숫자 비교로** 알아내는 계산. 컴퓨터는 눈이 없어서 그림을 보고 판단하지 않는다.

**사각형 충돌 (AABB)**
네 조건이 모두 참이면 겹친 것으로 본다. 외울 필요는 없고 **"가로로도 겹치고 세로로도 겹치면 충돌"** 로 기억한다. 조건을 `&&`(그리고)로 잇는다.

**원 충돌**
두 중심 사이의 **거리가 반지름 합보다 작으면** 겹친 것. 거리는 피타고라스 정리로 구한다 — `Math.sqrt(dx*dx + dy*dy)`.

**히트박스 (Hitbox)**
충돌 판정에 실제로 쓰는 영역. 그림과 꼭 같을 필요는 없고, **그림보다 조금 작게** 만들면 플레이가 훨씬 할 만해진다. 테두리로 그려 두면 판정 문제를 눈으로 확인할 수 있다.

**`Math.sqrt()` / `Math.floor()` / `Math.random()`**
제곱근 / 소수점 버리기 / 0~1 사이 랜덤 숫자. 점수를 정수로 만들 때 `Math.floor`, 적의 위치를 랜덤으로 둘 때 `Math.random`을 쓴다.

**`gameState` (게임 상태)**
게임이 지금 어떤 국면인지 기억하는 변수. `"playing"`, `"gameover"` 같은 값을 담는다. 8장에서 `"start"`를 추가하면 시작 화면이 된다.

**게임 오버 (Game over)**
실패 조건이 충족된 상태. **게임 루프는 멈추지 않는다** — 상태만 바꾸고, 루프는 계속 돌면서 게임 오버 화면을 그린다. 그래야 재시작할 수 있다.

**재시작 / `resetGame`**
상태 값들을 처음 값으로 되돌리는 함수. 점수, 위치, 적 배치를 모두 되돌려야 한다. 하나라도 빠뜨리면 "재시작했는데 점수가 그대로"가 된다.

**난이도 튜닝**
적의 개수·속도·크기, 플레이어 속도, 판정 영역을 조정해 어려움을 맞추는 작업. 목표는 **내가 플레이해서 10~30초 버티는 수준**이다.

**플레이테스트 (Playtest)**
다른 사람에게 플레이시켜 보는 것. 설명 없이 시작했을 때 무엇을 해야 하는지 알아보는지가 핵심 관찰 항목이다. 9장의 주제.

## C.10 디버깅 (7장)

**디버깅 (Debugging)**
버그를 찾아 고치는 일. **90%는 "어디가 문제인가"를 찾는 일**이고, 고치는 것은 마지막 10%다. 위치를 알면 AI도 정확하게 고친다.

**버그 (Bug)**
의도와 다르게 동작하는 것. 에러가 나는 버그와, 에러 없이 결과만 틀리는 **조용한 버그**가 있다. 후자가 훨씬 많다.

**개발자 도구 (DevTools)**
`F12`로 여는 브라우저 도구. 이 수업에서 쓰는 탭은 **Console**(에러와 출력)과 Elements(HTML 구조) 둘이다. **테스트할 때는 콘솔을 열어 두는 것이 습관이 되어야 한다.**

**스택 트레이스 (Stack trace)**
에러 메시지 아래에 붙는 `at gameLoop (script.js:47)` 같은 줄. **파일 이름과 줄 번호**가 들어 있고, **클릭하면 그 줄로 바로 이동한다.**

**`SyntaxError`**
문법이 깨졌다. 보통 괄호나 중괄호의 짝이 안 맞는다. 이 에러가 나면 **코드 전체가 실행되지 않아서 화면이 아예 안 뜬다.**

**`ReferenceError: X is not defined`**
X라는 이름을 모른다. **변수 이름 오타**(대소문자 포함)이거나, 선언하지 않고 썼다. 가장 흔한 에러.

**`TypeError: Cannot read properties of null/undefined`**
없는 것의 속을 보려 했다. `null`이면 보통 **`getElementById`가 요소를 못 찾은 것**(id 불일치), `undefined`면 보통 **배열 번호가 범위를 넘은 것**이다.

**`NaN` (Not a Number)**
"숫자가 아님". 숫자에 글자를 섞어 계산하면 생긴다. 에러는 안 나고 화면에 `NaN`이 그대로 표시된다.

**`null` / `undefined`**
`null`은 "비어 있음"을 명시한 값, `undefined`는 "값이 아직 없음". 둘 다 **그 안의 속성을 꺼내려 하면 `TypeError`가 난다.**

**`console.log(값)`**
값을 콘솔에 출력한다. **디버깅의 주역.** 이름표를 붙여 찍고(`console.log("player.x =", player.x)`), 루프 안에서는 조건을 걸어 찍는다(1초에 60줄이 쏟아지므로).

**범위를 반으로 좁히기 (이분 탐색)**
코드 중간에 `console.log`를 찍어, 그 지점에서 값이 정상인지 보고 **문제가 앞쪽인지 뒤쪽인지 가른다.** 몇 번 반복하면 문제의 줄에 도달한다. 프로도 가장 많이 쓰는 방법.

**재현 조건**
버그가 **언제** 생기는지. "오른쪽 벽에 붙었을 때만", "빠르게 두 번 누를 때만" 같은 것. 이것을 특정하면 원인이 거의 좁혀진다. AI에게 버그를 설명할 때 가장 강력한 정보다.

**시각화 디버깅**
보이지 않는 것을 화면에 그려서 확인하는 기법. 히트박스를 테두리로 그리거나, 좌표·개수·상태를 화면에 글씨로 띄운다. **보이면 추측하지 않는다.**

**디버그 플래그 (`showDebug` / `showHitbox`)**
디버그 표시를 켜고 끄는 변수. 개발 중에는 켜고, 제출할 때는 끈다. **코드는 지우지 않는다** — 다음에 또 필요하다.

**주석 처리로 끄기 (`//`)**
줄을 지우지 않고 잠시 실행되지 않게 하는 것. 모르는 줄의 역할을 확인하는 가장 빠른 방법이다.

**`is~` / `has~` 로 시작하는 이름**
예/아니오 값(불리언)을 담은 변수나 함수. `isJumping`은 "점프 중인가?"라는 뜻이다. 이름으로 역할을 짐작하는 데 도움이 된다.

## C.11 소리, 저장, 에셋 (8장)

**`new Audio("파일명")`**
소리 파일을 불러와 준비하는 것. **게임 루프 안이 아니라 코드 위쪽에서 한 번만** 만든다. 매 프레임 새로 만들면 게임이 느려진다.

**`.play()` / `.currentTime = 0`**
재생 / 처음으로 되감기. **이미 재생 중일 때 `play()`를 다시 부르면 아무 일도 일어나지 않으므로**, 되감아서 처음부터 다시 나게 한다. 단 이건 **이전 소리를 끊고 다시 시작하는 것**이지 겹쳐 나는 것이 아니다. 겹침이 꼭 필요하면 `cloneNode()`로 사본을 만들어 재생한다 (많이 만들면 느려진다).

**`.volume` / `.loop`**
음량(0~1) / 반복 재생. 배경음악은 `volume`을 0.3 이하로 두고 **끌 수 있게** 만든다.

**자동 재생 제한 (Autoplay policy)**
브라우저는 **사용자가 클릭이나 키 입력을 하기 전에는 소리를 재생하지 않는다.** 광고 소음을 막기 위한 정책이다. 그래서 "아무 키나 눌러 시작" 화면을 거치면 그 뒤로는 소리가 자유롭게 난다.

**화면 전환 (State transition)**
`gameState` 값을 바꿔 화면을 갈아 끼우는 것. `"start"` → `"playing"` → `"gameover"`. **상태 값 하나만 늘리면 화면이 하나 늘어난다** — 6장에서 루프를 멈추지 않는 구조로 만든 이유다.

**난이도 곡선 (Difficulty curve)**
시간이나 점수에 따라 어려움이 올라가는 설계. 처음 10초는 거의 안 죽을 정도로 쉽게, 그 뒤로 조여 온다.

**`%` (나머지 연산)**
나눈 나머지를 구한다. `i % 2 === 0`은 "짝수일 때"라는 뜻. 일정 간격을 만들 때도 쓰이지만, **"몇 초마다"를 프레임 수로 만드는 데는 쓰지 않는다** — 기기마다 달라진다. 시간 간격은 `Date.now()`로 잰다.

**`Math.min()` / `Math.max()`**
둘 중 작은 값 / 큰 값을 고른다. `Math.min(speed + 0.5, 12)`는 **속도를 올리되 12를 넘지 않게** 한다. 난이도 **상한**을 두는 기본 도구다.

**`localStorage`**
브라우저에 값을 남겨 두는 저장소. 새로고침하거나 브라우저를 닫아도 남는다. `setItem("이름", 값)`으로 저장, `getItem("이름")`으로 꺼낸다.

**`localStorage`의 함정 — 꺼내면 글자다**
무엇을 넣어도 **문자열로 저장된다.** 그래서 꺼낸 값으로 크기를 비교하면 `"9" > "100"`이 참이 되는 일이 생긴다. `Number(...)`로 숫자로 바꿔 쓴다.

**`|| 0`**
"없으면 0을 쓴다". 처음 플레이하는 사람은 저장된 값이 없으므로 필요하다.

**`JSON.stringify()` / `JSON.parse()`**
배열이나 객체를 글자로 바꾸기 / 글자를 되돌리기. `localStorage`에 **순위표처럼 여러 값을 저장할 때** 필요하다.

**에셋 (Asset)**
게임에 쓰는 그림, 소리, 글꼴 등의 소재.

**스프라이트 (Sprite)**
게임에 쓰는 캐릭터·물체 그림.

그 에셋을 어떤 조건으로 쓸 수 있는지 정한 약속. **"무료"와 "자유롭게 써도 됨"은 다르다.**

## C.12 다듬기와 모바일 (9장)

**플레이테스트 (Playtest)**
다른 사람에게 플레이시켜 보는 것. 규칙은 **설명하지 않고, 말 걸지 않고, 변명하지 않고, 본다.** 말보다 **행동**이 정확한 정보다.

**30초 규칙**
처음 30초 안에 무엇을 해야 하는지 모르면 그 게임은 실패한다. 링크를 받은 사람은 설명서를 읽지 않는다.

**증상과 처방**
테스터는 보통 **처방**("더 빠르게 해")으로 말한다. 고칠 것은 그 사람이 **무엇을 하려다 실패했는지**(증상)이고, 처방을 그대로 따르면 더 나빠질 수도 있다.

**우선순위 (빈도 · 치명도 · 비용)**
두 명 이상이 겪었나 / 게임을 못 하게 만드나 / 숫자 하나로 되나 구조를 바꿔야 하나. **1순위 2~3개만 고친다.**

**미반영 판단**
받은 피드백을 반영하지 않기로 하는 것도 설계다. **이유를 기록하면** 반영한 것과 같은 평가를 받는다. 모든 의견을 따르는 것은 설계가 아니다.

**리팩터링 (Refactoring)**
겉보기 동작은 그대로 두고 **코드 내부만 정리**하는 것. 4원칙: ① 먼저 커밋 ② 한 번에 하나 ③ "동작은 절대 바꾸지 마" 명시 ④ 매번 플레이해서 확인.

**테스트 체크리스트**
코드를 고친 뒤 하나씩 눌러 확인하는 목록. 시작·조작·충돌·점수·소리·재시작·콘솔 에러 등. **고칠 때마다 전부 확인하는 것**이 깨짐을 막는 유일한 방법이다.

**"최적화해 줘" / "더 좋은 구조로" 가 위험한 이유**
동작이 바뀌거나, 클래스·모듈처럼 **내가 설명할 수 없는 구조**로 바뀐다. 이 수업의 평가 기준(코드를 내 말로 설명한다)에 정면으로 어긋난다.

**`viewport` meta 태그**
`<meta name="viewport" content="width=device-width, initial-scale=1.0">`. 이 줄이 없으면 휴대폰이 페이지를 **축소해서** 보여 줘서 글씨가 깨알같이 작아진다.

**`max-width: 100%`**
canvas가 화면 폭을 넘지 않게 하는 CSS. 단 **canvas의 `width`/`height` 속성 값은 바꾸지 않는다** — 그건 좌표계이고, CSS는 보이는 크기만 줄인다.

**좌표 비율 보정**
canvas의 실제 크기(`width="800"`)와 화면에 보이는 크기가 다르면, 마우스·터치 좌표가 어긋난다. 두 크기의 **비율로 나눠 보정**해야 한다. 모바일에서 터치 위치가 안 맞는 거의 모든 원인이다.

**터치 이벤트 (`touchstart` / `touchmove` / `touchend`)**
마우스의 `mousedown` / `mousemove` / `mouseup`에 대응한다. 터치할 때 **화면이 스크롤되거나 확대되는 것**은 `preventDefault`로 막는다 (5장과 같은 문제).

**반응형 (Responsive)**
화면 크기에 따라 배치가 달라지게 만드는 것. 이 수업에서는 **"잘리지 않게 보이기"** 까지만 한다.

## C.13 API와 온라인 (11장 · 심화)

**API (Application Programming Interface)**
프로그램이 다른 프로그램에 요청을 보내는 **창구**. 주방에 들어가지 않고 정해진 창구로 정해진 양식의 주문서를 보내는 것과 같다.

**요청의 네 요소**
**주소(URL)** 어느 창구인가 / **방식(method)** 무엇을 하려는가 / **헤더(header)** 신분증과 양식 / **본문(body)** 보낼 내용.

**`GET` / `POST` / `PATCH` / `DELETE`**
가져온다 / 새로 만든다 / 고친다 / 지운다. 랭킹에 필요한 것은 `GET`과 `POST` 둘뿐이다.

**`fetch(url)`**
JavaScript에서 API를 호출하는 명령.

**`async` / `await`**
"답이 올 때까지 기다린다". 인터넷 요청은 시간이 걸리므로 `await`을 붙이고, `await`을 쓰는 함수 앞에는 `async`를 붙인다. **빠뜨리면 `undefined`가 나온다** — 3장의 `img.onload`와 같은 문제다.

**`try` / `catch`**
"해 보고, 실패하면 이렇게 해라". 인터넷 요청은 반드시 실패할 수 있으므로 모든 요청을 감싼다. **원칙: 랭킹이 안 되더라도 게임은 플레이할 수 있어야 한다.**

**JSON**
데이터를 글자로 주고받는 형식. 객체·배열과 거의 똑같이 생겼다. `res.json()`을 거치면 6장에서 쓴 **객체 배열**이 되고, `for` 반복문으로 그려 낼 수 있다.

**정적 (Static) 웹페이지**
HTML/CSS/JS 파일만으로 된 페이지. GitHub Pages가 파일을 그대로 내려 줄 뿐이라 **데이터를 기록해 둘 공간이 없다.** 그래서 랭킹에는 외부 서비스가 필요하다.

**백엔드 서비스 (BaaS)**
데이터베이스와 접근 규칙을 대신 맡아 주는 서비스. Supabase, Firebase 등.

**API 키**
"누가 보낸 요청인가"를 확인하는 신분증.

**공개용 키 (publishable / public / anon)**
**공개되도록 설계된** 키. 브라우저 코드에 넣어도 된다. 비밀로 지키는 게 아니라, **그 키로 할 수 있는 일을 서버에서 제한해서** 지킨다.

**비밀 키 (secret / service_role)**
**절대 공개 금지.** 모든 데이터를 읽고 지울 수 있다. 브라우저 코드에 넣지 않는다. 키 이름은 서비스마다 바뀌지만 판단 기준은 하나다 — **`secret`이나 `service`가 붙으면 공개 금지.**

**키가 노출되었을 때의 순서**
① **서비스 대시보드에서 즉시 재발급·폐기** ② 코드에서 지운다. **2번만 하면 안 된다** — Git은 모든 이력을 보관하므로 지운 키도 커밋 이력에서 조회할 수 있다.

**브라우저 코드는 숨길 수 없다**
난독화·변수명 변경·파일 분리 모두 소용없다. 브라우저가 실행하려면 읽을 수 있어야 하고, 읽을 수 있으면 사람도 읽을 수 있다.

**RLS (Row Level Security, 행 수준 보안)**
"이 표에 대해, 누가, 어떤 동작을 할 수 있는가"를 정하는 설정. **켜지 않으면 공개용 키로 누구나 전체 삭제가 가능하다.** 켜고 나면 **규칙을 만든 동작만** 허용된다 — 규칙이 없으면 차단이다.

**RLS 차단은 에러로 오지 않는 경우가 있다**
읽기는 `200` + **빈 목록**, 수정·삭제는 `204`(0개 처리)로 온다. 등록만 `403` 에러다. 그래서 **응답 코드로 "막혔는지"를 판단하면 거꾸로 읽는다** — 삭제 차단은 **표의 행 수가 그대로인지**로 확인한다.

**`with check` (서버 쪽 제한)**
등록 정책에 함께 거는 조건. 점수 범위나 이름 길이를 여기에 걸면 **브라우저에서 우회할 수 없다.** 브라우저 코드에 적은 제한은 정상 사용자의 실수만 막는다.

**최소 권한 원칙**
필요한 동작만 허용한다. 랭킹에는 읽기(SELECT)와 등록(INSERT)만 열고, 수정(UPDATE)과 삭제(DELETE)는 막는다. 그러면 키가 노출되어도 최악은 "장난 점수 추가"까지다.

**클라이언트를 믿지 않는다**
브라우저에서 보낸 데이터는 사람이 아무 값으로나 바꿀 수 있다. 콘솔에서 요청을 직접 보내면 플레이 없이 999999점을 올릴 수 있다. **내 코드가 허술해서가 아니라 원래 그렇다.** 완전한 해결은 서버에서 검증하는 것이고, 이 수업 범위에서는 상한·플레이 시간 검사 같은 **완화책**까지다.

**CORS**
브라우저가 "이 사이트가 저 서버에 요청해도 되는가"를 확인하는 규칙. 이 장에서 CORS 에러가 나면 대개 **주소나 키가 잘못된 것**이다.

**서버리스 함수 (Serverless function)**
비밀 키를 보관하는 작은 중간 서버. 브라우저 → 내 함수(키 보관) → 유료 API 구조로 쓴다. **이 수업 범위를 넘지만, "브라우저에 비밀 키를 둘 수 없을 때는 중간에 서버를 둔다"** 는 해결 방향은 기억해 둔다.

## C.14 라이브러리와 AI 기능 (12장 · 심화)

**라이브러리 (Library)**
남이 미리 만들어 둔 코드 묶음. **편리함을 주고 이해를 가져간다.** 직접 만들어 본 다음에 쓰면 무엇을 대신해 주는지 보이지만, 처음부터 쓰면 문제가 생겼을 때 **내 코드와 라이브러리 중 어디가 문제인지 구분할 수 없다.**

**Phaser**
2D 웹 게임용 라이브러리. 게임 루프, 스프라이트, 물리 엔진, 입력, 사운드, 화면 관리가 들어 있다.

**Scene (씬)**
Phaser에서 화면 단위. 우리가 `gameState`로 갈랐던 것(`start`/`playing`/`gameover`)에 해당한다.

**`preload` / `create` / `update`**
Phaser의 세 구역. 에셋 미리 불러오기(3장의 `img.onload`) / 처음 한 번 실행 / **매 프레임 실행(4장의 `gameLoop`)**.

**물리 엔진 (Physics engine)**
중력, 충돌, 튕김을 대신 계산해 주는 것. 6장에서 직접 만든 충돌 판정이 한 줄로 줄어든다.

**CDN**
라이브러리를 설치하지 않고 인터넷에서 바로 불러오는 방식. `<script src="https://...">` 한 줄이면 된다.

**게임 AI (전통적 의미)**
적의 행동을 **규칙으로** 만드는 것. 플레이어를 추적하고, 거리에 따라 행동을 바꾸고, 패턴을 섞는다. **AI API와 아무 상관이 없지만** 플레이어에게는 "똑똑하다"고 느껴진다. 4~6장에서 배운 것만으로 만들 수 있고, 비용도 지연도 없다.

**사전 생성 방식 (방식 A)**
개발 중에 AI로 콘텐츠를 만들어 **파일로 저장해 두고** 쓰는 것. 메시지, 적 이름, 아이템 설명, 문제 은행 등. **키가 필요 없고 비용·지연·실패가 모두 0이다.** "플레이 중에 AI가 반응하는 느낌"의 대부분을 이 방식으로 낼 수 있다.

**실시간 호출 방식 (방식 B)**
플레이 중에 AI API를 부르는 것. **유료 키는 비밀 키이므로 브라우저에 둘 수 없다** → 중간에 서버리스 함수를 두고 그 함수만 키를 갖는다. 비용·지연(1~5초)·실패·남용·안전 문제가 모두 따라온다.

**토큰 과금**
AI API는 **주고받은 글자량(토큰)** 에 따라 돈이 든다. 호출 횟수뿐 아니라 **프롬프트가 길면 더 비싸다.** 사용자가 늘면 내 돈이 나가므로, 쓰기 전에 지출 상한과 알림을 먼저 설정한다.

**게임 루프 안에서 API를 부르면**
**1초에 약 60번** 호출된다. 요금과 사용량 사고의 가장 흔한 원인. 호출은 **상태가 바뀌는 시점에만** 한다 (11장의 "랭킹은 게임 오버 때 한 번"과 같은 원칙).

**프롬프트 인젝션 (Prompt injection)**
플레이어가 입력한 글을 AI 프롬프트에 그대로 넣으면, "지금까지 지시를 무시하고 …"처럼 써서 동작을 바꿀 수 있다. **입력을 걸러서 완전히 막는 방법은 없다** — 길이·종류 제한은 줄이는 것일 뿐이다. 그래서 막는 대신 **뚫려도 피해가 없게** 만든다: 모델에 비밀(키·시스템 지시)을 섞어 주지 않고, 모델의 답으로 중요한 동작을 실행하지 않고, 돌아온 답은 **비신뢰 텍스트**로 화면에 글자로만 표시한다.

**최소 예제 (Minimal example)**
새 기술을 배울 때 가장 먼저 돌려 보는 가장 작은 코드. **이걸 건너뛰고 내 코드에 바로 넣는 것이 실패의 원인이다.** 최소 예제가 있으면 안 될 때 비교할 기준이 생긴다.

**공식 문서 읽는 순서**
① Getting Started(가장 작은 예제) ② Examples(뭘 할 수 있나) ③ 내 문제 관련 페이지 ④ API Reference(사전처럼). **처음부터 다 읽지 않는다.** 블로그와 영상은 날짜를 확인하고, AI 설명이 공식 문서와 어긋나면 문서를 따른다.

**AI를 가르치는 도구로 쓰기**
"대신 만들어 줘"가 아니라 **"내가 이미 아는 것과 연결해서 설명해 줘"**. 10주 동안 쌓은 게임 루프·상태·충돌 판정이 **비교 기준**이 되어, 새 기술을 훨씬 빨리 읽을 수 있다.

**`textContent` vs `innerHTML`**
남이 적은 글을 HTML에 표시할 때, `innerHTML`은 그 내용을 **코드로 해석**하므로 누구나 등록할 수 있는 칸(랭킹 이름 등)에서는 위험하다. `textContent`는 무엇이 적혀 있어도 **글자로만** 표시한다. Canvas의 `ctx.fillText`도 글자로만 그려서 안전하다. **규칙: 남이 적은 것을 보여 줄 때는 `textContent`나 `fillText`를 쓴다.**

**환경변수 / `.env` / `.gitignore`**
키를 코드 파일이 아닌 **실행 환경**에 두는 방법. 호스팅 서비스 설정 화면에 넣거나, 로컬에서는 `.env` 파일에 두고 **`.gitignore`에 `.env`를 적어 커밋되지 않게** 한다. 저장소가 Public인 이 수업에서는 특히 중요하다 (12장 선택 과제).
