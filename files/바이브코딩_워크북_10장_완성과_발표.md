# 10장. 완성과 발표

> **이번 주 목표** 게임을 **끝낸다.** 그리고 10주 동안 한 일을 3분으로 말한다.

---

## 1. 학습 목표

이 장이 끝나면 다음을 할 수 있다.

- 내 게임을 **다른 사람의 환경에서** 검증할 수 있다.
- 처음 보는 사람이 이해할 수 있는 `README.md`를 쓸 수 있다.
- 10주 동안의 작업을 돌아보고 배운 것을 언어화할 수 있다.
- 3분 안에 내 작업을 설명하고 시연할 수 있다.
- 이 수업이 끝난 뒤 스스로 다음을 배우는 방법을 안다.

---

## 2. 개념 설명

### 2.1 "완성"은 상태가 아니라 결정이다

게임을 만들다 보면 끝이 없다. 고칠 것은 항상 남아 있고, 넣고 싶은 기능도 계속 생긴다. 그래서 완성은 이렇게 정의한다.

> **완성 = "여기까지"라고 결정하고, 남을 것을 정리하는 일.**

프로 개발자도 똑같다. 게임이 완벽해져서 출시하는 게 아니라, **출시일이 와서 출시한다.** 남은 것은 "다음 버전에서"로 넘긴다.

그래서 이번 주의 규칙은 하나다.

> **🚫 새 기능 추가 금지.** 9장보다 더 엄격하게.

발표 직전에 기능을 넣다가 게임이 깨지는 것은 매년 반복되는 일이다. 넣고 싶은 것은 **`README.md`의 "앞으로 하고 싶은 것"에 적는다.** 그게 더 좋은 평가를 받는다 — 무엇이 남았는지 아는 사람은 자기 작업을 이해하고 있다는 뜻이다.

### 2.2 "내 컴퓨터에서는 되는데요"

제출 직전에 가장 많이 발생하는 사고다. 원인은 늘 같다. **내 환경에만 있는 조건에 기대고 있었던 것.**

| 내 환경 | 남의 환경 |
|---|---|
| 로그인되어 있다 | 로그아웃 상태다 → 저장소가 Private이면 안 열린다 |
| 파일이 내 컴퓨터에 있다 | GitHub에 올라간 것만 보인다 → 커밋 안 한 파일은 없다 |
| Windows (대소문자 구분 없음) | 서버 (대소문자 구분) → `Player.png`와 `player.png`는 다르다 |
| 캐시에 옛 파일이 남아 있다 | 처음 받는다 → 캐시 때문에 나만 되는 경우가 있다 |
| 크롬 | 사파리·엣지일 수 있다 |
| 큰 모니터 | 휴대폰일 수 있다 |
| `localStorage`에 최고 점수가 있다 | 비어 있다 → 처음 플레이 상태를 테스트해야 한다 |

그래서 최종 점검은 **"내가 아닌 조건"에서** 한다. 세 가지를 반드시 한다.

1. **시크릿 모드**(`Ctrl+Shift+N`)로 배포 주소를 연다 → 로그아웃 + 캐시 없음 + `localStorage` 비어 있음, 세 조건이 한 번에 해결된다
2. **휴대폰**으로 데이터(와이파이 끄고)로 연다
3. **다른 사람**에게 링크를 보내 열리는지 확인한다

> **시크릿 모드가 최종 점검의 핵심 도구다.** "처음 오는 사람"의 환경을 가장 가깝게 재현한다.

### 2.3 `README.md` — 저장소의 얼굴

링크를 받은 사람이 가장 먼저 보는 것이 `README.md`다. 평가자도 여기서부터 본다.

**들어가야 할 것** (`README.md`는 2장 과제에서 처음 만들었다. 아래 Step 3에서 완성한다)

| 항목 | 왜 필요한가 |
|---|---|
| 게임 제목과 한 줄 설명 | 무슨 게임인지 |
| **플레이 링크** | 가장 중요하다. 맨 위에 둔다 |
| 조작법 | 링크를 받은 사람은 설명서를 안 읽는다 |
| 게임 규칙 (점수·게임 오버) | 목표가 무엇인지 |
| 스크린샷 1장 | 열어 보기 전에 분위기를 전한다 |
| **사용한 에셋 표** (출처·라이선스) | 8장 과제. 빠지면 감점 |
| 개발 환경 / 사용한 AI 도구 | **AI 사용은 숨기지 않고 기록한다** (0장 원칙 3) |
| 앞으로 하고 싶은 것 | 무엇이 남았는지 아는 것도 실력이다 |
| 모바일 지원 여부 | 9장 과제 |

**스크린샷 넣는 법**

`Windows + Shift + S`로 게임 화면을 캡처해서 `my-game` 폴더에 `screenshot.png`로 저장한 뒤, `README.md`에 이렇게 쓴다.

```markdown
![게임 화면](screenshot.png)
```

파일 이름은 영어로. 저장소에 **커밋해야** 보인다.

### 2.4 10주 회고 — 무엇이 남았는지 확인한다

매주 쓴 회고는 그 주의 기록이었다. 이번에는 **10주 전체**를 돌아본다.

1주차 회고를 다시 읽어 보면 대부분 놀란다. "이걸 몰랐었나" 싶은 것들이 적혀 있다. **그 격차가 이 수업의 결과물이다.**

아래 네 질문에 답한다. 과제이기도 하지만, **발표 자료의 재료**가 된다.

| 질문 | 왜 |
|---|---|
| ① 가장 어려웠던 문제와 뚫은 방법 | 발표의 핵심이 된다 |
| ② AI에게 맡기는 법이 어떻게 달라졌나 | 이 수업의 진짜 학습 내용 |
| ③ 10주 전의 나에게 한 가지 조언한다면 | 배운 것의 압축 |
| ④ 다음에 만들고 싶은 것 | 다음 단계 |

②번을 쓸 때는 **1주차와 9주차의 프롬프트를 나란히 놓고** 비교해 보면 좋다. 거의 모두 이런 변화가 보인다.

```
1주차:  "자기소개 페이지 만들어 줘"
9주차:  "script.js를 정리해 줘. 동작은 절대 바꾸지 마.
         게임 루프 안의 그리기 부분만 draw() 함수로 분리해 줘.
         다른 것은 건드리지 마."
```

**범위를 좁히고, 금지 조건을 붙이고, 확인 방법을 정하는 것** — 그것이 10주 동안 늘어난 능력이다. 이 능력은 게임이 아닌 어떤 작업에도 그대로 쓰인다.

### 2.5 3분 발표 구성

발표 시간은 짧다. 구성을 미리 정해 두지 않으면 시연만 하다 끝난다.

```
[0:00~0:30]  무슨 게임인가        제목 + 한 줄 설명 + 목표
[0:30~1:30]  시연                 실제 플레이. 한 판을 끝까지
[1:30~2:30]  가장 어려웠던 문제    무엇이 막혔고 어떻게 뚫었나  ⭐
[2:30~3:00]  코드 한 부분 설명     내 말로. 왜 그렇게 짰는가    ⭐
```

**⭐ 두 구간이 평가의 핵심이다.** 게임이 화려한 것보다, **막힌 것을 어떻게 뚫었는지**와 **코드를 이해하고 있는지**가 중요하다. 0장에서 말한 원칙이 끝까지 그대로다.

**시연 사고를 막는 세 가지**

| 위험 | 대비 |
|---|---|
| 와이파이가 안 된다 | **로컬 파일로도 실행 가능한 상태**를 준비해 둔다 |
| 발표 중에 바로 죽는다 | 난이도를 올려 둔 상태로 발표하지 않는다. 미리 한 판 연습한다 |
| 소리가 교실을 덮는다 | **M 키 음소거를 미리 켜 둔다**. 발표 전에 음량 확인 |
| 링크를 못 찾는다 | 브라우저에 **탭을 미리 열어 둔다** |

**"가장 어려웠던 문제"를 말하는 틀**

이 부분이 막막하면 아래 네 문장으로 말한다. 7장의 디버깅 기록 양식과 같은 구조다.

```
1. "○○을 하려고 했는데, △△가 되는 문제가 있었습니다."
2. "원인을 찾으려고 ○○을 해 봤습니다." (console.log / 히트박스 표시 등)
3. "알아보니 원인은 ○○이었습니다."
4. "그래서 ○○으로 고쳤습니다."
```

**실패한 것을 말해도 된다.** "끝까지 못 고쳤지만 원인이 ○○인 것은 확인했습니다"도 좋은 발표다. 이 수업의 평가 기준은 **막힘을 다루는 능력**이고, 그건 해결 여부와 별개다.

**말하지 않아도 되는 것**

- 코드를 한 줄씩 다 설명하는 것 (3분으로 불가능하다)
- 쓴 기술의 목록 나열 ("Canvas와 requestAnimationFrame과…")
- 변명 ("시간이 없어서", "원래는 더 하려고 했는데")

마지막 것이 특히 그렇다. 9장 플레이테스트의 ③번 규칙과 같다. **변명 대신 "앞으로 하고 싶은 것"으로 말한다.** 같은 내용이지만 완전히 다르게 들린다.

### 2.6 수업이 끝난 뒤

10주 동안 배운 것을 정리하면 이렇다.

| 배운 것 | 게임 밖에서 |
|---|---|
| 요청의 범위를 좁혀서 말하기 | 모든 AI 활용에 그대로 쓰인다 |
| 결과를 확인하고 되돌리기 | Git은 어떤 작업에도 쓸 수 있다 |
| 원인을 좁혀 가며 찾기 | 문제 해결의 기본 구조 |
| 남에게 시켜 보고 고치기 | 모든 만드는 일의 공통 과정 |
| 모르는 것을 모른다고 특정하기 | 배우는 능력 그 자체 |

**이 중 어느 것도 JavaScript 문법이 아니다.** 문법은 AI가 기억한다. 위의 다섯 가지는 사람이 해야 하는 일이고, 그래서 이 수업의 내용이었다.

**더 가고 싶으면 (심화 11~12장)**

| 방향 | 다루는 것 |
|---|---|
| 온라인으로 확장 | API, API 키 보안, 온라인 랭킹 (11장) |
| 게임 라이브러리 | Phaser 같은 도구로 더 큰 게임 (12장) |
| 게임 안에 AI | 게임에 AI 기능을 넣기 (12장) |
| 스스로 배우기 | 새로운 기술을 혼자 익히는 방법 (12장) |

심화를 듣지 않더라도, **지금 만든 저장소는 계속 쓸 수 있다.** 방학에 기능을 하나 더 붙이면 그대로 포트폴리오가 된다.

## 3. 따라 하기 실습

작업 폴더는 **`my-game`** 이다.

> **시작 전에 커밋한다.** 소스 제어 → `10장 시작 전 상태 (최종 후보)` → Commit.
>
> **이 커밋이 중요하다.** 오늘 뭔가 잘못되면 **이 지점으로 돌아와서 그대로 제출**할 수 있다. 발표 당일의 보험이다.

### Step 1. 최종 점검 — 내 환경 (8분)

9장에서 만든 **`테스트목록.md`** 를 열고, 하나씩 **실제로 눌러서** 확인한다. 눈으로 코드를 보는 것이 아니라 플레이한다.

- [ ] 체크리스트 전 항목 통과
- [ ] 콘솔(`F12`)에 빨간 에러 없음 — **시작 화면, 플레이 중, 게임 오버 세 상태 모두**
- [ ] `showDebug`, `showHitbox`가 꺼져 있음
- [ ] 실험용 `console.log`가 남아 있지 않음

하나라도 실패하면 **먼저 고친다.** 다음 단계로 넘어가지 않는다.

### Step 2. 최종 점검 — 남의 환경 (10분)

**이번 주의 핵심 단계다.** 2.2의 세 가지를 실제로 한다.

**(1) 시크릿 모드**

1. `Ctrl+Shift+N`으로 시크릿 창을 연다
2. 배포 주소를 **직접 입력**해서 연다
3. 확인한다

- [ ] 페이지가 열린다 (저장소가 Public이다)
- [ ] 그림과 소리가 정상이다 (파일 이름 대소문자)
- [ ] CSS가 적용되어 있다 (흑백 화면이 아니다)
- [ ] **최고 점수가 0에서 시작한다** — 처음 오는 사람의 상태다
- [ ] 한 판을 끝까지 플레이할 수 있다
- [ ] 콘솔에 에러가 없다

> **여기서 문제가 나오면 대부분 두 가지다.** ① 커밋/Sync를 안 한 파일이 있다 ② 파일 이름 대소문자가 다르다. 부록 D.5를 본다.

**(2) 휴대폰**

1. 와이파이를 끄고 데이터로 연다
2. 확인한다

- [ ] 화면이 잘리지 않는다
- [ ] 글씨가 읽힌다
- [ ] 터치 조작이 되거나, **"PC에서 플레이해 주세요"가 보인다**

**(3) 다른 사람**

옆 사람에게 링크를 보내고, **아무 설명 없이** 열어 보게 한다.

- [ ] 열린다
- [ ] 무슨 게임인지 말할 수 있다 (30초 규칙)

### Step 3. `README.md` 완성 (12분)

아래 양식을 채운다. **AI에게 쓰게 하지 않는다** — 내용은 내가 정한다. 문장을 다듬는 것만 맡긴다.

```markdown
# (게임 제목)

(한 줄 설명 — "____가 ____하면서 ____하는 게임")

## 플레이하기
👉 https://(내아이디).github.io/my-game/

![게임 화면](screenshot.png)

## 조작법
| 키 | 동작 |
|---|---|
| ← → | 좌우 이동 |
| 스페이스바 | 점프 |
| R | 다시 시작 |
| M | 음소거 |

## 규칙
- 목표:
- 점수:
- 게임 오버:

## 모바일
(지원함 / PC에서 방향키로 플레이 권장)

## 개발 환경
- 순수 HTML / CSS / JavaScript (Canvas)
- 외부 라이브러리 없음
- 에디터: VS Code
- 사용한 AI 도구: (도구 이름)

## 사용한 에셋
| 파일 | 용도 | 출처 | 라이선스 |
|---|---|---|---|
| player.png | 플레이어 | (주소) | CC0 |
| hit.mp3 | 충돌음 | (주소) | CC BY (작자: ○○) |
| (도형으로 직접 제작) | 배경 | - | - |

## 제작 과정
10주 동안 매주 한 단계씩 쌓아 만들었습니다.
자세한 기록은 [회고.md](회고.md)와 [플레이테스트.md](플레이테스트.md)를 참고하세요.

## 앞으로 하고 싶은 것
- [ ] (넣고 싶었지만 못 넣은 것)
- [ ] (아는 문제점)
```

**스크린샷을 찍어 넣는다.** `Windows + Shift + S` → `screenshot.png`로 저장 → 커밋.

> 문장 다듬기만 AI에게 맡길 때: `"아래 README의 내용은 그대로 두고, 문장만 자연스럽게 다듬어 줘. 내용을 추가하거나 바꾸지는 마."`

### Step 4. 10주 회고 작성 (10분)

`회고.md` **맨 위에** "10주 전체 회고"를 추가한다. 주차별 회고는 그 아래에 그대로 남긴다.

**먼저 1주차 회고를 다시 읽는다.** 그다음 쓴다.

```markdown
# 10주 전체 회고

## 1. 가장 어려웠던 문제와 뚫은 방법
(한 가지를 골라 7장의 여섯 줄 양식처럼 쓴다)

## 2. AI에게 맡기는 법이 어떻게 달라졌나
- 1주차에 쓴 프롬프트:
- 9주차에 쓴 프롬프트:
- 무엇이 달라졌나:

## 3. 10주 전의 나에게 한 가지 조언한다면

## 4. 다음에 만들고 싶은 것
```

**2번이 이 수업의 핵심 평가 항목이다.** 1주차와 9주차의 프롬프트를 실제로 복사해서 나란히 놓는다.

### Step 5. 발표 준비 (8분)

**메모 한 장**을 만든다. 슬라이드를 만들 시간은 없고, 필요하지도 않다. `발표메모.md`로 저장해도 좋다.

```
[0:00] 제목 / 한 줄 설명 / 목표
   → "____는 ____하는 게임입니다."

[0:30] 시연
   → 미리 탭을 열어 둔다. M키로 음소거. 한 판 연습해 둔다.

[1:30] 가장 어려웠던 문제  ⭐
   1. ____을 하려는데 ____가 되는 문제
   2. 원인을 찾으려고 ____을 해 봤다
   3. 원인은 ____이었다
   4. ____으로 고쳤다

[2:30] 코드 한 부분  ⭐
   → 보여 줄 함수: ____
   → 하는 일: ____
   → 왜 이렇게 짰나: ____
   → 없으면 어떻게 되나: ____
```

**발표 전 최종 확인**

- [ ] 배포 주소 탭을 미리 열어 뒀다
- [ ] 음소거를 켜 뒀다
- [ ] 보여 줄 코드 부분을 VS Code에 열어 뒀다
- [ ] 한 판 연습해서 **바로 죽지 않는다**는 걸 확인했다
- [ ] 와이파이가 끊겨도 로컬에서 실행할 수 있다

### Step 6. 최종 커밋 (3분)

```
최종 제출
```

커밋 → **Sync Changes** → **시크릿 모드로 한 번 더 확인.**

> **발표가 끝난 뒤에는 코드를 건드리지 않는다.** 제출 상태가 확정된다.

## 4. 최종 제출물 (과제)

### 과제 1. 최종 게임 (필수)

- [ ] 배포 주소에서 **시크릿 모드로도** 한 판이 끝까지 플레이된다
- [ ] 시작 → 플레이 → 게임 오버 → 재시작이 모두 작동한다
- [ ] 콘솔에 빨간 에러가 없다 (세 상태 모두)
- [ ] 휴대폰에서 화면이 정상이거나, 안내가 표시된다
- [ ] 디버그 표시가 꺼져 있다

### 과제 2. `README.md` (필수)

- [ ] Step 3의 모든 항목이 채워져 있다
- [ ] **플레이 링크**가 맨 위에 있다
- [ ] 조작법이 표로 정리되어 있다
- [ ] 스크린샷이 보인다
- [ ] **사용한 에셋 표**가 있다 (안 썼으면 "외부 에셋 없음")
- [ ] **사용한 AI 도구**가 적혀 있다
- [ ] "앞으로 하고 싶은 것"이 적혀 있다

### 과제 3. 10주 전체 회고 (필수)

- [ ] 네 질문이 모두 채워져 있다
- [ ] 2번에 **1주차와 9주차의 실제 프롬프트**가 복사되어 있다
- [ ] 주차별 회고(1~10주차)가 아래에 모두 남아 있다

### 과제 4. 발표 (필수)

- [ ] 3분 안에 끝낸다
- [ ] 시연이 작동한다
- [ ] **가장 어려웠던 문제**를 네 문장 틀로 말한다
- [ ] **코드 한 부분**을 자기 말로 설명한다

### 과제 5. 저장소 최종 상태

저장소에 아래 파일들이 모두 있어야 한다.

```
my-game/
├── index.html
├── style.css
├── script.js
├── README.md              ← 완성된 것
├── 회고.md                 ← 10주 전체 + 주차별 1~10
├── 기획서.md               ← 3장
├── 디버깅기록.md            ← 7장
├── 플레이테스트.md          ← 9장
├── 테스트목록.md            ← 9장
├── debug-practice.html     ← 7장
├── screenshot.png
└── (에셋 파일들)
```

- [ ] 파일 이름에 한글·공백이 없다 (`.md` 문서는 예외)
- [ ] 연습용 잔해(`test.txt`, `복사본` 등)가 없다
- [ ] 저장소가 **Public**이다

## 5. 최종 체크리스트

제출 직전에 **순서대로** 한다.

```
1. 테스트목록.md 전 항목 플레이 확인
2. F12 콘솔 — 세 상태 모두 에러 없음
3. showDebug / showHitbox 끔
4. README.md 완성 확인
5. 10주 회고 작성 확인
6. 커밋 → Sync Changes
7. ⭐ 시크릿 모드로 배포 주소 열어 전체 확인
8. ⭐ 휴대폰 데이터로 열어 확인
9. 링크 두 개 제출
```

```
① 저장소 링크: https://github.com/(내아이디)/my-game
② 배포 링크:   https://(내아이디).github.io/my-game/
```

> **7번과 8번을 건너뛰지 않는다.** 10주 작업이 링크 하나 때문에 0점이 되는 일이 매년 생긴다.

## 6. 마지막으로

10주 전에는 코드 한 줄도 몰랐다. 지금은 인터넷에 주소가 있는 게임을 가지고 있다.

그런데 더 중요한 것이 생겼다. **막혔을 때 무엇을 해야 하는지 아는 것.**

- 에러가 나면 콘솔을 본다
- 원인을 모르면 범위를 좁힌다
- 요청할 때는 범위와 금지 조건을 함께 말한다
- 망가지면 되돌린다
- 내가 만든 것은 남에게 시켜 보고 고친다

이 다섯 개는 게임에만 쓰이는 게 아니다. **앞으로 AI와 무엇을 만들든 그대로 쓰인다.** 그리고 AI가 더 좋아져도 이 다섯 개를 할 사람은 여전히 필요하다.

0장에서 이렇게 썼다.

> 코딩은 막히는 일이 대부분이고, 잘하는 사람은 막혔을 때 빠져나오는 데 익숙한 사람이다.

10주 동안 여러 번 막혔을 것이다. 그리고 빠져나왔다. 회고 파일에 그 기록이 남아 있다. **그게 이 수업의 결과물이다.** 게임은 그 증거다.

수고했습니다. 🎉

## 이번 주 자주 막히는 지점

| 증상 | 원인과 해결 |
|---|---|
| 시크릿 모드에서 페이지가 안 열린다 | 저장소가 Private이다 → Settings에서 Public으로 |
| 시크릿 모드에서만 이미지·소리가 없다 | 파일을 커밋/Sync 안 했거나 **이름 대소문자 불일치** (부록 D.5) |
| 시크릿 모드에서만 CSS가 안 먹는다 | 절대 경로를 쓰고 있다 → 상대 경로로 (부록 D.5) |
| 시크릿 모드에서 최고 점수가 이상하다 | **정상이다.** `localStorage`가 비어 있는 상태다. 0으로 시작하는지 확인하는 것이 목적 |
| 스크린샷이 README에 안 보인다 | 이미지 파일을 커밋했는지 / 파일 이름이 정확한지 |
| 발표 중에 게임이 바로 죽는다 | 난이도 상한을 올려 둔 상태다. 미리 한 판 연습한다 |
| 발표 중에 소리가 터졌다 | M 키 음소거를 미리 켜 둔다 |
| 와이파이가 안 돼서 시연을 못 한다 | `index.html`을 Live Server로 로컬 실행 — 미리 준비해 둔다 |
| 발표 직전에 기능을 넣다 깨졌다 | **실습 시작 전에 해 둔 "최종 후보" 커밋으로 되돌린다.** 그래서 커밋해 둔 것이다 |
| 제출할 파일이 빠졌다 | 과제 5의 파일 목록과 저장소를 하나씩 대조한다 |
