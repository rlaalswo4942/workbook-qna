## 1. 한 줄 소개

바이브코딩 워크북을 장별 가이드로 읽으면서, 궁금한 문장에 형광펜을 긋고 질문하면 같은 수업 사람들에게 실시간으로 공유되는 사이트. 이름만 정하면 시작하고, 질문은 모두와 나누고 메모는 나만 본다.

## 2. 왜 만들었나

- 학생들이 **워크북 · VS Code · GitHub · 추가 강의 자료를 오가며** "어느 부분을 어디에서 어떻게 처리하는지"를 가장 어려워했다
- 질문이 메신저에 흩어지면 **워크북의 어느 문장에 대한 질문인지** 사라진다 → 질문을 본문 위치에 고정
- 과제가 "저장소 + 배포 링크" 제출로 바뀌어 서로의 결과물을 한곳에서 볼 곳이 필요했다

## 3. 주요 기능

### 3.1 장별 가이드 (워크북 18개 문서)
- 학습 목표 · 핵심 개념 · 실습 순서 · 과제 · 제출 체크리스트 · 필수 링크 · 자주 막히는 지점을 원고에서 자동 추출
- 원문은 섹션 폴더(접고 펼치기)로, `.md` 원문 내려받기 제공
- 공개본에서는 개인 체크 표시(`- [x]`)를 초기화

### 3.2 어디서 · 어떻게 안내 + 작업 지도 (2026-10-15)
- 실습 **Step 78개**마다 **장소 칩**(13곳: 이 사이트 · 공식 사이트 · 탐색기 · VS Code 편집기 · AI 채팅 · 소스 제어 · Live Server · F12 콘솔 · GitHub 웹 · 배포 주소 · 휴대폰 · 테스터 · Supabase), 이동 순서, "확인 —" 성공 기준, 헷갈리는 지점 팁
- 칩 표기: 내 컴퓨터 = 테두리 / 인터넷 = 검정 채움 / 사람·기기 = 점선 → "내 컴퓨터에서만 보이는 것 vs 남에게 보이는 것"을 한눈에
- 장마다 "만들고 고치는 파일 · 어디서", "제출 · 어디서"(Commit → Sync → GitHub 확인 → 시크릿 창 → 링크 제출)
- `#map` 작업 지도: 큰 그림(2개 레인) · 장소 카드 · 매주 흐름 10단계 · 주소 4개 구분 · 저장 4단계 · 되돌리기 종류 · FAQ 11개 · 장별 이동표

### 3.3 마킹 질문 (공유)
- 본문을 드래그 → 색(질문·막힘·핵심·팁) 선택 → 형광펜 / 메모지 → 질문 등록
- 마킹은 상단 칩 · 좌측 트리 · 섹션 폴더에 색 점으로 표시, 클릭하면 해당 위치로 이동(`#ch2:m123`)
- 저장 형식: 블록 id + 글자 오프셋 + 인용문 → 원고가 조금 바뀌어도 가장 가까운 같은 문장을 찾아 다시 칠함
- 마킹 클릭 메뉴: 형광펜↔메모지 전환, 색 변경, 삭제(본인만)

### 3.4 실시간 채팅
- 장별 질문방 + 전체 라운지, 답변 스레드, 탭(전체 · 답변 대기 · 마킹만 · 내 글 · 🔒 내 메모)
- Supabase Realtime 구독(INSERT/UPDATE/DELETE), 구독 연결 시점마다 서버 목록으로 재동기화

### 3.5 이름 로그인 = 고유 아이디 (2026-10-15)
- 스터디_프레임의 `features.login` 방식 이식: 처음 접속 시 이름 입력 → 아이디(NFKC 정규화 · 소문자), **비밀번호 없음 · 인원 제한 없음**
- 이미 쓰인 이름이면 "본인이면 확인" 경고
- 글에는 이름 표시, 같은 이름이면 다른 기기에서도 "내 글"·본인 삭제
- 로그인 도입 전 브라우저 토큰으로 쓴 글도 계속 본인 글로 인정(하위 호환)

### 3.6 개인 공간 (나만 보기)
- 장별 **메모장**(채팅의 🔒 내 메모 탭)과 **🔒 나만 보기 마킹**은 아이디 공간에만 저장 → 다른 이름으로는 보이지 않음
- 나만 보기 마킹 → "질문으로 올리기"로 언제든 공유 전환
- 같은 이름이면 기기 간 이어짐(탭 복귀 시 서버에서 다시 받아옴), 서버 미설정 시 이 기기에만 저장

├── files/*.md            ← build.mjs가 생성하는 원문 내려받기본
├── tools/
│   ├── build.mjs         워크북 .md → chapters.js + files/

### app.js 구성 (위에서 아래 순서)
1. DOM 헬퍼 `h()` — 문자열 자식은 텍스트로만 넣음(XSS 안전), `html`은 워크북 원문에만
2. 이름 로그인 — `USER`, `SECRET = 'workbook-qna:user:' + 아이디`, `OWNER = sha256(SECRET)`
3. 저장소 추상화 `makeStore()` — Supabase(실시간) / 로컬(localStorage + BroadcastChannel) 같은 인터페이스
4. 렌더링 — 상단 장 탭 · 마킹 칩, 좌측 트리, 홈, 장 화면(가이드 + 원문 폴더), 작업 지도
5. 마킹 — 선택 영역 → 오프셋 계산, TreeWalker로 텍스트 노드를 `<mark>`로 감싸기
6. 채팅 · 마킹 메뉴 · 저장소 폴더
7. 개인 공간 — `priv = {t, memos: {장: 텍스트}, marks: [...]}`, 0.8초 디바운스 저장, 최신값 우선
8. 이름 입력 화면 · 로그아웃
9. 라우팅 — `#ch2` 장 · `#ch2:s3` 섹션 · `#ch2:guide` · `#ch2:m123` 마킹 · `#map` · `#map:p-git` 장소 카드

### 데이터 모델 (Supabase)

| 대상 | 내용 | 접근 |
|---|---|---|
| `posts` | id, chapter, parent_id(답변), block, start_offset, quote, color, style, body, nick, owner_hash, repo_url, page_url | 읽기·쓰기는 누구나(RLS), 직접 수정·삭제는 차단 |
| `delete_post(id, secret)` | 해시 일치 시만 삭제, 답변은 cascade | security definer RPC |
| `update_mark(id, secret, color, style)` | 본인 마킹 형태 변경 | security definer RPC |
| `private_notes` | owner_hash(PK), data jsonb(≤500KB), updated_at | **정책 없음** → 표 직접 접근 불가 |
| `get_private(secret)` / `put_private(secret, data)` | 비밀의 해시로만 읽기·쓰기 | security definer RPC |

본인 확인 원리: 글에는 비밀의 **SHA-256만** 저장되고, 삭제·개인 공간은 서버 함수가 **비밀 원문을 받아 해시를 비교**한 뒤에만 수행한다.
